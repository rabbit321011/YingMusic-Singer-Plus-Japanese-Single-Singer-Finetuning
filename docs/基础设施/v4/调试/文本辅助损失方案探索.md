# 文本辅助损失方案探索

> 2026年7月1日，与 Codex 的多轮讨论
> 研究方向：在材料4（V5路线）之外探索文本约束的强化方法
> 核心问题：SVS FlowMatching 对文本条件不敏感，咬字差

---

## 一、问题根源

V4c FlowMatching 训练中 FlowB loss 恒在 0.93-0.97，不随文本质量变化：

- mel spectrogram 自带声学信息，模型可以走"忽略文本→直接拟合mel"的捷径
- FlowMatching 的 MSE loss 无法区分"模型在利用文本"还是"模型在忽略文本"
- 结果：B区咬字弱，文本依赖性训练不充分

---

## 二、探索方案一：对比损失（cosine similarity）

### 2.1 原始思路

```python
# 用 Whisper encoder 的 audio feat 和 text feat 做余弦对比
pos_sim = cosine(whisper_audio_feat, target_text_feat)
neg_sim = cosine(whisper_audio_feat, random_text_feat)
loss = max(0, 0.2 - pos_sim + neg_sim)
```

### 2.2 问题

1. **Whisper 音频编码器和文本 embedding 不是同空间**：Whisper 是 seq2seq ASR，不是 CLIP/CLAP 这类跨模态对比模型。audio feat 和 text embedding 之间没有天然 cosine 可比性
2. **对比损失只保证可区分，不保证正确**：模型只需加到"whisper 能区分 A 句还是 B 句"的程度，不需要咬字更清晰
3. **任意特征提取器都行，跟 Whisper 无关**：这个方案只用了 Whisper 输出是向量的属性，没有利用它的文本理解能力

### 2.3 结论

**废弃。** 对比损失在错误的几何空间里算距离，没有语义保证。

---

## 三、探索方案二：Teacher-Forcing ASR CE Loss

### 3.1 核心思想

用冻结的 Whisper 做 teacher-forcing 解码，直接优化"生成音频可被识别为目标文本":

```python
# 一步重建干净 latent（CFM 免费获得，不需要 ODE 积分）
x_clean_hat = x_t + (1 - t[:, None, None]) * v_pred

# 变回音频
audio = BigVGAN(x_clean_hat)          # ~50ms

# 提取 Whisper 音频特征
audio_feat = WhisperEncoder(audio)     # ~100ms

# Teacher-forcing: 一次性算完所有 token 的 CE
logits = WhisperDecoder(audio_feat, target_tokens)  # ~100ms
loss_asr = CrossEntropy(logits, target_tokens)

# 总损失
loss = cfm_loss + 0.01 * loss_asr      # t ∈ [0.5, 0.85] 时才加
```

### 3.2 为什么比对比损失好

| | 对比损失 | CE (teacher-forcing) |
|---|---|---|
| 度量 | cosine（不同空间，无意义） | 概率（Whisper 自己的训练目标，有意义） |
| 优化方向 | 让 whisper 能区分 A vs B | 让 whisper 确定这是目标文本 |
| 风险 | 学无意义的方向 | 优化 Whisper 偏好（reward hacking） |

### 3.3 为什么 CE 优于 GRPO

| | GRPO | CE (teacher-forcing) |
|---|---|---|
| 梯度 | 策略梯度（采样→打分→估计），方差大 | 直接反向传播，确定性 |
| 信号 | reward model 离散打分 | 连续概率 |
| 我们试过 | PER +4.4%，统计不显著 | 理论上信号更强 |

### 3.4 CFM 端点纠正

**V4c 的 CFM 约定**：

```
x_t = (1 - t) * noise + t * full_latent
v_target = full_latent - noise
t=0 → noise, t=1 → clean
```

**一步重建**:
- `x_clean_hat = x_t + (1 - t) * v_pred`  ← ✅ 正确
- `x_noise_hat = x_t - t * v_pred`        ← ❌ 这是噪声端点，不能拿去 Whisper

**推荐 t 范围**: [0.5, 0.85] — 太小重建太脏，太大接近真实学不到东西

### 3.5 风险

1. **Reward hacking**：模型可能学到 Whisper 偏好的频谱特征（过强辅音、压缩语速），而不是自然发音
2. **小权重策略**：0.01 权重 + 晚启动（10 epoch 后），避免早期破坏声学先验
3. **Whisper-small 局限性**：日语 tokenizer 精度有限，CE loss 对日语咬字的约束力可能不够强

### 3.6 结论

**方向有价值但不紧急。** 计算成本可控（约 250ms/step，仅 35% step 触发），但本质上和 GRPO 共享同一个信号源（Whisper-small），GRPO 已经验证了信号太弱的瓶颈。可以在 SPFM/Wet 增强等主线优化完成后，作为低风险低权重的辅助项加入。

## 四、与材料4的定位关系

| 方案 | 材料4 地位 | 本次讨论地位 |
|------|----------|-------------|
| SPFM 自净化流匹配 | V5 主线（Phase 3） | ✅ 对齐 |
| Wet 仿真增强 | V5 主线（Phase 3） | ✅ 对齐 |
| VAE decoder 微调 | V5 主线（Phase 2） | ✅ 对齐 |
| 混合训练 | V5 主线（Phase 3） | ✅ 对齐 |
| GRPO | 已暂停（Phase 结束） | - |
| **CE 辅助损失** | **不在材料4中** | **本次新增，低优先级** |
| **对比损失** | **不在材料4中** | **废弃** |
