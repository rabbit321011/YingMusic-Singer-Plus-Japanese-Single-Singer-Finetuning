# VAE Decoder Adaptation Audit — 2026-07-15

## 1. Objective

Determine whether the fixed Stable Audio 2 VAE decoder can be adapted to preserve target singer's subtle gentle, beautiful, natural timbre while keeping the existing YingMusic latent interface unchanged.

This audit does not start training.

## 2. Established Motivation

A three-sample blind test showed that the VAE reconstruction was the degraded candidate in all cases:

- sample02: clearly blurrier;
- sample03: smaller difference, but articulation sounded slightly tongue-tied;
- sample04: clearly blurrier and less natural.

The VAE is therefore a confirmed quality ceiling for the target product, not a transparent component.

## 3. Architecture Facts

Source configuration:

- 44.1 kHz stereo input/output;
- Oobleck encoder and decoder;
- downsampling ratio 2048;
- latent frame rate 44100 / 2048 = 21.5332 Hz;
- stochastic VAE bottleneck;
- encoder output 128 channels split into mean and scale;
- sampled latent 64 channels;
- decoder input 64 channels;
- total VAE parameters: 156,112,514;
- encoder parameters: 77,989,888;
- decoder parameters: 78,122,626.

The encoder is marked `requires_grad: false` in the shipped configuration. The decoder is trainable by default.

YingMusic-Singer-Plus did not introduce or train this VAE. The paper states that it adopts the VAE from Stable Audio 2. Therefore this work is a domain adaptation of the Stable Audio 2 decoder under YingMusic's existing latent contract.

## 4. Original Training Intent Preserved in Config

The shipped JSON preserves the Stable Audio VAE training recipe:

- Encodec-style multi-scale discriminator;
- adversarial weight 0.1;
- feature matching weight 5.0;
- perceptually weighted multi-resolution STFT loss weight 1.0;
- waveform L1 weight 0.0;
- KL weight 1e-4;
- decoder/autoencoder AdamW LR 1e-4;
- discriminator AdamW LR 3e-4;
- EMA enabled.

However, the YingMusic repository only includes inference-side autoencoder code. It does not include the original autoencoder training wrapper, loss factory, or discriminator implementation. The current local Python environment also lacks `auraloss` and the full `stable_audio_tools` package.

This means a faithful full training reproduction is a medium project, not the correct first experiment.

## 5. Stochastic Bottleneck Consequence

`VAEBottleneck.encode()` samples:

```text
z = mean + randn * softplus(scale)
```

A local 5.02-second probe measured:

- posterior std mean: about 0.0504;
- mean absolute difference between two latent samples: about 0.0563.

For the first decoder information probe, cached latents must be fixed. Otherwise changing random latent samples add noise to the training comparison. Recommended first probe:

- cache one sampled latent per segment using a fixed seed;
- optionally cache posterior mean as a second condition;
- train and evaluate each condition separately;
- do not silently switch YingMusic inference to posterior mean.

## 6. Local Memory Probe

A real decoder backward pass was tested locally using one 108-latent-frame segment:

- segment length: 221,184 samples = 5.0155 seconds;
- latent shape: `[1, 64, 108]`;
- all 78.1M decoder parameters trainable;
- peak allocated VRAM: 8.57 GB;
- peak reserved VRAM: 9.25 GB;
- local GPU: RTX 5070 Ti Laptop 12 GB.

This excludes optimizer-state and full MR-STFT/discriminator overhead. Local training has too little safety margin for the intended experiment. Local is suitable for code smoke tests only; formal Stage B should run on the server.

Training crops must be exact multiples of 2048 samples. Arbitrary 5.0-second crops produce output-length mismatch.

### 13.4 Training-planning boundary

Training has not started and no training script/config has been created.

The official trainer already contains the needed encoder-freeze behavior. With `warmup_steps: 0` and `encoder_freeze_on_warmup: true`, `global_step >= warmup_steps` is true from the first step and the encoder executes under `torch.no_grad()`. No official source modification is required for decoder-only gradient flow.

The existing YMSP config supplies the original official-style MR-STFT, Encodec discriminator, feature-matching, adversarial, KL, AdamW, scheduler, and EMA settings. Before B0, choose explicitly between:

1. an exact original-loss-chain engineering smoke test; or
