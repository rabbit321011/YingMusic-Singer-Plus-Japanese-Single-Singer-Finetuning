# 唱法音色样本池

## 任务定位

当前轻柔音色雾感只完成少量样本定位，无法判断问题是否覆盖更广泛的轻柔唱法。需要先建立能够跨歌曲检索相似唱法和音色的句级表示，再扩展 DiT 条件交叉诊断。

第一阶段交付的是可检索样本池，不要求预先给全部数据强制分配离散风格标签。

## 模型候选

1. 已有 BYOL singer-identity：服务器已有歌唱域声纹模型和源码。模型按 44.1 kHz 训练、默认 EfficientNet-B0 + temporal average pooling，并为每个输入片段输出 1000 维向量；与当前 44.1 kHz 数据直接匹配。2026-07-20 已在 `yysinger` 用真实 2.931 秒句子完成 CPU checkpoint 加载与前向，输出 `[1,1000]` FP32 且数值正常；下一步验证 GPU batch、句长分桶和短句稳定性。文件名扫描未找到可直接复用的历史向量产物。

2026-07-21 GPU smoke 进一步确认：模型显存很轻，但 3 ms 原长输入会因 nnAudio reflect padding 小于 `n_fft/2` 失败；短句补到约 4 秒会造成明显表示变化，<1 秒样本 native-vs-window cosine 约 0.35–0.51；长句组内 padding 也可把 cosine 降至约 0.67–0.74。因此正式全量前必须用边界覆盖 benchmark 决定短句、窗口、归一化和 batching，不能把固定补零或组内补长当作无害加速。

正式 8/桶边界 benchmark 后，BYOL 第一基线确定为：peak normalization、主体 native 原长、batch size 1、多 GPU 独立 shard；禁止组内补长 batch。两个 3 ms 句仅补到 STFT 可运行最小长度，并保留质量/padding 标记，检索默认排除信息不足片段。AMP 仍待 FP32 配对验证。全量前另需完成本地/服务器 WAV 文件大小一致性审计。

后续配对验证中 CUDA AMP-FP16 首样本即产生 NaN/Inf，因此正式推理固定 FP32，最终矩阵再保存 FP16。服务器 WAV header inventory 已冻结为计算源；本地 WAV 是相同路径/格式但不同切写版本，最终双端保存的是同一服务器向量产物。

## 六模型混杂诊断结论（2026-07-21）

三模型均在相同 89,828 句过滤库、128 个固定 query 上完成 exact cosine 检索。CAM++ 跨 recording top1/random cosine 中位为 0.889/0.536，emotion2vec 为 0.989/0.941，说明都有非随机结构；但绝对 cosine 尺度不可跨模型直接比较。

进一步使用 torchcrepe F0、相对旋律轮廓及 librosa 频谱指标，并为每个 query 构建不同 recording、duration+RMS 严格匹配的共同 control。control 的 duration/RMS abs-log2 p50 仅 0.0088/0.0245。

- F0 median cross/matched（semitones）：BYOL 0.916/2.933、CAM++ 0.444/2.933、emotion2vec 0.455/2.933。
- 相对 F0 contour RMSE cross/matched：BYOL 3.261/3.957、CAM++ 2.828/3.957、emotion2vec 2.460/3.957。
- spectral centroid、rolloff、flatness、slope 等在三模型也均显著比 matched control 更近。

这证明三种 baseline 都强编码音高、旋律和频谱形态。CAM++ 的音区耦合最强，emotion2vec 的旋律轮廓耦合最强；不能把任何一个模型的近邻/聚类直接当唱法标签。下一阶段必须做声学因素控制后的残差检索，以及跨歌曲人耳盲听。

VoiceCLAP 使用完全相同的 128 query 与 duration+RMS matched control 后，F0 median cross/matched 为 `0.750/2.933` semitones，相对 F0 contour RMSE 为 `3.047/3.957`；spectral centroid/flatness/slope 也显著更近。它比 CAM++/emotion2vec 的音区耦合弱，但依然强编码音高、旋律与频谱形态，dense vocal-style caption 监督并未自动得到“去旋律的唱法空间”。因此四个模型都必须经过声学控制和盲听。

## 验证门槛

- 每个时间戳句子最终保存一个向量。
- 先跑代表性小样本，不直接全量安装和计算所有重模型。
- 排除同源文件或同歌曲后评价 top-k 近邻。
- 建立少量“唱法相似/不相似”人工 pair，比较 cosine retrieval 指标。
- 聚类实际使用postprocessed候选时，必须用同Query candidate-top1 vs raw-top1直接盲测；每模型至少20个decisive判断，不能由raw-vs-control结果代替。
- 自动聚类必须导出中心、边界与随机样本供试听。
- 第二标注者必须使用独立reviewer ID/JSONL；跨人一致性只能由共享item计算，禁止把两人event合写后按最后一条覆盖。
- 若模型只聚出歌曲、音区、录音质量或分离伪影，不进入融合。
