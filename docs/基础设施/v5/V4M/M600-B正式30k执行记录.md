# M600-B 正式 30k 执行记录

## 裁决与目标

M600-D 已在 30k 完成，但相对 338M HighLR 的 last-1000 训练 Loss 只低 `0.364%`，12k 盲听也
仅小幅领先。该结果证明加容量有稳定但很弱的收益，不能区分是 scaling 本身收益弱，还是
`1024 x 40` 的纯加深布局没有有效利用新增参数。用户于 2026-08-05 授权启动近等参数量的
M600-B，保持来源、数据、训练预算和 loss 不变，只把容量布局改为深宽平衡结构。

```text
M600-B: dim=1024, depth=31, heads=24, dim_head=64, ff_mult=3
DiT state elements=600,462,048
control: M600-D=602,599,648; HighLR=338,118,880
```

本实验用于回答“同为约 600M，深宽平衡是否优于纯加深”，不直接证明 1.5B 可行。最终裁决
必须同时看同 step Loss、paired eval 和盲听；训练 Loss 不代替听感。

## 显存优化裁决与代价

200-step `FSDP + no_sync + activation checkpoint off` 实测：

```text
steady mean / median / p95 = 2.788 / 2.752 / 3.160 s/update
max allocated = 13.255GiB
max reserved = 16.166GiB
minimum physical free = 6.689GiB
checkpoint size = 11,516,561,527 bytes
checkpoint save = about 32.99s
```

正式训练关闭 activation checkpoint：D 的同口径实验显示它只节省约 `0.48GiB`，却慢约 24%。
也不启用每 microbatch 同步：它可多释放约 `2.48GiB` 物理余量，但慢约 6.8%，当前已有超过
3GiB 的安全门限。若正式运行出现低于 3GiB 的真实余量，不得静默切换这些手段；先保留现场并
重新裁决，因为两者都会改变速度，逐 microbatch 同步还会改变 FP32 归约顺序。

## 冻结合同

```text
GPU set
FSDP FULL_SHARD, per-block auto wrap
FP32 parameters, gradients, optimizer and sharded EMA
no_sync: 4 local microbatches then one gradient synchronization
activation checkpoint: off
batch_size=1, grad_accum=4, effective batch=16
lr=1.4e-5, warmup=500, hold=23500, max_steps=30000
FlowB weight=2.0, CKA weight=0.7, drop_text=0.15
seed=42, max_duration=30s
checkpoint every 1000 updates, empty_cache every 100 updates
physical free safety floor=3GiB on every rank
diagnostic trace retains the latest 100 updates
```

这与 HighLR 的正式 30k schedule 一致。M600-D/B 都从同一 P500 fresh optimizer/fresh EMA 开始，
不得从 D checkpoint 迁移，也不得在正式运行中更换精度、结构、数据或 loss。
