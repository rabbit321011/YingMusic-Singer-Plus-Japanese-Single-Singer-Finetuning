# M600 深宽容量门禁

## 触发证据

TIME 与 HighLR 已分别沿数据量和优化强度给出一致的边际收益结论：

```text
V4PH-TIME30H < V4PH-TIME65H，但音色差距非常轻微。
V4PH < V4PH-30K-HIGHLR，但音色改善仍较小，且仍弱于 V4fg。
```

因此继续增加训练数据或延长高学习率都不是无效方向，但在当前 338M DiT 上的边际收益较小。
用户据此把模型容量提升为下一主变量，同时否决直接从 338M 跳到 1.5B：先用约 600M 模型建立
容量门禁。

## 共同实验边界

- 两个 M600 候选均保持 residual stream `dim=1024`、`dim_head=64`、文本/MIDI/VAE latent、
  H/PUL 与 GAME MIDI_P 接口不变；
- 来源冻结为历史 V4PH Phase-A P500：
  `${SERVER_ROOT}/YingMusic-Singer-Plus/ckpts/v4ph_phase_a/step_000500_final.pt`，SHA256: redacted
  `d82eb26f31429c9ed52f5ad22c95162fa3f3dc4c60f15d9114cc2616bbd772ac`；
- 正式对照为从同一 P500、同一 65H strict-control manifest 完成的
  `V4PH-30K-HIGHLR`；
- 数据、P500、H placement、GAME cache、loss、seed、有效 batch、30k 上限和 HighLR schedule
  保持一致，容量布局是唯一主变量；
- 新增容量在 transition 零步不得改变来源函数；不得依靠后续训练修复转换错误；
- M600 首轮保持 FP32 数值语义，不同时引入 BF16 音质变量；显存通过 FSDP 分片和 activation
  checkpoint 解决；
- M600 是容量门禁，不承诺其 checkpoint 将直接继续扩成 1.5B。

## M600-D：先行实验

```text
dim=1024
depth=40
heads=16
dim_head=64
ff_mult=2
DiT parameters=602,599,648
```

来源 22 个 block 原样映射到目标 40 层，新增 18 个 block 使用现有 AdaLN-zero 初始化，满足：

```text
new_block(x) = x
```

来源 block 顺序不可改变；新增恒等 block 在其间确定性均匀插入。转换 manifest 必须逐层记录
`source_index -> target_index`，未映射目标层必须恰好等于 18。所有非 block tensor 形状不变并
逐 tensor 精确复制。

M600-D 的优点是没有宽度迁移、LayerNorm 统计变化、head 复制或 FFN 扩宽，零步函数保持最容易
证明。代价是 40 层串行计算较深，不能单独回答更宽 block 是否更有效。

用户已裁决先做 M600-D。最初只授权转换、资源 probe、四卡 FSDP smoke 和 6k 门禁；用户随后于
2026-08-04 撤销“6k 后再决定 12k”的限制，授权从 transition step 0 连续正式训练到 12k并
保留 6k 中间 checkpoint。同 step 盲听解盲后，M600-D 12k 主观小幅胜过 HighLR 12k，用户已
授权从已验证 12k final DCP 按原冻结合同续训到 30k。D 的 30k last-1000 训练 Loss 仅比
HighLR 低 `0.364%`，因此用户于 2026-08-05 授权启动 M600-B 同合同 30k；1.5B 仍未授权。

## M600-B：已授权正式 30k

```text
dim=1024
depth=31
heads=24
dim_head=64
ff_mult=3
attention inner dim=1536
FFN inner dim=3072
DiT parameters=600,462,048
```

M600-B 同时增加深度和 block 内部宽度，但 residual stream 保持 1024：

- 22 个来源 block 扩为 31 个，新增 9 个 AdaLN-zero 恒等 block；
- Attention 保留原 16 个 head，新增 8 个 head 的输出投影列严格置零；
- FFN 保留原 2048 个 hidden unit，新增 1024 个 unit 的第二投影列严格置零；
- 新 head/FFN 内部权重允许确定性初始化，但零步不能影响 block 输出；
- 原 head、原 FFN、AdaLN、residual、long skip 与所有非 block 权重精确复制。

M600-B 与 D 参数量相差小于 0.4%，可在相同计算预算下回答容量应该偏向深度还是深宽平衡。
转换、独立等价性审计、四卡 FSDP 更新、严格恢复、普通 publish 合并、真实 H/GAME-P 音频和
200-step 显存/速度门禁均已通过。正式入口保持 FP32、FSDP、`no_sync`、activation checkpoint
off，并与 HighLR 使用相同 `lr=1.4e-5 / warmup=500 / hold=23500 / max_steps=30000`。

200-step B 基线的稳态 mean/median/p95 为 `2.788/2.752/3.160s`，max allocated/reserved 为
`13.255/16.166GiB`，最小物理余量 `6.689GiB`，100 到 200 step 无爬升。关闭 activation
checkpoint 的理由与代价保持透明：D 同口径只省约 `0.48GiB` 但慢约 24%；逐 microbatch 同步
可多释放约 `2.48GiB`，但慢约 6.8% 且改变 FP32 归约顺序，当前均无必要启用。完整证据和正式
路径见 `M600-B正式30k执行记录.md`。

正式 30k 已于北京时间 2026-08-05 14:47 启动，并于 2026-08-06 完成；step 100 平均
`2.761s/update`、Loss `12.031609`、max reserved `16.139GiB`、最小物理余量 `6.275GiB`，
全程无错误或显存爬升。M600-B 的转换、训练、publish 和三模型听评均已完成。

### M 分支最终裁决（2026-08-06）

用户完成 HighLR/M600-D/M600-B 的实名听评，结论为：M 分支确有提升，但听感提升非常小。它支持
“600M 容量方向可工作”，却不支持“参数增加会带来显著质量跃升”。因此 M 分支在 600M 门禁处
完成并停止，不继续追加 M600 训练，也不自动进入 1.5B；1.5B 若重启，必须另立来源、结构和预算
合同。

## 显存边界

当前 338M FP32 完整复制训练的实际 `nvidia-smi` 高水位可达约 23GB。增加约 262M trainable
parameters 后，参数、EMA、梯度和 AdamW 两份状态的新增驻留理论值接近 4.9GiB，另有新增激活；
因此 M600 禁止复用当前每卡完整复制的手动同步入口。

首版资源方案冻结为：

```text
FSDP FULL_SHARD
FP32 parameters / gradients / optimizer
逐 block activation checkpoint 作为实测后启用的可切换项
FP32 sharded EMA
PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True
VAE 保持现有实现，避免首轮引入 latent 预计算变量
```

任何显存优化在启用前必须同时报告收益与代价：

| 手段 | 预期收益 | 代价与风险 | 首轮策略 |
|---|---|---|---|
| FSDP FULL_SHARD | 将 parameter、gradient、AdamW 和 EMA 分摊到四卡；M600-D 200-step 基线最差 reserved 为 16.402GiB | 每 block 发生参数通信；速度受 PCIe/NCCL 影响；训练入口和分片 checkpoint/resume 明显更复杂；浮点归约顺序可能与旧手动同步不同 | 必需；四卡 10-step、严格 resume、发布合并和 200-step 门禁已通过 |
| Activation checkpoint | 单卡完整复制时前向结束 live activation 降约 1.58GiB；四卡 FSDP 200-step 最差 reserved 再降 0.477GiB | 反向重算并增加 FSDP all-gather；FSDP 实测稳态均值慢 23.9%、p95 慢 34.2%；RNG 保存错误会破坏严格恢复 | M600-D 首轮关闭；只有其他手段仍不能满足 3GiB 余量才作为后备 |
| 每 microbatch 同步梯度 | 不用 `no_sync` 暂存完整梯度；FSDP 实测 max allocated 降 2.012GiB、最差 reserved 降 2.479GiB | reduce-scatter 从每 update 1 次增为 4 次；稳态均值慢 6.8%；与旧本地累积后统一归约的 FP32 顺序不同 | M600-D 容量单变量首轮保持关闭；新增组分或继续扩模时优先于 activation checkpoint 启用 |
| FP32 sharded EMA | 将完整 EMA 从每卡一份降为每卡一个 shard | 推理前必须离线合并；保存、审计和发布格式更复杂 | 必需；保持 FP32，不引入精度损失 |
| `expandable_segments:True` | 已在 338M probe 中把 reserved 峰值从约 20.20GiB 降到约 16.93GiB | 不减少真实 tensor/计算；不同分配序列的收益可能变化，不能替代物理余量门禁 | 启用；同口径记录开/关结果 |
| BF16 mixed precision | 参数/激活/通信可进一步下降，Tensor Core 速度可能提高 | 数值轨迹改变，可能影响 loss、音色和稳定性；与既有 FP32 HighLR 不再是严格单变量 | M600 首轮禁用；只有 FP32 资源门禁失败时另开对照 |
| VAE latent 预计算 | 移除每卡约 0.58GiB VAE 权重及在线 encode 工作区 | 占用磁盘，新增 cache provenance；预处理差异可能改变训练输入 | M600 首轮禁用，保留为后备方案 |

最终报告必须给出每卡峰值、step time、吞吐和 checkpoint 大小，不能把显存下降误报为无代价收益。

### 单卡完整复制 200-step 探针（2026-08-04）

该探针测的是 `602,599,648` 参数的 M600-D，不是 338M control。GPU set 上完整复制模型，固定
EMA + AdamW、FP32、`grad_accum=4`、同 seed、同一组 800 个 shuffled 样本、
`expandable_segments:True`，并在 update 100/200 后调用 `empty_cache()`。两组都正常完成。

| 指标 | 无 activation checkpoint | 逐 block activation checkpoint |
|---|---:|---:|
| step time mean | 1.754s | 2.363s |
| step time median | 1.761s | 2.322s |
| step time p95 | 2.007s | 2.842s |
| 200-step 进程总时长（含约 11s 初始化） | 362.20s | 484.59s |
| max allocated | 20.005GiB | 20.005GiB |
| max reserved | 21.094GiB | 20.533GiB |

step time 增加 `34.7%`，p95 增加约 `41.6%`。它在前向结束点能少保留约 `1.58GiB` live
activation，但 backward/VAE 临时峰值与 allocator cache 使这部分不会等额变成长期物理余量。
`empty_cache()` 每 100 step 释放约 7.3GiB reserved cache，这不是可以稳定交给更大模型使用的
真实 tensor 预算；两组清理前余量也都低于 3GiB 门禁。因此单卡完整复制只用于优化比较，不得

ETA 只能来自最终四卡 FSDP 形态至少 100 steps 的实测，不能套用上述单卡数字。

### 四卡 FSDP 200-step 优化裁决（2026-08-04）

三组均从同一 transition、同一 seed、同一 DistributedSampler 序列独立启动，FP32、EMA、AdamW、
`grad_accum=4`、`expandable_segments:True`，update 100/200 后 `empty_cache()`。速度用每一步四个
rank 中的最慢值；稳态统计排除前 10 steps；显存取四个 rank 中的最坏值。

| 组合 | 稳态 mean / median / p95 | max allocated | max reserved | 最小物理 free |
|---|---:|---:|---:|---:|
| FSDP，`no_sync`，checkpoint off | 2.972 / 2.934 / 3.377s | 13.270GiB | 16.402GiB | 6.453GiB |
| FSDP，`no_sync`，全量 checkpoint | 3.681 / 3.525 / 4.532s | 13.270GiB | 15.926GiB | 6.930GiB |
| FSDP，每 microbatch 同步，checkpoint off | 3.173 / 3.160 / 3.304s | 11.258GiB | 13.924GiB | 8.932GiB |

`empty_cache()` 口径：

| 组合 | update 100 清理前 / 后最小 free | update 200 清理前 / 后最小 free |
|---|---:|---:|
| `no_sync`，checkpoint off | 6.453 / 18.398GiB | 6.531 / 18.379GiB |
| `no_sync`，全量 checkpoint | 6.930 / 18.369GiB | 6.967 / 18.351GiB |
| 每 microbatch 同步，checkpoint off | 8.951 / 18.359GiB | 8.932 / 18.361GiB |

大量 reserved cache 可被 `empty_cache()` 释放，但它不是可直接计入新模型的永久预算；选择仍按最坏
allocated、清理前物理余量和长期是否爬升共同裁决。三组 reserved 在 100-200 steps 均未持续
增长。

| steps | `no_sync` / checkpoint off | 全量 checkpoint | 每 microbatch 同步 |
|---:|---:|---:|---:|
| 6k | 4.95h | 6.13h | 5.29h |
| 12k | 9.91h | 12.27h | 10.58h |
| 30k | 24.76h | 30.67h | 26.44h |

6k/12k/30k 分别另加约 1.7/3.3/8.3 分钟；一次 resume load 约 11.45s。用户授权的正式 12k
采用连续训练、训练后离线合并 6k/12k 再做同构生成评测，不在训练进程内插入 eval。因此上表
只估算到达训练 checkpoint 的时长，后处理和 27 组生成耗时另计。

裁决：M600-D 首轮使用 `FSDP + no_sync + activation checkpoint off`。它已有 6.453GiB 最坏物理

全量 checkpoint 只多出 0.477GiB，却使稳态均值慢 23.9%，当前不采用。若加入新组分或继续扩

## M600-D 执行门禁

### 转换门禁

- 来源 P500 路径、SHA256: redacted
- 22 个来源 block 各映射一次，新增 block 恰好 18 个；
- 所有来源非 block tensor 精确复制；
- 与历史 HighLR Phase-B 一致，只转换 P500 `model_state_dict`；补齐 unsupported P rows 后从
  transition weights 新建 fresh EMA，禁止继承 P500 的 EMA counter；
- 目标 DiT 参数量精确等于 `602,599,648`；
- optimizer/scheduler 不继承，并在 transition metadata 明确声明 fresh optimizer、fresh EMA policy；
- FP32 eval 下对多个长度、timestep 与 CFG/drop 组合完成逐层和最终输出等价性审计。

### 训练工程门禁

- CPU checkpoint round-trip 与有限值审计；
- GPU set 隔离单卡 forward/backward/update 显存 probe；
- 四卡 FSDP 10-step，确认所有来源层和新增层按预期更新；
- 连续 10 与 5+resume5 对 model shard、EMA shard、optimizer、scheduler、rank RNG 和数据游标；
- 分片 checkpoint 离线合并后能由真实推理入口读取；
- 与 338M control 的 step-0 输出差异来自允许的浮点/分片误差，不得出现听感退化。

### 分阶段训练门禁

```text
10-step smoke
  -> 连续正式训练到 12k，保留 6k/12k checkpoint
  -> 结束后固定 27 组同构推理与盲听
  -> 12k 明确领先才讨论 30k
```

6k/12k 必须与 `V4PH-30K-HIGHLR` 的同 step checkpoint 使用相同推理协议比较。Loss/FlowB 只
证明训练健康，不替代音色、噪音、咬字、旋律和高音稳定性的听感裁决。

## 对 1.5B 的含义

- D 明确胜出：证明增加深度容量有价值，但不自动证明 `1024 x 101` 或 `2048 x 25` 最优；
- D 持平：在实现和训练门禁健康的前提下，暂缓 1.5B，必要时用 B 判断容量布局问题；
- D 退化：先检查新层唤醒与遗忘，禁止用更大模型掩盖问题；
