# 音色优先来源重审

## 1. 触发结论

固定 27 组听评已给出两条关键结果：

```text
V4IjPH 相对 V4IPH 仅轻微改善，仍不及 V4PH。
V4PH 的音色远不如 V4fg。
```

用户据此决定暂停继续堆叠 PH 家族的小结构实验，等待 M 分支；当前不启动 V4KPH、V4PHg 或
其他新长训。

## 2. 原来源假设失效

初版 M 设计曾把 V4IjPH v2 final 作为候选来源。V4IjPH 已未通过感知晋级，因此禁止把它默认为
正式 V4M 来源。

函数保持扩模只能保持一个来源 checkpoint 的函数，不能自动融合两个来源的优点：

| 来源 | step 0 能保持的优势 | 同时继承的问题 |
|---|---|---|
| V4fg 10k | 当前最佳音色、285k online VAE 适配 | 没有 H/PUL、GAME MIDI_P 或 INS 接口 |
| V4PH 30k | H/PUL 与 GAME MIDI_P 结构控制 | 音色远不如 V4fg，且绑定 official VAE |
| V4IjPH 30k | PH 接口与 INS adapter | 感知未晋级，且音色不可能优于其上界 V4PH |

因此“扩到 1.5B”本身不是音色改善方案。若来源是 V4PH，函数保持门禁成功只证明大模型在
transition 时没有进一步变差，不证明后续训练会自动达到 V4fg 音色。

## 3. M 启动前必须重做的裁决

正式实现转换器前，先冻结 M 的首要目标：

1. 若音色优先，应以 V4fg 作为来源候选，并把 H/P 等控制重新视为扩模后的后续接入问题；
2. 若控制接口优先，可从 V4PH 出发，但必须接受 step 0 保留弱音色，并建立对 V4fg 的持续听感门禁；
3. 不允许声称函数保持转换可以跨 checkpoint 合并 V4fg 音色与 V4PH 控制；
4. 来源、VAE、输入 schema、训练数据与目标函数必须一起冻结，不能只按参数量决定；
5. 新增容量是否改善音色只能由训练后的固定同名听评裁决，loss/FlowB 不替代听感。

## 4. 当前状态

- M 继续保留为后续主期待方向；
- 原 V4IjPH 候选来源已撤销；
- V4fg 与 V4PH 的来源取舍尚未裁决；
- 转换器、transition checkpoint、FSDP smoke 与正式训练均未启动；
- 在新来源与目标获得用户明确授权前，不消耗 GPU。
