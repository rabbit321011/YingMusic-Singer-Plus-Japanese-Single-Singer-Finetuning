# 脏源训练增强全网调研

## 研究目标

寻找有论文或真实训练代码支撑、能把干净数据变成贴近真实推理 source 的脏数据、并以 clean singing 为监督目标的训练增强方法。所有候选都要核验原始来源、训练调用、参数、数据要求、许可证和本项目适配性；不根据算子名称自行补全实现。

## 项目约束

- 任务：target singer + 任意旋律 source + 日文歌词，输出干净target singer歌声。
- 旋律表示链：`source -> SOME -> MIDI_P -> F0 -> MIDI`；Singer 训练前向只实际使用 `source` 产生的 `MIDI_P [B,T,128]`，不存在标量 F0 或 MIDI 条件入口。
- 当前训练由同一条干净target singer waveform 同时产生 clean target latent 与 SOME `MIDI_P`。关键代码位于 `YingMusic-Singer-Plus-src/train_plus_v4c.py:364-394`。
- 项目没有时间对齐的 lead/harmony 多轨训练数据。
- 当前 `MIDIFuzzDisturb` 仅启用 `equal_space [1,9]` temporal dropout；其既有目的为压制 MIDI_P 残留语义泄漏，不等同于 source 域仿真。
- 已知推理 source 域包括极高音、VOCALOID 异常发声、重度混音、异常和声及伴奏分离残留。极高音属于应保留的旋律信息，不能默认作为 target 不变的噪声。

## 证据分级

| 等级 | 要求 |
|---|---|
| A | 官方论文 + 官方代码，且能定位真实训练调用、配置和结果 |
| B | 官方论文给出完整算法/参数并有独立可靠实现，或官方训练代码清楚但论文证据较弱 |
| C | 论文方法可信但代码、关键参数或数据不可得；仅可作设计参考 |
| D | 推理代码、未调用 helper、社区猜测或只有算子名称；不得称为训练实现 |

每个候选还要单独标注：是否需要多轨/配对数据、是否保持 melody/lyrics/时序、扰动进入哪个分支、clean target 是否成立、是否能改变 SOME 输出但不摧毁主旋律。

## 搜索与验真日志

### R2-SVC Wet Sound Simulation

原始来源：

- 论文：<https://arxiv.org/abs/2510.20677>
- HTML：<https://arxiv.org/html/2510.20677>
- Demo：<https://c9412600.github.io/svc/index.html>

已证实：

- Wet 仅包含 Harmony、Echo、Reverb，作用于 waveform，三者独立触发。
- 概率分别为 `0.30 / 0.40 / 0.40`，mixing ratio 为 `0.40 / 0.35 / 0.50`。
- perturbed input 对 clean waveform target。
- 论文明确写明 Wet 应用于除 F0 extractor 外的所有模块；Jitter/Glide/Jump 属于独立的 Random F0 Perturbation，不属于 Wet。

缺失与限制：

- Harmony、Echo、Reverb 的具体算法、参数范围及 mixing ratio 公式均未公开。
- 未发现 R2-SVC 官方仓库、模型、补充材料或可靠第三方复现。
- SRE 消融同时移除 Wet 与 F0 perturbation，不能隔离 Wet 的贡献。
- 原拓扑明确绕过 F0 extractor；把 Wet source 送入本项目 SOME 以改变 MIDI_P 属于新改造，不是论文复现。

证据等级：C。

### YingMusic-SVC 多轨和声增强

原始来源：

- 论文：<https://arxiv.org/abs/2512.04793>
- 方法段：<https://arxiv.org/html/2512.04793#S3.SS3>
- 官方仓库：<https://github.com/GiantAILab/YingMusic-SVC>

已证实：

- 使用约 500 小时内部专业多轨数据，包含时间对齐的 lead 与 backing/harmony vocal stems。
- 训练构造为 `x_mix = x_lead + alpha * x_harm`，mixed input 进入 content/mel 条件分支，监督目标保持 clean lead mel。
- 原用途是模拟人声分离后残留背景和声，使 SVC 抑制 harmony leakage，而不是生成或保留和声。
- 论文未公开 `alpha` 的取值、分布、触发概率和响度处理。

项目判断：方法目标与异常和声/分离残留高度相关。当前工作区没有检索到明确拆成 `lead vocal / backing or harmony vocal` 的对齐多轨资产；常见的 `vocals / bass / drums / other` 四 stem 或项目分离器的 `vocals / other` 输出不满足该条件，因为其中 `vocals` 仍把主唱与和声合在一起。若另有四轨数据实际包含独立 lead/harmony vocal，则需按轨道定义重新审计，不能继续假设“没有数据”。任意异步人声叠加或自行 pitch shift 仍不是 YingMusic 原方法。

证据等级：C（方法明确，关键数据与公开训练实现不可得）。

### YingMusic-SVC Remix Echo/Reverb

来源：

- 实现：<https://github.com/GiantAILab/YingMusic-SVC/blob/main/Remix/auger.py>
- 调用：<https://github.com/GiantAILab/YingMusic-SVC/blob/main/gradio_app.py>

已证实：代码用 torchaudio/SoX 实现 Echo 与 Reverb，但在 `run_inference()` 结束后对 `vc_path` 做效果并混回伴奏。它是推理输出后处理，不是训练输入增强。函数默认 wet 值与 R2-SVC 的 `0.35 / 0.50` 相同不能证明 R2 训练实现；实际 wrapper 配置又使用 `0.18 / 0.25`。

证据等级：D，不纳入可用训练扰动器。

## 第一轮跨领域宽搜与纠错

Agent Reach 第一轮宽搜覆盖 arXiv、ICASSP/ISCSLP、GitHub、Hugging Face 和项目页，得到 ROSVC、RobustSVC、SVC with Accompaniment、Degradation-Robust VC、REF-VC、SPA-SVC、URGENT 等候选。报告中以下推断已拒绝：

### ROSVC Robustify

来源：

- 论文：<https://arxiv.org/abs/2210.11096>
- Demo：<https://t-naoya.github.io/rosvc/>
- D3Net：<https://github.com/sony/ai-research-code/tree/master/d3net>

训练流程：

`X_dirty = Mel(D3Net(x_clean * RIR + instrumental))`。先在 clean data 上训练完整 one-shot SVC，再冻结原模型，在 content encoder 与 style encoder 中插入 pre/post enhancement blocks，只训练这些 blocks，使 dirty embedding 对齐原 frozen encoder 的 clean embedding。为避免破坏 clean 输入，还同时约束 enhanced encoder 对 clean 输入保持原 embedding。

数据构造细节：

- 20 个由 reverb plug-in 生成的 RIR，80/20 train/test split。
- 混响输入为 `gamma * (x * r) + (1-gamma) * x`，`gamma` 从 `[0,1]`随机采样。
- MUSDB18 的 bass/drums/other 各自随机缩放到 `[0.75,1.25]`后相加为 instrumental；不需要与 clean vocal 对齐。
- 混合后真实运行 D3Net，训练对象看到的是分离残留而非理想加法混合。

证据：Table III 对 source/reference 不同污染组合及 MUSDB18 真实样本直接比较 w/ 与 w/o Robustify；最难 synthetic 条件的自然度/相似度由 `3.24/3.44` 提升到 `3.85/4.22`，MUSDB18 由 `3.54/3.76` 提升到 `3.87/4.22`。

论文把主链路写到了公式级：`X' = Mel(D3Net(x * r + m))`；训练细节还给出 dry/wet RIR 混合 `gamma*(x*r)+(1-gamma)*x`、MUSDB18 `bass/drums/other` 各自 `[0.75,1.25]`缩放、20 个插件生成 RIR 的 80/20 划分，以及冻结原模型只训练 enhancement blocks。但它没有公开全局 accompaniment/vocal 混合电平或 SNR、RIR 插件与预设、完整 D3Net checkpoint/config、随机裁剪/归一化和训练仓库。因此它是清楚的研究链路蓝图，不是能复现作者 dirty 分布的完整配方。

限制：无官方训练仓库或可靠复现；其 enhancement-block 结构属于 ROSVC encoder，不能声称可直接插入 SOME。项目可直接借鉴的是“混合 -> 部署同类 separator -> clean/dirty 表示对齐”证据，任何具体接法仍是新工程，也不能称为 ROSVC 等价复现。

证据等级：C。

### RobustSVC

来源：

- 论文：<https://arxiv.org/abs/2409.06237>
- Demo 仓库：<https://github.com/wei-chan2022/RobustSVC>

论文在约 30 小时 OpenSinger 子集与 MUSDB 上训练 HuBERT-based melody extractor。训练期间将 MUSDB random BGM 覆盖到 clean vocal，输入 noisy singing，监督 pitch/energy/VUV clean sequences；HuBERT 在 5k step 后冻结。噪声测试覆盖 0/5/10/15 dB，RobustSVC 在各档均优于直接 Pitch&Energy 与 separation baseline。

限制：论文没有公开训练混合概率和完整 SNR 采样规则；GitHub 仓库仅包含 Jekyll Demo 与音频，没有训练代码、配置或 checkpoint。论文的组件消融没有把 BGM augmentation 单独移除，因此不能隔离其贡献。

证据等级：C。

### Singing Voice Conversion with Accompaniment Using SSL Melody Features

来源：

- 论文：<https://arxiv.org/abs/2502.04722>
- Demo：<https://ccchange2024.github.io/SVC-with-Accompaniment/>
- Demo 仓库：<https://github.com/ccchange2024/SVC-with-Accompaniment>

这是与 RobustSVC 同一研究线的 ICASSP 2025 后续。melody extractor 使用 HuBERT/WavLM 各层 weighted sum + 3 个 FFT blocks，预测 clean pitch、energy、VUV；clean pitch 标签取 PYIN、REAPER、Parselmouth 三者中位数。OpenSinger clean vocal 以 50% 概率加入随机 MUSDB BGM，MUSDB 自带 mix/vocal/stems 也用于训练。测试 BGM SNR 为 0/5/10/15 dB，各占 25%。

论文结果显示 proposed WavLM 在 BGM 条件的 F0RMSE/F0CORR 明显优于原始 pitch/energy、CREPE 和 Demucs+CREPE；但训练时 BGM 的 SNR/响度混合公式未公开，Demo 仓库无训练代码。

项目意义：它直接证明“无需对齐多轨，用随机公开 BGM 训练 melody extractor 从脏输入恢复 clean melody”在 SVC 上成立。把相同数据构造用于 SOME 或把 dirty SOME 输出送给 Singer，均属于后续适配，不能称为论文原实现。

证据等级：C。

### Toward Degradation-Robust Voice Conversion

来源：

- 论文：<https://arxiv.org/abs/2110.07537>
- 第一作者入口：<https://github.com/cyhuang-tw/robust-vc>
- 共同作者完整 MIT 仓库：<https://github.com/ga642381/RobustVC>
- WavAugment：<https://github.com/facebookresearch/WavAugment>

这是 speech VC，不是 SVC，但公开证据完整。官方 `AdaIN-VC-robust/data/dataset.py` 以 `clean_wav_ratio=0.4` 保留 40% clean、60% dirty；`data/noise.py` 对 dirty data 使用 DEMAND 加性噪声及独立 50% reverb、50% band rejection。训练 SNR 从 `{0,5,10,15}`采样，测试用未见的 `{2.5,7.5,12.5,17.5}`。`train.py` 明确用 `noisy_mels` 输入、`clean_mels` 作为 reconstruction target。S2VC-robust 也由 dataset 返回 dirty source 和 clean ground mel。

WavAugment 提供实际调用的 libsox/PyTorch EffectChain，MIT 许可，支持 reverb、additive noise、band reject、clipping、time dropout 和 pitch randomization。仓库已归档，但代码与论文训练调用可核。

限制：全部实证来自英语 speech；DEMAND 环境噪声、低频 band rejection 与当前伴奏/和声失败域不等价。可复用的是 denoising-training 契约和代码组织，不是其退化集合在歌声上的有效性结论。

证据等级：A（实现与论文完整），项目相关性中等。

### OpenVPI SOME 原训练增强

来源：本地官方仓库 `TEMP/OpenVPI-SOME`，上游 <https://github.com/openvpi/SOME>。

SOME 的 train binarizer 对每条训练样本额外生成 8 个 `[-12,+12]`半音 key-shift 版本，Mel 前端按 key shift 重算，同时 `pitch` 与 `note_midi` 标签同步平移。它扩展音域并保持 input/target 等变，不制造 dirty input；没有 noise、BGM、RIR 或 separation-artifact augmentation。

证据等级：A（真实官方训练调用），但不属于本目标的 source corruption。

### OpenVPI GAME

来源：

- 官方仓库：<https://github.com/openvpi/GAME>
- 技术报告：<https://github.com/openvpi/GAME/blob/main/ALGORITHMS.md>
- 训练实现：<https://github.com/openvpi/GAME/blob/main/training/augmentation.py>
- 真实 dataset call site：<https://github.com/openvpi/GAME/blob/main/training/data.py>

GAME 是 SOME 的官方下一代 MIDI extractor。仓库提供 MIT 训练代码、预训练 PyTorch/ONNX 模型和 clean/dirty 评测，README 明确声明可处理 noise、reverb、accompaniment 与 separated voice。

默认在线增强：

- colored noise：`p=0.25`，PSD exponent `U(0,2)`，代码中振幅指数从 `[-6,-1]`采样。
- natural noise/accompaniment：`p=0.25`，每次叠加 1-3 条 noise/music；各条通过重解释采样率获得 `0.5x-2x` playback zoom、随机 offset、`[-12,+12] dB` gain；合并后按 clean/noise peak ratio 归一，再以 `[-24,-6] dB`相对峰值混入。技术报告称 6-24 dB SNR，但代码实现是 peak ratio，不是 RMS SNR。
- RIR：`p=0.25`，用随机 kernel 做 FFT convolution，按 RIR 峰位置裁回原长并 peak-normalize；不额外混入 dry signal。
- pitch shift：`p=0.5`、`[-12,+12]`半音，输入 Mel 与 clean score 标签同步平移，属于等变音域增强。
- loudness scaling：`p=0.5`、`[-6,+6] dB`。
- spectrogram masking：time/frequency 各 `p=0.15`，最大 50 帧/20 Mel bins，交叉模式概率 `0.5`。

训练 `MIDIExtractionDataset` 实际调用 waveform chain -> Mel -> spectrogram chain，只有 pitch shift 会同步修改 score；noise、RIR、mask 均保持 clean MIDI target。验证可返回同一样本的 clean 与 deterministic dirty spectrogram，并报告 dirty metrics。公开训练数据约 32 小时私有四语歌声，增强资产使用 DEMAND、MUSAN、MIR-1K、MusicNet、MUSDB18-HQ 和 MB-RIRs。

限制：技术报告提供 clean/dirty 绝对指标和三种模型规模比较，但没有 no-augmentation control，不能单独证明每种增强的因果贡献。GAME 输出为 region/boundary/257-bin note 表示，不是 Singer 当前消费的 SOME `[T,128]` logits，不能直接替换 checkpoint。

项目意义：其 augmentation module 与数据需求本身不依赖 GAME 表示，是目前找到的最完整、最接近 SOME、且真实用于歌唱 MIDI extractor 训练的 clean->dirty 工具。复用该 pipeline 处理 source copy 后继续走当前 frozen SOME，是来源明确的工程适配；是否足以覆盖target singer推理 source 仍需固定真实失败集检验。

证据等级：B（官方技术报告 + 完整训练代码 + release + dirty 评测，无同行评审论文/因果消融）。

### RMVPE 与社区训练 fork

来源：

- 论文：<https://arxiv.org/abs/2306.15412>
- 作者仓库：<https://github.com/Dream-High/RMVPE>（Apache-2.0）
- 社区 fork：<https://github.com/yxlllc/RMVPE>（仓库没有许可证）

作者仓库确有 `train.py` 与 `src/dataset.py`，但在线训练代码只从准备好的 MIR-1K waveform 读取音频，没有 noise/RIR 在线增强。论文中的 RMVPE-Poly 与 RMVPE-Vocal 主要区别是训练数据使用 polyphonic mixture 还是 clean vocal；论文用白/粉/棕/pub noise 做 0 dB 测试，不应误写为训练增强。

`yxlllc/RMVPE` 是可核验的后续真实训练实现。`train.py` 对训练集明确传入 `use_aug=True`，`src/dataset.py` 实际执行：

- `key_shift ~ U(0, 5)` 半音，并同步移动 cent/pitch label；
- 对单声道样本加入 PSD exponent `U(0,2)`、幅度 `10^U(-6,-1)` 的 colored noise；
- 对 MIR-1K 双声道样本把 channel 1 作为 vocal、channel 0 作为 accompaniment/noise，并以 `U(-1,1)`缩放后叠加；
- 对混合后 waveform 施加随机音量缩放。

README 说明其训练数据是处理后的 MIR-1K、PTDB 与 M4Singer vocoder 合成数据。该 fork 没有许可证、没有增强消融，也没有证明 VOCALOID/UTAU/SynthV 域鲁棒性，因此只能作为“有人真实这样训练 pitch extractor”的实现参考，不能直接复制代码或把结论外推到 Singer。

项目判断：RMVPE 输出连续 pitch/class posterior，不是当前 Singer 的 SOME `[T,128] MIDI_P` 接口。它适合用于真实失败集诊断或作额外 teacher 参考，不是 drop-in 替换项。

证据等级：作者 RMVPE 为 A（模型论文与训练代码），但其 noise 只用于测试；`yxlllc` 增强分支为 C（真实训练调用明确，但非作者方法、无许可证与消融）。

### 合成音色与 representation perturbation 负结果

#### ContentVec

来源：<https://github.com/auspicious3000/contentvec>

官方训练 dataset 的 `random_formant_f0()` 同时随机改变 formant、pitch scale 与 pitch range，随后再做 10-band random EQ。它的目标是让 SSL content representation 丢弃音色和 F0 信息。因为本项目要从 source 保存旋律，而不是让表示对音高不变，所以不能把 ContentVec information perturbation 当作 melody-preserving WET；也没有来源证明“只删除 F0 部分、保留 formant”仍是原方法。

#### Seed-VC

来源：<https://github.com/Plachtaa/seed-vc/blob/main/train.py>

官方 `train.py` 的确用 OpenVoiceV2 转换 waveform 音色，再从转换后 waveform 提取 `S_alt` semantic tokens。但 target mel 仍来自原 waveform，若启用 F0 条件，`F0_ori` 也从原 waveform 提取。它证明的是“改变音色后训练 semantic representation”，不是“转换后的 waveform 可直接送 SOME 且保持 melody”；因此不纳入现成 source augmenter。

#### VOCALOID/UTAU/SynthV

Agent Reach 对 arXiv、GitHub 与 Exa 组合搜索没有找到专门针对 VOCALOID/UTAU/SynthV 异常发声到真实歌声的 robust melody/MIDI extractor 训练方法。M4Singer vocoder 合成数据、SPA-SVC pitch augmentation 与 SingAug 都不是这一问题的直接证据。当前将其记录为公开研究空白，不自行补算子。

## 增强资产的许可与可获得性

## 本项目接入审计

### 真实训练数据流

`YingMusic-Singer-Plus-src/train_plus_v4c.py:357-394` 当前对同一条 waveform 做两件事：

1. `vae.encode_audio(w_2d)` 生成 clean target latent，并从其前缀构造 reference `cond`；
2. `MelodySpectrogram(w_2d) -> frozen midi_teacher` 生成 `midi_p`，再经 `MIDIFuzzDisturb` 成为 Singer melody condition。

因此 source-WET 的正确边界是复制 waveform：

```text
clean_wav ───────────────> VAE ──> clean target latent / clean reference cond
    └─ copy -> augmenter -> MelodySpectrogram -> frozen SOME -> dirty MIDI_P -> Singer
```

污染不得进入 clean VAE target 或 reference cond。增强必须保持样本长度与时间轴；pitch-shift 若只作用 source 会改变旋律语义、让 target 不再成立。

`train_plus_v5a1.py:387-388` 当前 Phase 1 会把 `midi` 强制清零，所以它无法检验 source robustness。WET 实验必须从仍实际消费 melody condition 的 V4c 或等价后继训练分支开始。

### GAME 不能整包照搬

第一阶段可忠实复用的是 GAME 的 waveform-domain destructive chain：

- colored noise；
- natural noise/accompaniment；
- RIR convolution。

代码层面可调用 `build_augmentation_chain(..., destructive_only=True)` 并只取返回的 `wav_chain`，或者做保持算法和参数不变的 PyTorch 等价移植。当前训练在进入 `process_batch()` 前已把 waveform 放到 GPU，而 GAME 使用 NumPy/librosa/scipy；若直接调用会产生每步 GPU→CPU→GPU 同步。更合理的工程位置是 Dataset worker：同时返回 `clean_wav` 与同长度 `source_wav`，再分别送入两个分支。这个位置调整是本项目适配，不是 GAME 原实现。

第一阶段不纳入：

- pitch shifting：GAME 会同步移动 score label；本项目若保持原 clean waveform target，不能只移动 source。这不代表极高/低音不能靠变调构造：若存在经验证、保持时长且充分保留target singer与音质的 waveform pitch shifter，应先把 clean waveform 与旋律标签同步移动，令变调后的 clean waveform 成为新 target，再从它复制 source 做 WET。GAME/SOME 当前的 key-shift 只在 Mel 前端与 MIDI label 上同步移动，并没有为 Singer 生成可用的 clean waveform target，不能直接承担这一步。
- loudness scaling 与 spectrogram masking：它们作用于 GAME 自己的 Mel，不是 waveform WET。可以后续单独评估，但不能伪装成真实推理 source。
- backing vocal/harmony：GAME README 明确要求 natural-noise 目录不要包含 singing voice 或 clear speech，因此 GAME 不能为无多轨 harmony 问题背书。

### 分离残留的最高拟真方向

ROSVC 给出的研究流程 `clean vocal * RIR + random instrumental -> D3Net -> dirty vocal` 与“用户先混音/分离，再把残留人声送入系统”的推理链最接近，而且随机 instrumental 不要求和 clean vocal 对齐。项目本地已有 separation 推理框架，但把它接进训练仍必须：

- 使用与部署相同或明确记录的 separator/checkpoint；
- 保存 separator 输入、输出和随机混合参数；
- 先离线缓存，避免每个训练 step 在线跑重型分离模型；
- 明确标为 ROSVC 启发的项目复现，因为 ROSVC 没有官方训练代码。

R2-SVC 的 Echo/Reverb/Harmony 没有实现细节，YingMusic-SVC `Remix/auger.py` 又是推理输出后处理；二者都不能为具体训练实现提供代码来源。

## 候选分级与实验顺序

| 优先级 | 候选 | 能覆盖的真实 source | 当前结论 |
|---|---|---|---|
| P0 | GAME waveform destructive chain | 环境噪声、器乐伴奏、房间混响 | 唯一同时满足歌唱域、官方真实训练调用、参数完整、无需多轨的可执行基线 |
| P1 | ROSVC mixture + RIR + deployed separator | 重度混音、伴奏分离残留、separator artifact | 场景匹配最好；论文给出链路蓝图但关键电平/RIR/checkpoint 与代码缺失，只能做明确标注差异的项目适配 |
| P1 参考 | RobustSVC / SVC with Accompaniment | 未分离伴奏下的 melody extraction | 直接证明随机 BGM 不需 aligned stems；混合细节和代码缺失 |
| P2 | Degradation-Robust VC | 噪声、混响、带阻退化 | A 级实现证据，但只在 speech VC 验证，适合作为训练契约参考 |
| P2 参考 | `yxlllc/RMVPE` | colored noise、MIR-1K 伴奏 | 有真实训练调用但无许可证/消融，只作源码参考 |
| 暂停 | R2 Wet / YingMusic harmony | Echo/Reverb/Harmony | R2 算法未公开；YingMusic 需要项目不存在的 aligned stems |
| 淘汰 | YingMusic Remix、ContentVec、Seed-VC 直送 SOME | 推理效果或 representation perturbation | 不构成 melody-preserving source 训练证据 |

建议按下面顺序实验，避免先训练再猜污染是否有用：

1. 建立固定真实 source 诊断集，至少覆盖极高音、VOCALOID 掐嗓、重混音、异常和声、分离不净；极高音单列为 coverage 问题。
2. 冻结 SOME，在同一批 clean waveform 上生成 GAME dirty copy，记录 clean/dirty `MIDI_P` 与解码旋律差异。先验证主旋律仍可恢复，并把增强强度分布与真实失败集对齐；不预设未经测量的通过阈值。
3. 第一个训练基线忠实使用 GAME 默认 waveform 参数，关闭 source-only pitch shift，不启用 spec masking。保留 clean target，只让 Singer 学习容忍 dirty `MIDI_P`。
4. 用 GAME 配置原生的 enable/disable 做单项消融：natural accompaniment、RIR、colored noise。不要自行改出一套无来源参数后再称为 GAME。
5. 若真实分离残留仍是主要失败，离线加入 ROSVC 路线：随机 instrumental + RIR 后跑实际 separator，再把输出送 SOME。
6. 用相同 checkpoint、训练步数与固定诊断集比较 clean source 和各类 dirty source；除了现有 F0 correlation/ASR/音色指标，必须保留人工听测，因为“输出听起来干净”不能由 SOME 稳定性单独证明。

## 全网负发现与搜索局限

- 没有找到“公开论文 + 作者训练代码”同时真实模拟 music source-separation artifact 的方法；ROSVC 有论文公式但无代码。
- 没有找到不需要 aligned lead/harmony stems、又有公开训练实现的 backing-vocal/harmony leakage augmenter。
- 没有找到 VOCALOID/UTAU/SynthV 异常发声专用的 robust melody/MIDI extractor 训练方法。
- Echo、compression、clipping、distortion 在通用音频库中有实现，但本轮没有找到它们在相同歌唱 melody/SVC 目标上的真实训练证据，因此不凭常识加入候选。
- Agent Reach 本轮 GitHub API 遇到 403，改用仓库 raw URL、Git clone、Zenodo API 与 OpenSLR 原页面人工核验。其报告曾误称 GAME 有增强消融、RMVPE fork 无增强、RobustVC 只有推理代码及 MB-RIRs 为 CC BY 4.0；这些说法均未采纳。

## 最终结论

全网调研支持“做 source-WET”这条路线，但不支持把 R2-SVC 的 Wet 当成一个已经公开、可复现的扰乱器包。当前最稳的落点是：以 OpenVPI GAME 的 waveform destructive chain 作为可执行训练基线，把 clean waveform 复制后只污染 SOME 分支；再以 ROSVC 的“混合 + RIR + 实际 separator”作为更贴近分离残留的第二阶段。

其中真正与当前推理分布最相关的是 natural instrumental/accompaniment 和 separator residual。Colored noise 与 RIR 有真实训练证据，但覆盖面更窄；pitch shifting、spec masking、ContentVec/Seed-VC perturbation 不应混入第一阶段。异常和声仍是公开方法与当前数据资产都没有解决的缺口，不能用任意异步叠人声冒充 YingMusic-SVC。
