# 四轨与训练切段对齐审计

## 问题

核验 MSST 处理过程中产生的 `ins / echo / noise / vocal` 四条整曲 stem，能否映射到 V4/V5 实际加载的分割训练样本。

## 服务器事实

服务器为 `${SERVER_USER}@${SERVER_HOST}`。新数据管线原始输入为 1,417 首歌曲，依次运行：

```text
original
  -> inst/vox separation: Vocals + Instrumental
  -> dereverb/echo:       dry + other
  -> denoise:             dry + other
  -> step4_final:         final clean vocal
```

四个概念 stem 因而对应：

- `ins`：第一步的 Instrumental；
- `echo`：第二步从 vocal 中移除的 other；
- `noise`：第三步从 dry vocal 中移除的 other；
- `vocal`：第三步最终 dry 输出。

当前服务器 `${SERVER_ROOT}/large_dataset/MSST_3step/` 只保留：

- `step4_final/`：1,417 条最终 vocal 整曲；
- `cut_manifest.json`；
- `trim_manifest.json`；
- `rms_manifest.json`。

`step1_vocals / step2_dereverb / step3_denoise` 中间目录当前不存在，因此 `ins / echo / noise` 音频本身不在服务器磁盘。原始输入压缩包 `${SERVER_ROOT}/dataset/hareru_large_dataset.zip`、MSST 模型和运行日志仍在，可另行判断是否重跑恢复。

## 映射方法

最终训练文件名保留原曲名与 `seg###`。`trim_manifest.json` 对每段记录：

- `source_mp3`；
- `segment_file`；
- `cut_start_s / cut_end_s`；
- `trim_start_s / trim_end_s`；
- `trim_dur`。

四轨整曲上的绝对区间可直接计算：

```text
absolute_start = cut_start_s + trim_start_s
absolute_end   = cut_start_s + trim_end_s
```

例如训练样本：

```text
sample_media.wav
```

映射到原曲：

```text
sample_media.wav
[13.897s, 25.136s]
```

区间长度 11.239 秒，与训练 manifest 的 11.239 秒一致。

## 覆盖统计

### 候选全集

| Split | 样本数 | 命中 trim manifest | 未命中 | 覆盖率 |
|---|---:|---:|---:|---:|
| `train_singnet.json` | 15,122 | 14,017 | 1,105 | 92.693% |
| `test_singnet.json` | 307 | 307 | 0 | 100% |

命中样本的 manifest duration 与训练 duration 最大误差 1 ms，没有超过 20 ms 的样本。

### V4/V5 实际 token 数据

训练实际加载：

- L1：7,604；
- L2：3,546；
- L3：840；
- 合计：11,990。

| Split | 实际样本数 | 可映射 | 不可映射 | 覆盖率 | 涉及新管线原曲 |
|---|---:|---:|---:|---:|---:|
| train token L1-L3 | 11,990 | 11,162 | 828 | 93.094% | 1,353 |
| test token L1-L3 | 232 | 232 | 0 | 100% | 40 |

828 条不可映射训练样本均来自旧数据管线，文件名通常含 `_Vocals_dry_dry_seg###`。服务器旧目录只保留分割后的 vocal，没有找到 Instrumental/other stem 或对应的新管线时间 manifest。

## 对齐实测

从 14,017 条可映射训练样本中固定随机抽取 8 条，用绝对时间在 `step4_final` 整曲 vocal 中定位，并与最终训练片段比较：

- 最佳起点相对 manifest 预测值偏差为 0 或 1 sample；
- 训练音频时长相对 JSON duration 的误差小于 0.007 ms；
- 说明 `cut + trim` 时间表确实对应当前训练 waveform，而不只是名称相似。

## 结论

四轨可以对齐到绝大多数实际训练样本。可严格支持的是新数据管线的 11,162/11,990 条训练样本和全部 232 条 token 测试样本。限制不是切段映射，而是服务器已删除前三步中间 stem；旧管线的 828 条实际训练样本目前也没有四轨映射资产。
