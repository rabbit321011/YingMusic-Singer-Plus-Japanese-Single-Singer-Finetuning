# V5-PgO 运行问题记录

## 2026-09-22：训练完成后 auditor 误报 optimizer state 不完整

### 现象

正式训练完整到达 step 8,000，final Eval 与 `step_008000_final.pt` 已成功写出，训练入口打印
`Complete at step 8000`。随后 formal pipeline 在审计 step 1,000 checkpoint 时退出 1；训练输出
和 final checkpoint 不受影响。

### 根因

旧 auditor 要求 optimizer parameter group 中每个 `requires_grad=True` 参数都已经建立 Adam 状态。
PyTorch AdamW 只在参数实际收到梯度后惰性创建状态。PgO 前向图直接使用 GAME-P cache 和
`midi_p_v4ph`，不会调用历史 `midi_extractor.*`；这些参数虽仍在 optimizer parameter group，
但不产生梯度，因此没有 Adam 状态是预期行为。

step 1,000 实测：

```text
optimizer parameter tensors: 947
active Adam states: 367
active set: 366 transformer tensors + midi_p_v4ph.embedding.weight
missing Adam states: 580
missing prefix: midi_extractor.* only
active optimizer step: 1000
```

这不是训练漏更新 DiT 或 P embedding，也不是 checkpoint 损坏。

### 修复

`audit_v5pgo_checkpoint.py` 改为按实际 PgO 计算图验证 active optimizer state：必须严格覆盖全部
`transformer.*` 与 `midi_p_v4ph.embedding.weight`，不得缺少或混入其他 active 参数；允许未进入
计算图的 `midi_extractor.*` 保持无 Adam state。原 formal pipeline 的 exit code 1 作为历史事实
保留，修复后另行重跑 0--8k 全 checkpoint 审计并记录 posthoc 结果。

### 复验结果

修正后的 auditor 已对 step 0、1k、2k、3k、4k、5k、6k、7k、8k 全部 checkpoint 重跑，
九个结果均为 `status=ok`。checkpoint SHA256 清单与 final sidecar 已重新生成；独立记录：

```text
${PRIVATE_PATH} = 0
${PRIVATE_PATH} = status ok
```

结论：原 `fresh_pipeline_exit_code=1` 仅表示旧 auditor 后处理误报，不影响 8k 训练完成状态、
模型权重、optimizer/scheduler/EMA/RNG/cursor 完整性或 checkpoint 可恢复性。
