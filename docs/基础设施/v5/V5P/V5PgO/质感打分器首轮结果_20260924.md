# 质感打分器首轮结果：2026-09-24

## 结论

本轮测的是五首歌、20 条生成候选与参考音频上的用户整体偏好。
DNSMOS SIG 最值得继续验证；没有证明任何打分器已经能可靠表达
花丸质感。未调权重、反转评分方向或启动训练。

| 打分器 | 生成严格偏好同向数 | 各曲同向率平均 | 参考对生成同向数 |
|---|---:|---:|---:|
| UTMOS22 | 6/18 | 35.3% | 25/38 |
| DNSMOS SIG | 15/18 | 79.3% | 29/38 |
| INS 相对原轨余弦 | 8/18 | 49.3% | 38/38 |
| GAME 音高概率诊断 | 9/18 | 52.7% | 38/38 |

18 对来自五个片段，不是 18 个独立实验。15/18 不是已确定的
总体准确率。INS/GAME 的参考比较含原轨自相似的结构性优势，
38/38 不能证明它们识别了目标质感。

## 计分规则

- 不推造绝对质感分或自然度分；本次标签是整体听感偏好。
- 相同来源的暗重复去重。G02 seed137 两次听评冲突，涉及它的
  比较从主指标排除，保留原始反馈。
- `=` 为近似同档，`>=` 暂为弱偏好，不计入严格偏好分母。
- 跨多个层级只要经过 `>` 或 `>>`，可形成严格传递偏好。
- `>>` 没有额外人为权重。
- 评分差绝对值不超过 1e-7 视为数值同分，不是感知等价阈值。
- 生成对生成、参考对生成、参考之间分别统计；同档和弱偏好
  对保留在 JSON 中，不计入严格方向命中率。

每组可用生成严格配对数依次为 5、2、3、5、3。

## 逐曲结果

| 组/曲目 | UTMOS22 | DNSMOS SIG | INS | GAME |
|---|---:|---:|---:|---:|
| G01 相遇天使 | 3/5 | 5/5 | 1/5 | 3/5 |
| G02 夜明けと蛍 | 1/2 | 1/2 | 2/2 | 1/2 |
| G03 旅人 | 2/3 | 3/3 | 1/3 | 1/3 |
| G04 月兔 | 0/5 | 4/5 | 3/5 | 1/5 |
| G05 团子 | 0/3 | 2/3 | 1/3 | 3/3 |

DNSMOS SIG 首选生成依次为 G01_06、G02_03、G03_05、G04_07、
G05_01。前四组落入无歧义候选中的用户最佳生成档，团子失败：
用户最佳生成是 G05_03，末档的 G05_01 却得到更高分
（3.48477 vs 3.38481）。不能用“4/5 命中”掩盖此反例。

UTMOS22 在月兔选择用户生成末档 G04_03，该组五对严格偏好全反；
团子三对也全反。G02/G05 的生成极差仅 0.01156/0.01089，低于
文档暂定 0.02 门槛；上表报告未过滤方向，不将其当强奖励。
即使剔除这两组，剩余也是 5/13。

INS 在相遇天使挑了用户生成末档 G01_02，其原轨余弦 0.98934，
高于最佳档 G01_06 的 0.93423。因此 embedding 接近原轨与
本轮偏好不等价；不据此否定其他唱法保持用途。

GAME 是音高护栏，其 9/18 不否定护栏用途。月兔用户偏爱 VAE
而非原轨，但 INS/GAME 自相似天然偏爱原轨，说明“贴近原轨”
与“更喜欢”不能混同。

## 评分输入与边界

依据 `docs/基础设施/v5/GRPO/GRPO完整计划.md` 的四个基础轴执行。
没有用旧 V4c DNSMOS P808 代替 SIG。DNSMOS JSON 还保留
P808/BAK/OVRL 原始输出，但它们不是主分析轴。

### UTMOS22 与 DNSMOS SIG

从已校验盲听 B 截取段生成 44.1k mono PCM24 副本，仅常数增益
至 -28 dBFS RMS，不做 EQ、限幅或降噪。复用现有
`score_noise_tier_models.py` 及冻结权重。权重、实现、输入 manifest
SHA256 随结果保存。暗重复独立前向，不用缓存伪造重复一致性。

本轮未构建或消费 Q100 表，只分析 raw 单轴方向；没有按 7:3
直接混合 raw MOS 冒充 QUA，没有计算正式 3:2:4 总奖励。
正式权重与训练合同未修改。

### INS

严格加载既有 ParaSpeechCLAP Intrinsic checkpoint：
`SHA256_REDACTED`。
输入实际等 RMS 盲听 B，复用 `ParaSpeechClapIntrinsic.encode`
的 44.1k→16k 重采样、归一化 embedding，与本组 source_B 求余弦。
不混入 A。只分析 raw cosine，未做训练参考标定映射。
个别自相似有约 1.2e-7 的浮点超 1 误差，保留 raw 值审计。

### GAME

为补齐完整上下文，同模型、同 A/H/P、同 seed 复跑并保留 A+生成 B。
前四组试听段逐字节复现；团子不是 bit-exact，但已归档的试听段
覆盖整个 B，可直接恢复真正被试听的完整 B。

所有组统一将有效评分区域替换为最初归档的 PCM16 候选波形，
仅缺失的外围生成上下文来自复跑。团子替换整个 B。
没有将原唱 B 冒充生成 B，没有修改用户试听文件。
有效上下文 float32 波形 SHA256 随 GAME 结果保存。

冻结 GAME medium 权重：
`SHA256_REDACTED`。
完整上下文 K4，再在试听 B 范围内的 latent-frame 中心取 128 维
整数音高 posterior 和 voiced/REST；同组共用 GAME RNG seed。
双方有声取概率余弦，状态不一致为 0，双方 REST 为 1，
按 target voiced/REST 平衡均值；空层仅平均现存层并记录计数。
这是有明确约定的离线诊断，不冒充已完成正式 GRPO 的全部
时间映射、空类与可靠性标定门禁。

四个评分轴在两组暗重复上的差值全部为零。

## 执行问题与验证

1. INS 旧环境 `style_clap/bin/python` 链接失效。未修改用户环境，
   改用现存 `yingmusic_plus/bin/python3`，严格权重加载及编码成功。

   最大单点最高 0.0012207。原因未定，不解释为质感变化。
   已用归档完整 B 恢复原评分对象。
3. GAME 合并缓存有 `language=ja`，无 `language_id`，首次硬停。
   改为严格查冻结 GAME 的 language_map，不静默回退，随后完成。
4. 排序单测 2/2 通过，覆盖弱偏好传递、去重、冲突排除与
   scorer 重复性失败检查。四个评分 JSON 回读 SHA256 均匹配服务器。
5. 本次只传脚本和小 JSON，无超过 2 MB 的新通信；完整上下文和
   评分副本留在服务器。所有推理评分已退出，未启动训练。
