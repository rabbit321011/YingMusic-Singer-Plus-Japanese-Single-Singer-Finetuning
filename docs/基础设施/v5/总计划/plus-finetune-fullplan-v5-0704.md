### 1.4 根因诊断（材料6 + SVC N 形曲线联合分析）

**三症状不再假定共享同一根因**：

> 文本条件信号的时间标签噪声过大（P95=6.62s ≈ 142帧 @ 21.53Hz），导致 MSE 在过宽的条件集上取均值。材料5 的"平均化税"理论和"收窄条件集"方向完全正确，但执行清单没有对齐理论——最直接最便宜的收窄手段（对齐重做）被埋在了昂贵的方案下面。
>
> **但唱功退化的根因不同于前两个症状**：YingMusic-SVC 微调实验中，3k 步（CFM cos=0.999999）听感全局最佳，3k→10k 穿谷，60k「厚重、清新感不可逆丧失」——eval loss 全程正常。SVC 没有 text 对齐环节，却出现与 V4 浴室感同型的听感退化。这构成「唱功退化不由对齐导致」的独立证据。

| 症状 | 头号嫌疑 | 修复归属 |
|------|---------|---------|
| FlowB 卡 0.90 | 对齐噪声 | P0 |
| B 区字位漂移 | 对齐噪声 | P0 |
| **唱功退化/浴室感** | **底模漂移 + 小数据均值化** | P1/P2 训练纪律（见 §十一） |

**对齐噪声的证据链**：

| 证据 | 含义 |
|------|------|
| P95=6.62s，目标 ±0.5s | 差一个数量级。142 帧比一句歌（43-108 帧）还长，text token 可被整句放进错误区域 |

## 三、P0：重做对齐（最高优先级）

### 3.1 核心思路

**分块是最大单一杠杆**。A3 实验已证明：WhisperX 无边界时 P95=10.02s，有 A7 粗边界引导时降到 1.27s——差 8 倍。A2 用 MFA 全局对齐 P95=9.37s，因为整条音频对齐导致误差逐句累积。

正确做法：**A7 先粗分句 → 在每句 ±窗口内局部强制对齐**。分块后误差不再累积，任何对齐器表现都会质变。

分块窗口宽度须按 A7 误差分布设定（如 ±P90），避免尾部样本真实边界落在窗口外导致对齐器在窗内找假边界。强制对齐的置信分数（MFA 有 per-utterance log-likelihood）低于阈值的样本标记为可疑而非采信——这批样本正是 L1 假消息的主要来源。

[此处参照 材料6 §三、DATA_PIPELINE_Timeset.md §2.6]

### 3.2 bake-off 四候选

| 配置 | 对齐器 | 声学模型 | 分块 | 预期 |
|------|--------|----------|:----:|------|
| **B1** | MFA | target singer 99h 自训 | A7 | 最可能赢（域匹配 + 论文支持） |
| **B2** | MFA | japanese_mfa（语音模型）| A7 | 检验 A2 失败多少来自不分块 |
| **B3** | SOFA | Test2_Plus | A7 | 检验社区模型成色 |
| **B4** | WhisperX | — | A7 | =A3，已知 P95=1.27s，保底 baseline |

决策规则：100 条 Gold Set 上 P95 最小者胜。B1/B3 打平选 MFA（生态更稳）。若全部不过 0.5s，退用 B4 的 1.27s——5 倍改善且误差局部有界。

**关键纠正**：MFA 3.0 在 CSJ 上的 15ms 边界错误不能迁移到歌声场景——A2 实验用 japanese_mfa 在target singer歌声上实测 P95=9.37s，比 Whisper A7 的 6.62s 还差。语音域的精度不等于歌声域。SOFA 也并非必然首选——格罗宁根硕士论文对比显示 MFA 在歌声上更稳定，但前提是在歌唱数据上训练/适配过。**工具选择通过 bake-off 实测决策。**

[此处参照 材料6 §三、§八]

### 3.3 粒度-精度决策表

bake-off 实测 P95 与允许的放置粒度：

| P95 范围 | 放置粒度 | 说明 |
|:--------:|:--------:|------|
| < 0.15s | 摩拉级 | 后门选项，非主路线 |
| 0.15-0.5s | 词级 | 后门选项 |
| > 0.5s（含 B4 保底 1.27s）| 句级 | 主路线，只收边界收益 |

> **词级/摩拉级后门警告**：过度精确的放置有压缩句内表达自由、逼近「抄源歌手 timing」极端的风险（论文 -w/o Dist 消融与 SFT Phase 1 最低 PER 均支持「适度松弛有利」）。即便 bake-off 精度达标，词级/摩拉级启用前必须做 A/B 对比**target singer表达性**（人耳），不能只看 PER。P0 修的是句起点准确性、不动粒度，不受此风险影响。

### 3.4 target singer自训 MFA 声学模型

MFA 支持 `mfa train` 用自己语料训练声学模型。target singer 99h 单歌手干声 + 假名歌词是理想条件——歌手音色一致，MFA 的 EM 算法不需要已有时间戳。OpenVPI DiffSinger 管线也是这么做。

发音词典用 pyopenjtalk 统一生成，确保 P0 产出的 TextGrid 音素和 vocab 对得上，否则无法直接喂 P2 训练。

训出来的模型和音素级 TextGrid 同时是 DiffSinger 备选路线数据。

[此处参照 材料6 §三、DATA_PIPELINE.md target singer集全流程]

### 3.5 验收标准

- 100 首 Gold Set 重新分层
- L1 占比大幅上升
- P95 < 0.5s 即通过；B4 的 1.27s 可接受
- 句级 Gold Set 金标继续有效无需重标
- ref_len 吸附用新边界

### 3.6 推理侧对齐器

推理时翻唱源是任意歌手，B1 target singer专用声学模型不能直接使用。推理侧采用人工对齐句边界（±0.1s 精度），或通用 WhisperX/MFA。

训练时对 text 放置加入**时间抖动增强**，使模型对推理侧放置误差鲁棒。改词翻唱场景的时间戳从源歌词映射，同样靠抖动增强兜底。

**抖动公式**（修正自 Fable 5 第二轮审查）：目标是覆盖推理侧放置误差（人工对齐 ±0.1s）+ 防止过拟合训练侧特定误差模式，**而非让抖动单独对齐训练侧 P95**。否则 B4 兜底场景（P95=1.27s）叠加 ±1.27s 抖动会把固有噪声翻倍。正确逻辑：**固有噪声 + 人工抖动的总量对齐推理需求**。

| bake-off 结果 | 抖动幅度 | 原因 |
|:---|:---:|------|
| B1 赢（P95 < 0.3s） | ±0.2~0.3s | 覆盖推理侧误差 + 少量余量 |
| B4 兜底（P95=1.27s） | 不加或 ±0.1s | 固有噪声已超额提供鲁棒性 |

> 通用公式：**抖动幅度 ≈ max(0, 0.3s − 训练侧 P95 贡献)**，按「固有噪声 + 抖动总量对齐推理需求」的原则内插。若 bake-off 赢家落在 0.5-1.0s 之间，按此公式内插取值。

推理侧与训练侧的对齐精度不对称（人工 ±0.1s vs 自动 P95）是固有 gap，但时间抖动增强将训练侧误差从隐性偏差变为显式建模噪声，两侧不对称自然消解。

[此处参照 材料6 §三 "推理侧对齐器"]

## 四、P0.5：V4d 证伪实验（1-2 天，流程保险）

### 4.1 目的

P0 bake-off 完成后，立即用 V4c **完全相同配方**（同超参、同起点、fp32、什么都不改）在重对齐数据上跑 10-20k 步。目的：在投入 P1/P2 大量算力之前，先检验"对齐是根因"这个假设。

这一步只花 1-2 天，是整个计划性价比最高的检查点。

[此处参照 材料6 §四]

### 4.2 实验设计

| 实验项 | 设置 | 与 V4c 差异 |
|--------|------|-------------|
| 配方 | 完全复用 V4c | 相同模型架构、超参数 |
| 数据 | P0 bake-off 选出的重对齐数据 | **唯一变量** |
| 精度 | fp32 | 与 V4c 一致 |
| 训练步数 | 10k-20k | 提前停止观察 |
| 起点 | V4c step 24000 checkpoint | 同起点 |
| **LR schedule** | **fresh warmup 500 → hold 1.4e-5** | V4c 原 warmup-hold(12k)-decay 为 30k 全程设计，续训必须重新声明 |
| **时间抖动** | **不加** | 抖动在 P2 才引入。「完全复用 V4c」隐含此意，显式写死防止污染单变量 |

### 4.3 三个可证伪预测与分级判据

[此处参照 材料6 §十核查清单#6]

**主判据**：FlowB 跌破 0.88（超出此前所有超参改动 ±0.02 噪声带 3 倍）即通过。

**辅助判据**（增强信心，不作为一票否决）：
- 21-30 假名桶 PER 从 0.562 显著下降

**判定逻辑**：

|------|------|

## 五、P1：日语 TTS 接地

### 5.1 为什么需要

官方 YingMusic 的训练课程：1M 步 TTS 预训练 → SFT。V4 的 28 个日语 embedding（ID 319-346，27/28 从未训练）只见了 99h 带噪对齐的歌声，等于跳过了整个发音先验阶段。

P1 的目标：先把这 28 个 embedding + ConvNeXt 文本编码器在干净朗读数据上喂饱，再回到歌声。

[此处参照 材料6 §五、VOCAB_TOKEN_MAP.md §3.3]

### 5.2 数据

| 数据集 | 规模 | 原始采样率 | 处理 | 用途 |
|--------|:---:|:---------:|------|------|
| Emilia-JA | 2800h | 24kHz | 上采样→44.1kHz 立体声 | 发音基础主力 |
| JSUT | 10h | 48kHz（原生） | 降采样→44.1kHz 立体声 | 全频带锚点 + 质量金标 |
| JVS（语音部分） | 30h | 24kHz | 上采样→44.1kHz 立体声 | 多风格补充 |

**注意事项**：
- Emilia 24kHz→44.1kHz 上采样后 12kHz 以上仍为空（"低通指纹"）。不影响 P1 目标（embedding 接地看音素-latent 对应不靠高频），但需 JSUT（48k 原生）和target singer混入一定比例作全频带锚点
- 单声道数据复制为双声道喂 VAE
- P2 回到全频带歌声会自然矫正，不建议为此上带宽扩展模型
- **自蒸馏 replay（条件触发备用武器）**：默认不启用。触发条件（双信号同时出现）：固定听感集「厚重/浴室感」加重 **且** 逐层 cos 显示声学侧深层显著漂移。触发后执行——官方底模生成 CN/EN 歌声（32 ODE 步 / CFG 3，**用target singer片段做零样本音色参考**，使锚数据 = target singer × 官方唱功）→ GRPO 时期 reward 管线过滤（Whisper/WavLM/DNSMOS，阈值沿用）→ 10-30h 成品，以 5-15% 比例混入。前置动作：管线脚本现在写好（约半天），数据触发时再生成。详见 §十一.4

[此处参照 材料6 §五、材料4 §九.1 Emilia 日语；chat.log D4]

> **执行提醒 R1——Emilia 申请现在就提：** HuggingFace gated 数据集，审批周期不可控，而它在 P1 的关键路径上。不要等 P0.5 通过才申请——申请是零成本并行项，被拒了还有时间找镜像或调整数据方案。
>
> **执行提醒 R2——2800h 重采样存储策略：** 2800h → 44.1kHz 立体声 wav 约 1.8TB。建议 dataloader 内 on-the-fly 重采样 + 声道复制，而不是预处理落盘——省 TB 级磁盘，且改采样策略时不用重跑预处理。VAE latent 若预提取缓存则另算：21.5Hz × 64 维，2800h 约 50GB 级——latent 缓存才是该落盘的东西。

### 5.3 训练要点

- **训练格式：直接沿用 A/B 分割**（非官方 TTS 预训练的随机掩码 70-100%）。理由：① 与 P2 格式同构，消除阶段间切换成本；② A/B 的正确性已被 V4 自重建验证；③ 语音数据天然适配——同说话人前段做 ref 就是标准 zero-shot TTS 设定。A 区 = 同一条语音的前段做参考（cond=真 latent、midi=null token），B 区 cond=零 + text 生成。midi 全程 = null token。
  - **P1 的 text 放置方式**：Emilia 是短 utterance + ASR 时间戳，同样句级放置（Emilia 自带标点分句），保持与 P2 完全同构。
- **分阶段解冻**（经 SVC N 形曲线数据修订两次后的最终版）：
  - **阶段一（开胃菜，数千步）**：冻结 DiT 主干，仅训 28 行日语 embedding + ConvNeXt 文本编码器。零破坏地吃掉最便宜的收益——16 个共享音素已通，流形内空间不小
  - **阶段二（主菜）**：全 DiT 解冻训练。**明确声明：DiT 是单体结构，attention 逐层混合 text/latent/midi，不存在可外科手术冻结的「声学通路」，全量解冻是必须的**（岛岛纠正 Fable「只飘 text 通路」强版本后的共识）
  - 「embedding + ConvNeXt」是验收关注点，不指冻结范围
- **转变谷预警**：从官方权重全量解冻训练必然经历「旧先验部分拆解、新拟合未自洽」的中间低谷（SVC 实测 3k→10k，eval loss 正常但听感下降）。**P1 中途 CER/听感变差不构成中止理由**——验收在充分步数后测，低谷期只记录不干预
- **逐层 cos 监控**（纯仪表，不设预算、不干预训练）：
  - **立即执行（零成本，不等 P1）**：用现有 cos 工具跑 V4c 24000 vs 官方底模，建立漂移基线——若已显著偏离（<0.99），浴室感的漂移假说直接坐实
  - P1/P2 每 5k 步记录**逐层** cos + 5 首固定听感抽检
  - 用途仅一个：听感退化出现时，定位退化层深与阶段，为是否触发 §十一.4 自蒸馏 replay 提供证据
  - 不设漂移预算、不干预训练（日语通路必须大幅移动，硬预算会卡死训练——岛岛纠正）
  - **保留理由**：SVC 实测中 cos 与听感的相关性远好于 eval loss 与听感——它是唯一能提前看见听感型退化的仪表
- **midi 条件**：采用 UniVoice 式**可学习 null token**。关键纪律：TTS 模式、SVS 的 A 区 midi、CFG drop_midi、P2 朗读样本的 B 区 midi **四处必须统一使用同一个 null token**——否则模型会学出多种"零"的不同含义，A 区 midi / TTS 朗读的信号变成隐藏变量
- **防遗忘**：混入少量 CN/EN 或歌唱数据（参考 F5-TTS 社区 Issue #636：215h 西语+35h 英语微调后英语单词重复；#57：280k 步后失去英/中能力）
- **训练模式**：从 YingMusic CN/EN DiT 权重出发的**增量训练**，不是从零开始

[此处参照 材料6 §五、材料4 §八 UniVoice 因子化条件分解；chat.log D2、D3、B1]

## 六、P2：重对齐数据上重跑 SFT

### 6.1 V4 A/B 设计保持不变

V1/V3 的失败已反向验证了训练/推理 B 区一致性原则的正确性。A/B 区拆分方案完全沿用：

- A 区 cond=真 latent、midi=**null token**（P1 引入，三处统一。**唯例外是 P0.5**——V4d 用 V4c 原配方，A 区 midi 仍是零，因为 P0.5 在 P1 之前）
- B 区 cond=零、**midi = 唱歌样本用真旋律 / 朗读样本用 null token**。朗读样本的 B 区 midi = null token（=UniVoice TTS 模式）；唱歌样本的 B 区 midi = 真旋律
- ref_len = T × random(0.125, 0.33)，≥5s（108 帧），≤65% T
- **CKA loss：唱歌样本仅在 B 区计算；朗读样本关闭 CKA loss**（无旋律 GT，CKA 无定义）。实现上按样本的 has_melody 标志开关，batch 内混合时 loss 归一化避免无 CKA 样本稀释权重
- CFG dropout：drop_audio=30%、drop_text=15%、drop_midi=30%，三者独立

**唯一变化**：数据源从 V4 的旧对齐切换为 P0 bake-off 选出的最优对齐配置。

[此处参照 plus-finetune-fullplan-v0527.md §3.2 A/B 分割方案、材料6 §六]

### 6.2 核心配置

|------|------|------|
| 混合训练 | 70% 朗读（Emilia+JSUT+JVS 语音）+ 30% 唱歌（JVS 歌唱+target singer） | WeightedRandomSampler |
| text 放置 | 句级放置 + 时间抖动增强 | 抖动公式见 §3.6（覆盖推理侧误差，不对齐训练侧 P95） |

### 6.3 注意事项

[此处参照 材料6 §六注意事项]

- 确认训练和推理的 text 放置方式**严格同构**
- **"第三句起胡言乱语"**：重对齐后若仍残留，是独立问题（距 A 区锚点太远 → 注意力涣散），DiTSinger 字符级 attention 窗口掩码是针对性解法
- **L2/L3 重对齐后重新分层**：L3 "均匀分布兜底"类样本大概率直接丢弃
- **MFA 自训发音词典**：kana→音素映射必须用 pyopenjtalk 统一生成，确保 P0 产出的 TextGrid 音素和 vocab 对得上，否则无法直接喂 P2 训练
- **长音处理**：唱歌超长元音是 MFA 时长模型软肋。词典里为元音加长音变体（如 a→aa），或分块窗口内放宽时长先验。bake-off 时留意 21-30 桶这类慢歌样本的表现

### 6.4 评估方案

| 评估项 | 频率 | 指标 | 对比对象 |
|--------|:----:|------|----------|
| 分桶 PER | 每 20k 步 | PER（按 V4 假名数桶 1-10/11-20/21-30/30+） | 全表 vs V4c |
| FlowB 曲线 | 每 20k 步 | FlowB | 趋势监控 |
| **逐层 cos** | **每 5k 步** | DiT 逐层 cosine similarity vs 官方底模 | 监控漂移，不设预算 |
| **人耳抽听** | **每 20k 步** | 咬字清晰度、字位漂移、唱功自然度（5 首固定） | V5 vs V4c vs 真实歌声 |

> 人耳评估频率从"仅 SFT 结束后一次"提到每 20k 步。项目史反复验证：人耳多次发现指标看不见的问题（GRPO +4.4% 人耳无区别、V5a1 指标好人耳拉不开）。成本仅几分钟/次，避免几十万步后才暴露方向性问题。

> **「没过拟合」不作为「数据够」的证据**：453M 扩散模型 + 小数据的典型失败是**均值化**而非过拟合——loss 全程健康、train/eval 不分叉、生成物平庸。SVC 已实证 eval loss 对此完全失明。数据充分性的唯一检验是生成质量（人耳 + cos）。
>
> **附带预警**：P0 修复对齐后，6.62s 标签噪声的隐性正则消失，过拟合可能首次真实出现——届时按正常手段处理（早停/增广），不必惊慌。

## 七、P3：唱功/身份评估（对齐修好后）

### 7.1 微观韵律被平均掉

颤音、滑音、时值微调不在 SOME 音符级 midi 里，模型必须自己生成——这是多模态均值最先抹平的东西。单歌手 99h 过拟合理论上应把它烤进权重——前提是标签噪声不再逼模型保守输出。

**但 SVC N 形曲线提供了独立证据**：3k 步（CFM cos=0.999999，参数几乎没动）听感全局最佳；60k 步「厚重、清新感不可逆丧失」。唱功退化的头号嫌疑是**底模漂移 + 小数据均值化**，而非对齐噪声。对齐修好后唱功可能自然恢复，也可能不恢复——若不恢复，归属 §十一处理。

### 7.2 "浴室感"

一部分可能是 SAO VAE 解码器问题（训练数据 AudioSparx 几乎不含日语，论文自认"speech generations are not intelligible"）。**冻结 encoder 微调 decoder 是低风险并行项，可与 P0 同时做**——latent space 完全不变，DiT 不需重训。

STAR-VAE（ICML 2026，同帧率 21.5Hz 同维度 64）开源后替换；Semantic-DACVAE-Japanese 作为备选（但 latent 维度不同需改 DiT 输入层）。

[此处参照 材料6 §七、材料4 §五 VAE 分析]

### 7.3 技术储备（P2 完成后选择性启用）

| 技术 | 用途 | 触发条件 |
|------|------|----------|
| 子中心嵌入（20 个子中心） | 保留类内方差 → 更自然表达 | 唱功仍平庸 |
| SVC 教师蒸馏（SVS→SVC→以 SVC 输出为 target） | 身份 enforcer | 身份相似度不足 |
| DiTSinger 字符级 attention 窗口掩码 | 解决"第三句胡言乱语"（若重对齐后仍残留） | 注意力涣散 |

[此处参照 材料5 §1.1 方案 A/B/C、材料6 §六注意事项]

## 十一、底模漂移风险管理（SVC N 形曲线经验）

> 本章全部来自 YingMusic-SVC 微调实测（5603 条/36.4h 单说话人，见 chat.log 开头）与 Fable 5 第三轮讨论。V5 主线结构不受影响，本章为风险管理的附加层。

### 11.1 SVC N 形曲线的经验证据

| 步数 | CFM cos（vs 预训练） | 听感 |
|:---:|:---:|------|
| 3k | 0.999999 | **全局最佳**（清新） |
| 5k | 0.998 | 开始下降 |
| 10k | 0.996 | 低谷 |
| 60k | ~0.92 | 厚重，清新感不可逆丧失 |

关键观察：
- eval loss 全程正常下降，无反弹——**对均值化退化完全失明**
- LR（Length Regulator）cos 在 3k 就跳到 ~0.96，之后几乎不变——LR 早期完成适配，后续变化来自 CFM
- 底模默认输出听感差（≈20k 水平或更差），好听感 = **官方先验 × 轻量条件适配**，不是「从零重建」

### 11.2 核心推论：保权重严格优于重训

官方 453.6M 权重 = 33,562h 内部歌唱数据 + 8×A800 × 141 万步的蒸馏物。那批数据你永远拿不到，但其蒸馏物开源了。重训底模 = 删掉这份蒸馏物，用开源歌声（总量 1-2k 小时，质量参差）重新压缩——你的 SVC 60k checkpoint 已经预览过这会长什么样（厚重、清新感不可逆丧失）。

好听感的唯一可行路径：**保住底模先验 + target singer坐标 + 日语 text 通路，不让声学层被均值化冲掉**。
