# 训练时长消融计划

## 研究问题

在模型结构、初始化、训练配方、更新步数和评测完全一致时，只减少可访问的训练音频，最终质量
如何随 30h、现有 strict-control 65.630h 和当前全量 token-safe 87.417h 变化。

本实验回答的是数据规模问题，不把模型路线选型、长音频训练、VAE 更换或额外 continuation
混入同一轮比较。

## 已知数据口径

| 数据口径 | 样本数 | 音频秒数 | 小时 | 用途 |
|---|---:|---:|---:|---|
| SOFA 对齐成功 train 全量 | private corpus count | 326,119.63 | 90.589 | 原始上限，不直接称为可训练池 |
| 当前全量 token/frame 门禁通过 | 14,661 | 314,700.92 | 87.417 | 增量候选来源，不是最终母池 |
| V4PH/H strict-control train | private corpus count | 236,268.77 | 65.630 | 冻结为 `TIME65H` 中间数据点 |
| V4PH 固定 eval | 201 | 约 4,356 | 约 1.210 | 固定评测，不计入训练预算 |

现有 14,661 条全量 token-safe manifest 与 `TIME65H` 不是严格嵌套：`TIME65H` 有 82 条、
2,321.811 秒不在其中。这 82 条在旧 strict-control 与全量 SOFA 中存在 phrase/overflow 口径
差异，不能静默互换。两者按 Path 合并后为 14,743 条、约 88.062h。

因此 `TIME87H` 是待重建的名义目标，不直接等于现有 14,661 条文件。正式 manifest 必须先原样
包含全部 `TIME65H` 记录，再从全量候选补充不超过 87h，并记录精确样本数、音频秒数、小时数和
SHA256: redacted
后，才允许另建 `TIME90H`。

## 基座选择门禁

当前不冻结 `{BASE}`。至少等待以下结论：

1. V4IPH 已有的无 A 负结果保留为证据，不因 loss 接近 PH 自动晋级；
2. V4IjPH v2 完成正式训练、同构推理、头戴听评和工程审计；
3. 若 L 与 P/H 组合形成 LPH 候选，先完成 L 的单变量听感与长程稳定性裁决；
4. 最终只选择一个完整、可从允许起点复现且已通过感知门禁的基座。

不能同时用 PH、IjPH、LPH 各跑一组后把差异解释为数据时长效应。若需要比较多个基座，应为
每个基座分别建立完整的 30/65/87 三点曲线。

### 首轮基座裁决

2026-08-02 用户在 GPU set 空闲后授权执行。当前证据中 V4IPH 已感知否决，V4IjPH v2 虽完成
30k 和工程审计但尚未感知裁决，V4PH 是唯一已通过感知门禁的当前可用候选。因此首轮冻结：

```text
BASE = V4PH
```

现有 V4PH 30k 作为 `V4PH-TIME65H` 中间点。新执行 `V4PH-TIME30H` 和
`V4PH-TIME87H`；两组各自从 Official base 后独立完成 P-only 500 与 Phase B 30k。若 IjPH、
LPH 或其他基座后续晋级，不替换本轮任一数据点，而是另建该基座自己的完整三点曲线。

## 三组数据合同

```text
TIME30H subset TIME65H subset TIME87H
```

- 母池只能包含最终基座所需的全部有效资产：waveform、SOFA phrases/tokens、H placement、GAME
  cache，以及基座特有但冻结的离线条件；
- `TIME65H` 直接冻结为现有 private corpus count 条 strict-control manifest，不从 87h 母池重新随机抽样；
- `TIME30H` 使用冻结 seed 和确定性算法从 `TIME65H` 内构造；
- `TIME87H` 必须逐条保留 `TIME65H` 的记录内容，再从全量 token-safe 候选选择新增 Path 直到
  冻结时长上限；不得用全量版本覆盖同 Path 的 strict-control phrase/tokens；
- 当前两个现成 manifest 不嵌套，不能直接进入训练。正式构建报告必须证明三组 Path 集合和
  共享记录内容均满足合同；
- 以 manifest 中实际加载且未被 loader 裁剪的 waveform 秒数计时；不得按文件大小、SOFA span、
  B 区期望长度或训练中累计重复曝光计时；
- 30h 不得超过名义上限。允许因整条样本不可拆而略低，误差上限在构建前冻结；`TIME65H`
  是 65.630h 的名义标签，报告和 checkpoint metadata 始终保留精确秒数；
- 不按原清单前 N 条截断。子集构建需固定 seed，并审计 BV 来源、样本时长、歌词/token 数、
  P class、REST、H phone/PUL 覆盖和空 Phrases；
- train/test 按现有 split 隔离，任何 eval 样本不得进入三个训练集合；
- manifest 顺序、选择脚本、汇总报告和 SHA256: redacted

子集算法在 `{BASE}` 和母池资产完整后才冻结。若平衡约束与严格嵌套冲突，优先保证无泄漏、
确定性和嵌套，再完整报告分布偏差，不人工试听后换样本。

## 完整训练谱系隔离

“训练数据只能有 30h/65h/87h”覆盖从 Official base 之后的所有可学习阶段，而不只覆盖最后的
联合训练。

- 若 `{BASE}=V4PH`，每组分别用自己的子集完成 500-step P-only、初始化裁决和 Phase B 30k；
- 若 `{BASE}=V4IPH`，每组使用自己的 P-only 产物，再从零完成对应 IPH 30k；
- 若 `{BASE}=V4IjPH v2`，每组必须先独立得到仅看过本组数据的 IPH step 8000，再执行相同的
  INS transition 和 8k->30k continuation；不得复用现有全数据 V4IPH step 8000；
- 若 `{BASE}` 包含其他预训练或 continuation 阶段，同样逐阶段追溯，直到三个分支汇合于共同
  允许的 Official base 和固定外部 teacher；
- 现有 65.630h checkpoint 只有在其 `{BASE}`、父 checkpoint、阶段划分、数据 manifest 和全部
  控制变量与最终 TIME 设计一致时，才可直接登记为 `TIME65H`；否则必须在同一 65h manifest
  上重跑；
- GAME、SOFA、INS 等冻结 teacher 可以离线处理完整母池，但训练 loader、loss 和 optimizer
  只能访问本组 manifest 对应条目；
- checkpoint 必须保存数据 manifest SHA、完整谱系父 checkpoint SHA、代码/config SHA、全局
  step、sampler cursor、optimizer/scheduler/EMA 和实际累计音频秒数。

任何从较大集合 checkpoint 派生较小集合模型的做法都属于数据泄漏，不能命名为 TIME 实验。

## L 路线的时长口径

V4L 的长窗口由既有短段拼接而来，不自动增加新的独立录音内容。若最终 `{BASE}` 包含 L：

- `TIME` 预算首先按去重后的底层 source waveform 秒数计算；
- 同一短段及由它派生的长窗口不能重复计为新增小时；
- 30/65/87 三组必须使用相同的短长采样政策和派生算法；
- 同时报告唯一 source 小时、manifest 表观小时、每 1,000 step 累计加载小时和短长 batch 比例；
- 若无法让三组同时满足数据预算与相同短长政策，L 不进入首轮 TIME 基座，先使用非 L 获选路线。

## 固定控制变量

基座冻结后，三组必须保持一致：

- Official base、模型结构、条件接口、VAE、teacher 与 cache schema；
- loss 组成及权重、CFG/dropout、A/B 或无 A 定义；
- world size、batch、grad accumulation、有效 batch、fp32/AMP 与梯度同步；
- seed、LR、warmup、hold、decay、最大 step、保存和 eval 周期；
- checkpoint/EMA 规则、resume 语义和正式推理代码；
- 固定 eval、固定生成集、CFG、solver、seed 和人工听评协议。

首轮保持相同更新步数，测量“小数据被重复更多轮”的实际效果。报告必须额外给出每组
steps/epoch、30k 内等效 epoch、唯一样本覆盖次数和累计加载音频小时，不能只列 global step。

## 执行门禁

1. 冻结 `{BASE}` 及其完整训练谱系；
2. 以 TIME65H 为不可删除核心，从全量候选兼容性重建并审计 TIME87H 母池；
3. 证明 TIME65H 是新 TIME87H 的严格子集，再确定性生成其子集 TIME30H manifest；
4. 独立审计三组的小时数、交并集、分布、缓存解析、路径和 train/test 隔离；
5. 为每组从共同允许起点执行最小单卡 update；
6. 每组执行四卡连续 10-step、5+resume5 exact-resume 和 checkpoint audit；
7. 门禁全部通过后再串行启动正式训练，独立 output、tmux session

服务器日志至少实时打印模型名、step、epoch、loss 分项、LR、累计训练音频小时、运行时长、
step time 和 ETA。任一组失败不得用另一组 checkpoint 热启动补救。

## 评价与裁决

三组至少比较：

- 固定 paired eval 的 Loss、FlowA、FlowB、CKA，但这些只作为训练健康指标；
- 同一真实跨源评分集的歌词时间、漏句/错槽、旋律与跑调；
- 发声区宽带噪音、电音、极高音稳定性、长程崩坏、音色和唱法；
- 多 seed 盲听偏好与问题分级；
- 数据效率：质量相对唯一训练小时、累计加载小时和训练耗时的变化。

主结论来自同构盲听和任务错误率，不用单个最低 loss 选模型。若 65h 与 87h 感知等价，才可
讨论现有 65.630h 数据是否足够。已有 65h checkpoint 是否进入严格三点拟合，取决于其基座和
完整训练谱系是否与另外两组完全一致。

## 停止条件

- 最终基座尚未通过感知门禁或其完整谱系无法从共同起点复现；
- 三组不是严格嵌套，或小时数统计包含 loader 裁剪、重复派生内容或 eval 泄漏；
- 任一小组复用了看过更大集合的学习权重或训练状态；
- 为适配某个时长组而单独修改 batch、LR、步数、dropout、模型或条件；
- smoke、exact resume、checkpoint provenance 或 cache 解析失败；
- 三组正式推理不是同一输入、同一代码和同一参数；
- 资源不足以完成完整三组，却尝试用不完整 checkpoint 给出数据规模结论。
