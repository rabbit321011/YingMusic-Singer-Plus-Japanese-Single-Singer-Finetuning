# 摩拉音素级对齐实验

## 目标

验证比当前句级起点更细的歌词时间条件能否改善句内咬字位置、长句文本稳定性和 PER，
同时不显著损害旋律、target singer唱法和声学质量。

H 不按日语书写字符直接对齐。`きゃ`、`っ`、`ん`、长音等必须按摩拉和实际发音处理。

## 当前基线

当前 SOFA/V4f 路线虽然输入 IPA token，但只使用每句的 `start`：

```text
phrase start -> token1 token2 token3 ... SEP
其余句内帧 -> PAD
```

训练实现以约 21.53 Hz 的 VAE latent 帧为文本时间轴。句内 token 从句首连续占用相邻帧，
没有使用 SOFA 已预测的 phone interval。SOFA 全量脚本也只保存了 phrase `start/end`，
没有持久化 phone tier。

## H 数据通路

```text
已知歌词或 Whisper 文本
  -> 规范化 kana
  -> 日语摩拉切分
  -> 为每个摩拉构造 SOFA phone 与 phoneme_to_word
  -> SOFA 全段强制对齐
  -> mora interval + phone interval
  -> 同一份 kana 进入现有 japanese_to_ipa
  -> 现有 vocab token ID
  -> 在 latent 时间轴按对应 phone 时间稀疏放置
```

SOFA 的 `word` tier 在 H 中承载摩拉分组，不表示自然语言分词。SOFA 模型仍然执行 phone
强制对齐；`phoneme_to_word` 只把 phone interval 聚合回稳定的摩拉边界。

## 冻结原则

1. SOFA 和训练 tokenizer 读取同一份规范化 kana。
2. 不把 SOFA phone label 直接当模型 token；模型仍使用现有 IPA tokenizer 和 token ID。
3. 每个摩拉内必须逐项证明 SOFA phone 与 IPA token 可对应；无法对应的样本标记或过滤，不猜测。
4. `SP/AP/pau`、歌词标点、句间 `<SEP>` 和 PAD 分开定义。
5. 首轮保持稀疏 text placement，不默认把同一 token 重复填满整个音素时长。
6. 首轮对照只改变 text placement；数据、DiT 起点、VAE、MIDI、CKA、seed、batch、LR 和 schedule 保持一致。
7. 训练与推理使用相同的摩拉切分、G2P、帧量化和冲突处理代码。

## 时间分辨率与验证集

H 的正式边界验证使用target singer真实训练数据，不使用外部歌手数据替代感知门禁。验证集从 token-safe
训练样本中选择 40 条长段，覆盖五档字符密度，每档 8 条且来自 40 个不同 BV：

| 项 | 范围 |
|---|---:|
| 时长 | 24.102–29.710s |
| 摩拉密度 | 0.579–6.429 mora/s |
| 密度档 | 极疏、疏、中、密、极密 |

当前 VAE latent 帧率约 21.533 Hz，单帧约 46.4ms。因此“时间戳更精细”不等于当前单通道
token 序列能无损表达。正式训练前必须结合target singer同步试听比较并冻结：

- start frame 的 floor/round 规则；
- 同帧冲突的单调顺延规则及最大允许偏移；
- 极短辅音与后续元音是否允许在摩拉内相邻放置；
- 超出摩拉或句边界时是过滤还是回退；
- duration-expanded token 仅作后续独立消融，不与首轮混写。

## 推理同构

同歌词推理：

```text
melody audio -> Whisper -> kana -> mora -> SOFA -> H placement
```

此时可直接取得与训练同构的摩拉和 phone 时间。

改词推理：Whisper/SOFA 得到的是旋律源原歌词时间，目标歌词是另一套摩拉序列。
必须冻结一个显式、确定性的目标摩拉投影规则，并与训练增强共同验收。候选包括按句内归一化进度、
音符/voicing 锚点或受限单调匹配进行投影。该规则未冻结前，oracle 时间实验只能作为因果诊断，
不能宣称完成任意改词工作流。

## 评价

- 首要因果指标：同歌词生成前后的 Whisper+SOFA 对齐保持度，判断摩拉是否仍落在原节拍槽；
- 文本：PER、句内错位位置、重复/漏读和长多句稳定性；
- 旋律：F0-CORR、voicing、音符起止、长音和滑音；
- 表达：抢拍、拖音、轻柔、咬字与target singer唱法是否被硬 timing 压缩；
- 声学：浴室感、雾感、电音、雪花声和局部崩坏；
- 对齐：phone/mora MAE、P95、漏音、增音、映射率、碰撞率和量化偏移；
- 推理：同歌词与真实改词必须分别报告，不能用 oracle 结果替代产品结论。

### 首要指标：生成前后对齐保持度

H 的直接动机是修复“歌词内容正确，但摩拉落到相邻节拍槽”的错节现象。例如：

```text
节拍：  1 2 3 4 5
生成前：a   b c
生成后：a b   c
```

FlowB 是 flow-matching 训练目标，只反映 B 区在当前条件下是否更容易拟合。它不能识别 `b` 究竟
落在原槽还是前一槽，因此只保留为训练健康指标，不作为 H 成立与否的代理指标。H 的正式同歌词
评测冻结为以下双通路：

```text
生成前 B 音频 -> Whisper -> 锁定 kana K -> SOFA -> 源 mora/phone 时间 S
生成后 B 音频 -> Whisper -> 识别 kana K_hat       -> 内容一致性门禁
              -> 使用同一 K 运行 SOFA             -> 生成 mora/phone 时间 G
```

生成前和生成后必须使用同一 Whisper、kana 前端、SOFA checkpoint、强制对齐模式及后处理代码，
并保存各自 SHA、置信度、raw/used tier。T1 输出是 B-only 且与 GT B 逐采样点等长，比较统一转换到
B-local 时间轴；不得将 reference tail 或 A 区长度混入误差。

Whisper 与 SOFA 分工如下：

- Whisper 判断“实际唱了什么”：比较 `K_hat` 与锁定 `K`，报告 exact rate、kana/PER、插入、删除、
  替换、重复和漏唱；
- SOFA 判断“同一内容唱在何时”：生成后仍以锁定 `K` 强制对齐，保证源/生成单位身份一一对应；
- 不允许用 `K_hat` 悄悄替换 `K` 后再宣称时间一致。`K_hat` 可另跑一次 SOFA 作诊断，但不能覆盖
  主结果；
- Whisper 不一致、SOFA 低置信或 phone/mora 数量异常的样本必须保留为显式内容/对齐失败，不能
  从分母删除，也不能靠强制对齐硬解释成成功。

错节以 mora 为主单位、phone 为诊断单位。每句选定稳定的 mora anchor；普通摩拉优先比较元音
nucleus onset，`ん/っ` 等无普通元音的单位需冻结独立规则。记源/生成第 `i` 个 anchor 为 `S_i/G_i`，
至少报告：

```text
句首进入误差：       G_0 - S_0
句内相对误差 r_i：   (G_i - G_0) - (S_i - S_0)
相邻间隔误差 d_i：   (G_i - G_(i-1)) - (S_i - S_(i-1))
```

- `r_i` 的 MAE、P95、最大值直接检验 H“句首不动、修正句内 token 时间”的假设；
- `d_i` 能抓住一个摩拉提前、后一个间隔被拉长的局部错节；
- 以相邻源 anchor 中点作为槽边界，统计生成 anchor 离开自身槽的比例、方向和最大连续错位数；
- 同时报告绝对句首误差，避免句内相对化掩盖整句抢拍或拖拍；
- 不使用可自由伸缩的 DTW 修饰主结果，因为它可能把要检测的错节重新配成“正确”。

anchor 规则、SOFA 置信门限和错槽阈值不凭经验直接冻结。先用用户已确认错节的 V4fg 10k 样本作
阳性对照，用确认正常的生成样本以及 GT B/VAE reconstruction 作阴性与测量噪声对照；若指标不能
把已知错节样本排到更差一侧，先修正指标，不评判 H。正式 H 门禁再在同一批输入、seed、CFG、
steps 下比较 H-Control 2k 与 H 2k，并生成源/H-Control/H 三轨时间线网页供人工复核。

## 停止条件

- SOFA phone boundary 在 Gold 歌声上不可靠；
- 统一 kana 后仍存在无法解释的大规模 phone/token 不一致；
- 帧碰撞处理造成系统性越界、换序或大幅时间偏移；
- 训练与推理使用不同的 kana、摩拉切分、tokenizer 或放置规则；
- H 只改善 loss/PER，但旋律、target singer表达或声学质量持续退化；
- 改词场景无法建立可复现的目标摩拉时间投影。

## H-v1 实现冻结

H-v1 的因果问题只允许是“细粒度 text placement 是否优于句级 placement”。现有训练
token 资产、样本集合和句首锚点均不得随 H 改变。以下约束是代码断言和全量数据门禁，
不是实现建议：

1. Control 与 H 读取同一条记录、同一组 token ID、同一 token 数量和顺序；
2. 每句第一个 token 的帧固定为同一次 batch、同一 `ref_len` 下现有句级 Control 的实际
   首帧，H 中帧差必须为 0；常规值是 `int(phrase.start * FRAME_RATE)`，但当随机 A/B
   边界落入句内时，现有 Control 会把 B 侧句首推到 `ref_len`；
3. H 不在训练时重新 tokenize；离线阶段只验证现有 token 能否与统一 kana 生成的 IPA
   token 逐项对应；
4. `<SEP>` 的数量和 ID 沿用当前实际训练实现，包括末句后的 `<SEP>`；
5. Control 与 H 的样本集合、A/B reference 边界、Official base、VAE、MIDI、CKA、seed、
   batch、LR 和 schedule 完全相同；
6. H 唯一允许变化的字段是首 token 之后各 token 的 `frame_index`；
7. 全量产物必须保存 token 序列 SHA256: redacted

### 逐句映射与回退

统一 kana 仍是 SOFA phone 和 IPA 映射的权威读音，但不用于悄悄替换现有 token。每句先做
以下离线检查：

```text
现有 phrase 非标点 tokens
  == normalized kana -> japanese_to_ipa -> 非标点 vocab token IDs
```

只有歌词音素逐项完全一致、SOFA 非静音 phone 仅含允许差异、且帧量化可表达的句子才使用
phone placement。现有标点 token 的 ID、数量和顺序必须原样保留；标点视为结构事件，内部标点
目标取前一 phone end 与后一 phone start 的中点，尾部标点目标取句末，不要求其符号与 kana
规范化产生的统一逗号相同。以下任一情况触发整句 `sentence_fallback`：

- 现有非标点 token 与统一 kana 非标点 token 不一致；
- SOFA phone 经 `japanese.py` 权威映射得到的 IPA/token 与统一 kana IPA/token 不一致；
- `cl` 未获得独立 SOFA interval；
- 出现 `cl` 删除以外的 phone 插入、删除或替换；
- 标点、pause 或异常 G2P 无法确定映射；
- 帧碰撞求解超过冻结门限或无法保持严格 token 顺序；
- 任一 token 越过句界、A/B 边界或 latent 有效范围。

若随机 A/B 边界落入句内，使实际 Control 句首不再等于离线候选句首，H 对该句执行动态
`sentence_fallback`。训练时必须在最终 text tensor 上再次断言：Control/H 的非 PAD token ID
及顺序相同，每句实际首 token 帧相同。不能只比较离线 manifest。

回退不是失败隐藏项。manifest 必须逐句保存 `placement_mode`、`fallback_reason` 和原始诊断，
汇总必须报告 phone-placement 覆盖率。促音近似可在 H-v1 之后单开消融，不写入 H-v1 Gold。

### 帧放置器契约

- 输入是连续秒级 phone interval、锁定的 token 序列、同一 batch 的 `ref_len`、句级 Control
  帧和实际 latent 长度；
- 第一个 token 帧是硬约束，不参与优化；
- manifest 以每句首个可靠 SOFA phone 为零点，保存后续事件的整数相对帧；训练时整体平移到
  本次动态 Control 句首，因此旧句首即使与 SOFA 绝对首 phone 有偏差也不会被改变；
- 后续 token 帧必须严格递增，目标相对位置来自对应 phone onset；
- `<SEP>` 的目标位置来自句末边界，但仍受 token 顺序和有效范围约束；
- 同帧碰撞使用确定性的最小偏移求解器，不允许简单向右贪心形成长距离级联；
- 输出保存目标帧、最终帧、带符号偏移、最大绝对偏移和碰撞数；
- 时间差先量化为整数微秒，再用 `44100/2048` 有理数换算相对帧；不以平台相关浮点结果
  作为 schema 权威时间；
- 求解器先最小化 phone 的最大绝对偏移，再最小化全部事件的 L1 偏移，同代价选择较小帧；
- H-v1 最大 phone 偏移硬门限冻结为 4 帧，超过即整句回退；
- 离线阶段保存不跨 A/B 的候选 placement；训练时若候选帧与本次随机 A/B 边界冲突，则整句
  回退 Control，不在训练热路径重新求解；
- 相同输入重复运行必须产生字节一致的 placement 结果。

40 条数据上的只读预审显示，简单向右顺延会移动约 24% 的 phone token，最大级联达到
13-14 帧，因此已明确禁止。正式偏移门限需由确定性求解器在 40 条回归及小批量探针上冻结，
冻结前不得启动全量任务。

H-Control 的用途是给 H 提供同代、同骨架的因果对照，不是 H 的预训练阶段，也不是计划发布的

### H-PUL/H-v2 候选设计（概念已收敛，待实现门禁）

2026-07-29 的讨论已冻结 H-PUL 的产品语义与最小实验范围。本节属于独立 H-v2 候选，不回写
H-v1 的“歌词 token 完全相同、只改时间”结论。用户随后授权按四卡 10-step smoke -> 独立
Official base 30k -> 检查 step 50 后交由用户监控的顺序执行，正式名称记为 V4H。

#### Token 语义

- `N_i`：现有歌词 token；ID、数量和相对顺序必须原样保留；
- `V=0`：本轮 V4H 设计阶段曾将其操作性解释为“该帧没有显式歌词 token onset”；正常 H 的
  phone 之间、句前空白均使用。后验讨论修正：Official 模型中的 V 原本就是由模型结合上下文
  自行处理的 filler，语义上严格对应本轮所称 PUL，并不存在一个已由 Official 学会的独立
  “known-empty V” 角色；
- `<PUL>=366`：该帧的 token 时间分配不预先指定，由模型结合紧凑歌词序列、MIDI 与声学条件决定；
  它可能对应发音、延音或停顿，不表示“此帧一定正在唱”；
- `<SEP>=365`：下一句即将开始的结构边界，不再解释为当前句实际发声结束；不新增 `<SEG>` ID。

PUL 不是 CTC 输出目标。V4f 已在学习“句首紧凑歌词序列 -> 后续整句音频”，H-PUL 只是把原来
含义含混的剩余 `V` span 显式标成“时间分配未知”。当前 `text_mask_padding=False`，V/PUL 都会
进入位置编码、四层 ConvNeXt，并以逐帧条件送入 22 层全时域 DiT。

#### 唯一正式布局

对第 `i` 句，`A_i` 是当前随机 `ref_len` 下原 Control 计算得到的首 token frame，`A_(i+1)` 是
下一句对应的运行时 Control 首帧。句段边界定义为：

```text
SEP_i = A_(i+1) - 1
```

最后一句没有下一句，`SEP_i` 取该样本 dense text 有效时间轴的最后一帧。A/B 切点不是歌词句段
边界；所有位置均以实际运行时 anchor 计算，不能只用离线 `phrase.start`。

```text
phone 对齐可靠：
A_i: N1 V V N2 V ... Nk V ... <SEP=365> | A_(i+1): N1 ...

phone 对齐失败、但句段容量合法：
A_i: N1 N2 N3 ... Nk <PUL=366> <PUL> ... <SEP=365> | A_(i+1): N1 ...
```

正常 H 与 H-PUL fallback 使用同一 SEP 规则。fallback 中原歌词 token 从 `A_i` 起连续放置，PUL
逐帧填满最后一个紧凑歌词 token 与 `SEP_i` 之间的全部位置；SEP 与下一句首 token 相邻，中间不再
插 V。由于 PUL 表示“自动决定”，它有意覆盖 SOFA 当前发声结束到下一句开始之间的停顿。

若 `SEP_i` 不能同时容纳全部原歌词 token、至少一个 PUL 和 SEP，或运行时 anchor 重合、历史
Control 已发生 token 覆盖/截断，则禁止覆盖、裁掉或换序歌词 token，进入结构安全出口：复用
exact Control。普通 phone fallback 不走 Control；Control 只处理无法表达的极端结构异常。

当前有效 token 最高为 SEP 365，配置 `text_num_embeds=373`、实际 embedding shape 为 `[374,512]`；

  通过后从相同 Official base 独立启动 V4H 30k，复用 H-v1 的 seed、数据顺序、loss、LR、schedule、

独立 token 的典型间距，说明 SEP 原本就是独立表示，并正因新的句界位置继续适配。功能门禁应另做
`SEP -> V` 或移除 SEP 的固定 Eval/生成反事实，embedding drift 本身仍不代表边界利用强度。

后验解释进一步修正：Official checkpoint 没有名为 PUL 的训练 ID，但 Official V 的实际 filler 语义
严格等于本轮定义的 PUL。正式 V4H 是把这个已有 V row bit-exact 复制到新 row 后，人为让正常
phone gap 与 fallback span 分别接收梯度；它测试的是同义表示的额外专门化，而不是学习 Official
缺失的新概念。正常 phone 与 fallback 的差别本可完全由歌词 token 的位置及 SEP 边界表达，无需
不同 filler ID。当前低 FlowB 不能归因于 PUL 身份。`PUL -> V` 是有价值的同-checkpoint 反事实，
但由于当前两行已分别适配，它不能完全替代从 Official base 开始的 V-only 重训；即使替换退化，
也只证明当前 checkpoint 已发生共适应。信息论上，PUL 相对 V 最多额外显式提供一个 fallback 模式
标记，而紧凑歌词与 phone anchor 的布局已经基本包含该信息。用户裁决不为这一小变量新增 V-only
重训或强制消融；该想法仅作实现备忘，不进入当前实验队列。当前 V4H 跑完后直接按 Whisper+SOFA、
错槽率与人工试听评估，资源优先用于已经积压的高价值实验。

这里的高价值后续特指 Exact policy 改动，而不是 V/PUL 身份消融。当前 V4H 的 Exact 会把存在
Control token 截断/跨句覆盖的历史 dense tensor 原样送入训练，监督信息可能与真实歌词矛盾；这才是
用户指定的下一项重要实验。候选规则为：`pul_frame_count > 0` 保持当前布局；`== 0` 仍视为合法，
输出 `N...N SEP | next N1` 并保持 SEP 在下一句首 token 前一帧；若歌词 token 无法严格单调放置、
发生真实覆盖或其他不可修复结构异常，则不再 Exact Control，而是整条样本退出训练。动态 A/B 切点
导致的异常最终采用安全 `ref_len` 还是固定 manifest 整条过滤，留待全量唯一 SampleId/场景审计后
冻结；不采用歌词 token 叠加。当前 30k 是旧 Exact policy 基线，跑完后再决定该高价值实验的启动。

三点全量 33,696 runtime 场景的 Exact 原因已进一步拆分。共 748 个样本场景触发整样本 Exact：
661 个（88.37%）是旧 Control anomaly，其中 475 个仅跨句 frame collision、172 个仅 A/B 或尾部
token truncation、14 个两者同时发生；累计记录 2,531 次 collision event 和 1,356 个 truncated
token。其余 87 个（11.63%）全部是 `insufficient_pul_capacity`，逐场景重建后 `pul_frame_count` 无一
例外均等于 0，没有负容量；它们实际可以合法输出 `N...N SEP | next N1`。因此若“过密”严格指连
token+SEP 都放不下，当前三点审计没有这种 Structural；若泛指旧紧凑 Control 的局部拥挤，则 661
个 anomaly 的确由碰撞/截断构成。Exact phrase 比例 4.79% 高于样本场景 2.22%，是因为任一句触发
后整条多句样本全部回退。

按唯一 SampleId 汇总，11,232 条中有 251 条在三个 `ref_len` 至少一次 Exact，占 2.23%，总时长
1.642/66.837 小时（2.46%）；其中 247 条三个点全部 Exact，仅 4 条在部分点可恢复。以整段 IPA
token/s 作为快唱密度代理，全量中位数/P90 为 4.78/7.63，Exact 样本为 7.47/11.93，确实显著
集中在快速、高密度尾部；无 Exact 样本的最高值仍有 15.95 token/s，而 Exact 集最高为 29.02。
因此整条 drop 是最简单、最干净的监督修复，但会有选择性地削弱最极端快唱数据。更准确地说，
当前单帧单 token 表示本来无法从这些冲突条件中学习“歌词可控的快唱”；整条 drop 还会额外丢掉
它们对快唱声学与旋律的贡献。若启动 ExactClean，必须把 former-Exact/高 token-rate 子集单列评测，
不能只看总体平均后宣称无能力损失。

用户随后提出更低信息损失的 Exact fallback：放弃无解的逐句 anchor 和全部句内 SEP，保留全部
歌词 token 顺序，退回类似 V4c/T0 的 A/B 两大区布局。A 区歌词从区首紧凑排列，剩余帧逐帧填
PUL，并在 A/B 边界前一帧放唯一一枚 SEP；B 区歌词从 B 区首紧凑排列，剩余帧全部填 PUL，不再
放句内或末句 SEP。只有连 A/B 总容量也不足时才整条 drop。按 V4c
`split_idx = int(len(lyric_tokens) * ref_len / total_frames)` 的 A/B token 数量划分做容量审计，748 个
当前 Exact 场景中 745 个可完整容纳，251 条异常样本中 250 条的全部异常场景均可容纳；仅 1 条、
3 个场景同时超出 A/B 容量，必须另行处理或 drop。因此该方案能保住约 99.6% 的异常快唱样本，
同时把“静默覆盖/截断歌词”改为“保留内容、只降低时间粒度”，信息论上优于整条过滤。下一步仍需
冻结歌词 token 归入 A/B 的确切规则；区内布局已按用户意见确定为紧凑歌词加稠密 PUL，不采用
V4c `uniform_align_text` 的均匀伪时间。本次只完成容量审计，尚未把候选写成 renderer 或启动训练。
按“仅 A/B 边界一枚 SEP”重新复算后，745/748 与 250/251 的容量结论不变。
