# 歌唱表现力控制研究

## 研究目标

当前系统的 `MIDI + TEXT` 主要规定音高骨架、歌词内容和时间位置，A 区提供参考音频条件。本研究探索
新增一条与 B 区时间轴对齐的 `performance` 条件，使系统同时具备：

1. **表现控制力**：获得 MIDI/TEXT 未描述的真实演唱起伏，包括音高进入和离开、力度、时值偏移、
   拖尾、颤音、气声、虚实声和发声张力。
2. **人类可控性**：人可以从参考演唱迁移上述表现，也可以按局部区域编辑具体唱法；该条件可独立关闭、
   弱化、正常使用或强化。

本目录只承载研究和实验设计，不自动授权修改 V5-P/V5-Pg 正式合同、实现训练代码或启动训练。

## 证据等级

- `P1`：论文原文、作者项目页、作者代码、官方产品文档、当前项目源码。
- `P2`：相邻任务的高质量工作，可支持候选设计，不能直接证明本项目有效。
- `D`：基于 P1/P2 和当前项目约束的推导，必须由消融实验验证。
- `H`：尚未验证的工作假设。

## 当前项目事实

### 条件入口

`YingMusic-Singer-Plus` 当前每帧输入为：

```text
[noised_x(64) | audio_cond(64) | text_embed(512) | midi_embed(128)]
                         -> Linear(768, 1024)
```

V5-P 训练中的 `audio_cond` 仅在 A 区放入目标音频前缀 latent，B 区为零。B 区目前没有与目标时间轴
对齐的声学表现条件。

### 训练条件丢弃

除 `p_only` 外，V5-P/V5-Pg 当前在每次 `compute_loss` 中为三个轴各调用一次 `random.random()`：

```text
audio drop = 0.30
text drop  = 0.15
midi drop  = 0.30
```

三个轴彼此独立，但每个布尔值作用于当前 rank 的整个 microbatch，不是逐样本 dropout。DDP 训练在模型
构建后使用 `seed + rank` 重置随机数，因此同一 global step 的不同 rank 可以看到不同 mask。

当前 `run_eval` 会重置固定 `eval_seed`，但仍调用同一个随机 dropout 逻辑。因此现有验证 loss 是可复现
的“混合条件 loss”，不是固定 full-condition loss。第四条件实验必须把 full、no-performance、drop-all
等命名 mask 分开评估，不能只比较这一项混合均值。

推理 `DiT.forward(cfg_infer=True)` 代码可以打包四种既定分支：

```text
full                  = A + TEXT + MIDI
drop_audio            = TEXT + MIDI
drop_text_and_midi    = A
drop_all              = none
```

但标准 `Singer.sample()` 传入 `cfg_infer_ids=(True, False, False, True)`，实际只计算 full 与 drop-all，
并执行 `full + g * (full - drop_all)`。所以当前是三个训练条件轴、四个硬编码候选顶点、默认两个推理
顶点；不是 A/TEXT/MIDI 三个独立 guidance scale。

### 目标约束

- A 区继续承担当前参考条件作用，新条件只覆盖 B 区。
- 新条件必须作为独立第四条件，不能复用现有 `drop_audio_cond`，否则 A 与 B 表现条件会被同时清零。
- `performance = null` 时应能退回当前 `A + TEXT + MIDI` 行为。
- 推理条件可以来自同时间轴的非花丸演唱，也可以来自其 SVC 结果。

## 外部方案核验

### 局部风格 token 与显式 F0

`P1` [Expressive Singing Synthesis Using Local Style Token and Dual-path Pitch Encoder](https://arxiv.org/abs/2204.03249)
提出逐帧 Local Style Token，并允许用户修改 style score 控制呼吸、强度、渐强和渐弱。其 MIDI/F0
双路径训练以 50% 概率选择 MIDI 或真实 F0；推理可修改 F0 控制 flatten、vibrato、portamento、
attack 和 release。

结论：局部表现必须是时间变化的；自动生成后允许用户修改，是已验证的交互范式。

### 音素级压缩风格表示

`P1` [TCSinger](https://aclanthology.org/2024.emnlp-main.117/) 的风格编码器执行：

```text
GT mel -> WaveNet blocks -> 按音素边界池化 -> 低维线性投影 -> CVQ
```

所得是音素级紧凑 style code。训练从目标音频提取，推理可从音频 prompt 提取，也可由全局和音素级
文本 prompt 生成。其风格包含演唱方式、情绪、节奏、技巧和发音。

`O` [TCSinger 官方实现](https://github.com/AaronZ345/TCSinger) 进一步确认：

- `style_encoder.py` 先把 80 维 mel 映射到 320 维隐藏层，经五个卷积块后按 `mel2ph` 音素边界池化，
  再经五个卷积块投影到 64 维 CVQ 输入；
- `egs/tcsinger.yaml` 配置为单个 CVQ、码本 `K=512`、lookup/channel 维度 `64`、commitment
  系数 `beta=0.25`；
- CVQ 包含低使用率码点的动态重初始化，并记录 code usage/perplexity；
- 人工控制接口按音素接受真假声、气声、咽音、颤音、滑音等技巧序列，同时保留全局唱法、情绪、
  速度和音域控制。

继续核验 [style_LM.py](https://github.com/AaronZ345/TCSinger/blob/main/modules/TCSinger/style_LM.py) 和
[sdlm.py](https://github.com/AaronZ345/TCSinger/blob/main/modules/TCSinger/sdlm.py) 后，可明确其消费路径：

- 训练时从目标 mel 抽取每音素 CVQ code，并冻结声学主模型，只训练 Style Language Model 用交叉熵
  预测 code，同时预测音素时值；
- 参考迁移时，参考片段的 code 和 duration 只作为自回归前缀，后续目标音素的 code 由
  `phoneme + MIDI note + speaker + previous code/duration` 继续生成；
- 人工控制时，六种音素技巧与全局风格先经 `TechEncoder`，再直接预测整段 code 和 duration；
- 预测 code 经码本查回 64 维 style latent，按 `mel2ph` 扩展到帧级，作为加法条件进入 pitch predictor
  和 mel decoder；F0 本身仍由独立的受 MIDI 约束扩散模块生成。

论文消融给出的相对 CMOS 为：

| 设置 | CMOS-Q | CMOS-S | 可支持的结论 |
|---|---:|---:|---|
| TCSinger | 0.00 | 0.00 | 基准 |
| VQ 替换 CVQ | -0.25 | -0.23 | 动态码本机制改善质量和 singer similarity |
| 去掉 style-adaptive decoder | -0.22 | -0.18 | 量化 code 后仍需要有能力的声学消费端 |
| style 与 duration 分开预测 | -0.12 | -0.22 | 联合预测时值与 style 有收益 |

这里没有单独报告 technique controllability 或 duration 误差，因此只能证明整体质量/音色相似度收益，
不能把 `w/o DM` 结果解释为“联合时值一定提高每一种局部技巧控制”。

附录还用 singer A 的 timbre 与 singer B 的 style 合成目标：对 A 的 MOS-T/Cos 为 `4.16/0.91`，对 B
为 `2.23/0.67`。这支持 style code 与 singer timbre 有一定解耦，但没有测试从 code 重建歌词、音素或
MIDI，因此不能视为内容泄漏已经排除。其 technique detector 对 vibrato 和 glissando 的 F1 均为
`0.70`，也说明弱监督技巧标签不是无噪声真值。

`O` 论文和当前公开代码还存在一个必须记录的差异。论文附录的 CVQ 公式包含 L2 normalization 与
contrastive loss；但当前 `style_encoder.py` 实例化 `VectorQuantiser` 时只传入 `K/dim/beta`，因此使用
默认 `distance='l2'`、`contras_loss=False`。`cvq.py` 虽然实现了 cosine distance 和 contrastive
分支，默认路径并未启用。除非 checkpoint 或未公开训练配置另有设置，不能假设直接运行仓库默认代码
会复现论文所述 CVQ 目标。

这说明 TCSinger 并不是在目标区间直接喂入目标声学 latent。它把目标 code 当作中间监督，再训练两个
可替换的先验入口：“参考前缀 -> code”和“人工标签 -> code”。对本项目最有价值的不是照搬其 SDLM，
而是采用相同的接口分层：

```text
target/SVC reference -> performance encoder -> P code      # 教师/直接参考路径
MIDI+TEXT+A          -> performance prior   -> P code      # 无参考自动路径
human controls       -> control mapper      -> P code      # 人工编辑路径
P code               -> B performance branch              # 唯一消费接口
```

这样第四条件本身保持统一，同时满足“参考带来控制力”和“人可以指定怎么唱”。

这份代码支持“音素池化 + 离散瓶颈 + 音素级人工控制”的架构方向，但不支持“4--8 维已经足够”这一
具体容量判断。相反，TCSinger 的已发表实现使用 64 维 lookup；本项目若直接尝试 8 维，属于比其更激进
的容量压缩，必须作为独立消融验证。

结论：这与“目标声学信息经过极窄瓶颈，推理换成参考音频”的设想最接近；关键不仅是降低通道维度，
而是先按音素池化，再进入离散码本。

### 量化参考风格

`P1` [StyleSinger](https://arxiv.org/abs/2312.10741) 从参考 mel 和 F0 提取细节，使用 Residual
Quantization 建立信息瓶颈，并通过内容表示作为 query 对量化风格序列做对齐注意力。作者将音符过渡、
颤音、发音和 articulation 归入该细节风格。

结论：残差量化适合逐级增加参考保真度；但 StyleSinger 的“style”同时包含较多属性，不能直接认为
已与内容和音色完全解耦。

### 表现属性级联生成

`P1` [ExpressiveSinger](https://doi.org/10.1145/3664647.3681642) 将表现控制明确拆为音素时值、F0
曲线和 amplitude envelope，再以级联扩散生成最终声学结果。作者报告这些控制提升 musicality、
一致性和可控性，并降低数据需求。

`P1` [Everyone-Can-Sing](https://arxiv.org/abs/2501.13870) 进一步将歌唱拆成：

```text
performance = F0 curve + amplitude envelope + performance timing
pronunciation = local content sequence
timbre = time-independent speaker embedding
style/technique = selector token
```

在 SVC 模式下，F0 和 amplitude 可直接从输入演唱提取。

结论：把表现力从音色、歌词和 MIDI 中显式分离，比依靠一个全局 style embedding 更符合本项目目标。

### 技巧标签、提示词与 CFG

`P1` [TechSinger](https://arxiv.org/abs/2502.12572) 使用音素级 technique sequence，覆盖强弱、
混声/假声、气声、气泡音、颤音、咽音和滑音。它用自动 detector 扩充标签，并将自然语言 prompt
映射为 technique sequence。训练中以 0.1 概率丢弃整句或局部音素的 technique label，采样时使用
conditional/unconditional vector field 做 CFG。

结论：把 performance 作为正式条件、在整句和局部两种粒度丢弃、再独立 CFG，有直接的歌声 Flow
Matching 先例。

### 自动表现标注

`P1` [STARS](https://aclanthology.org/2025.findings-acl.781/) 可联合输出音素对齐、音符转录、音素级
技巧和全局情绪/速度。其音素级技巧包括 mixed、falsetto、strong、weak、glissando、breathy、
bubble、vibrato 和 pharyngeal；官方代码和 checkpoint 位于
[gwx314/STARS](https://github.com/gwx314/STARS)。

论文和官方仓库核验后，STARS 对本项目有明确语言边界：

- 公开 checkpoint 只有 Chinese 与 Chinese-English 两种；论文数据是 GTSinger 中英子集加 30 小时
  中文自录数据，作者明确将“只验证中英”列为限制；
- 官方 phone set 是 Pinyin + ARPA，共 123 个 phone；本项目日语路径是 `pyopenjtalk -> IPA`，包含
  44 个日语输出符号和约 28 个日语独有 token，两者不能直接复用 ID；
- 仓库 `mixedtext2phoneme.py` 虽在语言枚举中写有 `japanese`，但仓库没有提交所引用的
  `mfa_dict/japanese.dict`，也没有日语 phone set 或日语 checkpoint。这是未完成占位，不是日语支持；
- STARS 单语模型平均 technique F1 为 `79.9`，双语模型为 `76.8`。双语逐类 F1 差异很大：
  breathy `50.5`、vibrato `50.0`、glissando `69.7`，而 falsetto `86.6`、weak `94.9`、strong
  `99.6`。平均 F1 会掩盖具体技巧的弱项。

`D` 因此不能直接用 STARS 双语 checkpoint 批量生成日语训练真值。更稳妥的日语接入顺序是：

1. 继续使用当前 H/SOFA 的日语音素边界和 GAME/MIDI 时间轴，先绕过 STARS 的 alignment/note heads；
2. 用少量人工日语片段建立逐音素 technique 真值，至少分别报告每类 precision/recall/F1，不接受只看
   macro average；
3. 冻结或部分冻结 STARS acoustic backbone，只适配日语 phone embedding 与 technique heads；
4. 为每一类单独设准入门槛，低可信类别保留为 soft probability 或不进入主训练条件；
5. vibrato 优先由 `delta_f0_high` 定义，breathiness 优先由 aperiodic RMS 定义，分类器只作为语义标签
   和交叉检查，不承担唯一监督。

`H` 第一版 technique label 可以优先保留 falsetto、mixed、pharyngeal、bubble、strong/weak 等较难用
单一连续曲线表达的类别；vibrato、glissando、breathiness 同时保留显式曲线，避免低质量分类标签覆盖
可测声学事实。

`P1` [GTSinger](https://github.com/AaronZ345/GTSinger) 提供六种技巧的人工音素级标签和受控对照：
mixed voice、falsetto、breathy、pharyngeal、vibrato、glissando，并提供 emotion、pace、range 等
全局标签。

结论：本项目不一定需要人工从零标注，可以先用自动标签作为弱监督，再以少量人工复核建立门禁。

### 显式动态控制

`P1` [Controllable SVS using Phoneme-Level Energy Sequence](https://arxiv.org/abs/2509.07038) 直接把
能量序列作为输入条件。其结果为：

| 模式 | Energy MAE | MOS |
|---|---:|---:|
| MIDI/TEXT baseline | 0.33 | 3.43 |
| 音素级 energy | 0.14 | 3.78 |
| 帧级 energy | 0.03 | 3.57 |

作者指出帧级控制最精确，但短于十秒也常超过一千个值，不适合人工操作；音素级控制保留主要动态走向，
且更方便编辑。

结论：自动预测某属性不等于可控。明确输入属性序列，才能建立输入变化到输出变化的因果控制。

### 颤音分解

`P1` [VibE-SVC](https://www.isca-archive.org/interspeech_2025/choi25e_interspeech.html) 用离散小波把
log-F0 分成低频轮廓和高频细节，单独预测高频 F0 以转换 straight/vibrato。推理可直接缩放高频 F0，
并支持局部帧级缩放。

结论：对可解释且有明确频带的表现属性，应优先显式分解，不必要求黑盒 latent 自行发现。

### F0 不是单一提取器真值

本地 singing-style acoustic audit 已有可复用配置：`torchcrepe full`、16 kHz、hop=160、
`fmin=50/fmax=1100 Hz`，并保存 periodicity。它适合建立 CREPE 侧轨，但 `1100 Hz` 上限和
`periodicity>=0.5` 是旧分析合同，不应未经数据审计直接冻结为生成控制合同。

`P1` [RMVPE](https://www.isca-archive.org/interspeech_2023/wei23b_interspeech.html) 在 polyphonic vocal
pitch 上直接处理混音，避免“先 separator 再 tracker”的串联误差；论文在 MIR-ST500 上相对次优方法
提高 `6.32%` RPA，并证明低 SNR 下比 CREPE 更稳。另一方面，CREPE 在干净单声源和复杂音色上有成熟
精度依据。VibE-SVC2 又说明 vocal fry 的 subharmonic 会让常规 F0 tracker 失败，需要额外纠错。

`D` 第一版采用多提取器共识，而不是任选一个 `.f0.npy`：

```text
clean/raw vocal : torchcrepe + RMVPE-vocal
mixture         : RMVPE-poly direct + separator->torchcrepe
WORLD analysis  : 使用上面得到的 consensus F0，不让 DIO/Harvest 独占 F0 真值
```

逐 512-sample cell 保存两条原始 F0、各自 confidence/periodicity、voiced flag、最终 consensus 和
`agreement_state`。初始共识规则：

1. 两者均 voiced 且差值小于 `50 cents` 时，在 log-F0 域按 confidence 加权。
2. 出现接近 `1 octave` 的分歧时，MIDI/GAME 只用于选择合理倍频候选，不能把连续 F0 量化回 MIDI。
3. 单 tracker voiced 时保留候选但标低置信；两者冲突且无法由 MIDI 解释时置 invalid，不做长距离插值。
4. vocal fry、极低周期性、清辅音和强 breathy 区单独统计，不把它们混进普通 voiced 准确率。
5. `fmax` 先按训练/参考 MIDI 与双 tracker 的观测分布审计；若存在高于 `1100 Hz` 的有效音符，必须
   提升范围或增加专用高音 tracker，不能静默 clamp。

`50 cents` 只是与常见 RPA 定义一致的候选门限，不是最终生成准入阈值。正式门限由人工标注的小型
高音、vibrato、breathy、fry 分层集确定。所有被 mask 的区间仍可由 MIDI low contour 和 performance
prior 补全，但不得把插值结果重新标成观测真值。

### 内容和音色泄漏

`P1` [CopyCat](https://www.isca-archive.org/interspeech_2020/karlapati20_interspeech.html) 使用
InstanceNorm、条件 VAE 和时间瓶颈做细粒度韵律迁移。作者实测隐藏维过小会损害 prosody transfer，
过大会产生 source speaker leakage，因此将 latent 沿时间轴固定倍率下采样后再复制上采样。

`P1` [Information Sieve](https://www.isca-archive.org/interspeech_2021/dai21_interspeech.html) 也发现
直接减小 style embedding 维度会恶化质量；其有效做法是时间下采样/上采样和 InstanceNorm，使解码器
依赖文本分支恢复内容、只依赖 style 分支恢复韵律。

`P1` [Controllable Singing Style Conversion with Boundary-Aware Information Bottleneck](https://arxiv.org/abs/2604.05526)
对 Whisper 表示做音素区间池化并缩放至 `lambda=0.1`，同时使用显式 frame-level technique matrix。
其消融中，`pooling + lambda=0.1` 的 Converted/Leakage 为 `83.3%/8.3%`，而
`pooling + lambda=1.0` 为 `66.7%/27.8%`。更关键的是完全关闭该表示的 `lambda=0` 虽把 Leakage
降到 `11.1%`，但 speaker similarity 从 `0.732` 降到 `0.428`，Converted 也从 `83.3%` 降到
`66.7%`。这不是本项目 performance bottleneck 的同构实验，但明确证明“继续压到零”不会单调改善
有效控制。

结论：`维度越低 -> 泛化越强` 不是单调规律。时间率、量化、归一化、输入分解和训练约束共同决定
实际泄漏与可用信息。

### 低比特率 prosody token

`P1` [Vevo2](https://arxiv.org/abs/2508.16332) 使用单码本 VQ-VAE 将 50 Hz chromagram 下采样八倍，
形成 6.25 Hz、512 码字的 prosody token，即：

```text
6.25 token/s * log2(512) = 56.25 bit/s
```

它主要重建 chromagram，因此更偏旋律/粗粒度 prosody，不能覆盖全部力度、气声和发声质量，但提供了
可执行的低带宽标尺。

### 可调带宽的音频条件

`P1/P2` [Audio Conditioning for Music Generation via Discrete Bottleneck Features](https://arxiv.org/abs/2407.12563)
使用 frozen audio encoder、Transformer、6 层 RVQ 和 5 Hz 时间下采样。训练时均匀随机使用 1--6 个
RVQ 层；推理使用越多层，结果越接近参考，使用越少层，生成自由度越高。该工作还发现高信息量音频
条件会压过文本条件，因此提出 double CFG 平衡两者。

`O` [MusicGen-Style 官方 AudioCraft 实现](https://github.com/facebookresearch/audiocraft/blob/main/audiocraft/modules/conditioners.py)
确认了以下细节：

- 发布配置使用 MERT 75 Hz 特征，`ds_factor=15`，所以条件帧率为 5 Hz；
- style Transformer 隐藏维度为 512，RVQ 为 6 层、每层码本 `K=1024`；训练时
  `torch.randint(1, n_q+1)` 为整个 batch 均匀抽取 1--6 层，推理通过 `eval_q` 选层数；
- 名义离散带宽是每层 `5 * log2(1024) = 50 bit/s`，因此推理范围约 50--300 bit/s；
- `eval_q` 默认是 3，但公开 API 允许设置 1--6；官方说明层数越少越不服从参考，层数越多越相似；
- double CFG 实际执行三组前向：`text+style`、`style-only`、`unconditional`：

```text
l = l_empty + alpha * (l_style + beta * (l_text_style - l_style) - l_empty)
```

其中 `beta=1` 退化为普通 CFG；增大 `beta` 主要强化文本相对于高信息量音频 style 的影响。

发布配置并非严格的四种 mask 各 25%。它先以 0.1 概率 batch-wise 丢弃全部条件，再分别以 0.4
概率 batch-wise 丢弃 text 和 style。按代码顺序推得近似分布为：both 32.4%、text-only 21.6%、
style-only 21.6%、none 24.4%。论文的 25% 四等分应视为方法描述，公开 checkpoint 配置采用了近似
覆盖。

这个实现还给出一个重要反例：瓶颈内部 embedding 可以保持 512 维，真正限制信息的是 5 Hz 离散码和
RVQ 层数。不能仅由“8 维比 64 维小”推断泄漏更少或泛化更强；连续值精度、时间帧率、码本数和层数
共同决定有效容量。

论文的 RVQ 层数消融进一步量化了相似度和复制风险的同步上升：

| MERT RVQ 层数 | 码率 | FAD | KNN-common | KNN-overfit | 人评 SIM | 人评 VAR |
|---:|---:|---:|---:|---:|---:|---:|
| 1 | 50 bit/s | 0.78 | 0.19 | 0.06 | 70.27 | 69.69 |
| 2 | 100 bit/s | 0.75 | 0.24 | 0.13 | 72.53 | 72.81 |
| 4 | 200 bit/s | 0.75 | 0.29 | 0.18 | 74.15 | 75.12 |

在音质基本不变时，更多 RVQ 层让结果更像参考，同时也更像参考所属的同一首歌。它不是单向的“控制
更好”，而是控制保真与复制风险一起增加。对本项目应寻找 Pareto 点，不能只按 Oracle 相似度选最大层数。

更关键的消融是 loss masking。MusicGen-Style 会从 LM 交叉熵中屏蔽送入 style encoder 的原始参考
片段；去掉该屏蔽后，FAD 从 `0.75` 变为 `1.11`，KNN-overfit 从 `0.18` 升至 `0.30`，并出现复制和
循环。即使 KNN-common 反而从 `0.29` 降至 `0.22`，过拟合仍更严重，说明普通“参考相似度”指标不足以
发现答案复制。

结论：本项目可以同时使用两个不同旋钮：

```text
RVQ depth / bitrate：决定参考中有多少细节可被模型看到
performance CFG：决定模型对已看到细节服从多强
```

二者不应被混为同一个超参数。

### 同目标 performance 的答案侧信道

`D` 本项目原始设想在训练时由目标 B latent 生成 performance condition，同时又要求 DiT 重建同一个
B。与 MusicGen-Style 的短参考片段相比，这条条件覆盖整个预测区间，侧信道风险更强。若 encoder、
quantizer、decoder 和 DiT 联合训练，它们可以共同发明一套不可解释的压缩编码；低维并不阻止这种协作。

因此 Oracle performance 只能测“条件通道容量上限”，不能证明参考迁移、泛化或人类可控性。第一轮
必须加入以下约束：

1. performance encoder 先用显式曲线、技巧标签和双视图一致性预训练；接入 DiT 的初期冻结 encoder，
   避免它立刻与生成器共谋编码目标答案；
2. 对 performance 输入做连续时间块 mask、轻量时间抖动和 SVC/codec 双视图，不能让每个目标帧总能
   看到同位置的精确 latent；
3. 训练时随机 RVQ depth，并显式覆盖 no-performance；推理同时扫 bitrate 与 `gP`；
4. 主要裁决使用不同 rendition/不同 singer 的参考迁移，Oracle 同目标只作为上界；
5. 增加“同参考来源检索率”或片段级 nearest-neighbor 指标，不能只用 F0/energy 相关性；
6. 若找不到同 MIDI/歌词的多 rendition 数据，至少使用 reference shuffle、错歌词参考和局部 holdout
   作为反事实测试。

不建议简单照搬 MusicGen 的“屏蔽参考区 loss”，因为这里参考覆盖整个 B，全部屏蔽会消灭主任务。对应
替代是冻结/预训练条件编码器、遮挡条件本身，以及把非 Oracle 参考作为主要评测分布。

### 实际编辑器暴露的控制维度

`P1` [OpenVPI DiffSinger](https://github.com/openvpi/DiffSinger/releases/tag/v2.0.0) 将时值、F0、energy、
breathiness、voicing 和 tension 建为可预测、可编辑曲线，支持局部 retake 和参数级联。

`O` [OpenVPI DiffSinger 当前实现](https://github.com/openvpi/DiffSinger/blob/main/utils/binarizer_utils.py) 对
这些名称给出了可复现定义：

```text
energy      = RMS(full waveform), dB
breathiness = RMS(aperiodic component), dB
voicing     = RMS(harmonic component), dB
r_tension   = sqrt(RMS(H_full)^2 - RMS(H_base)^2) / (RMS(H_full) + eps)
tension     = logit(clamp(r_tension))
```

harmonic/aperiodic 分离可由 WORLD 的 CheapTrick+D4C 完成，也可使用其专门训练的神经网络 separator。
官方 Best Practices 明确警告：energy、breathiness、voicing 不应三者同时启用，因为总能量本身由
harmonic 与 aperiodic 部分共同构成；当前更推荐 voicing 取代总 energy。voicing/energy 与 tension 也有
听感耦合，固定响度后单独改变 tension 可能降低自然度。

`D` 因此这些量应称为可重复计算的声学代理，不应直接宣称是生理意义上的“气息”或“声带紧张度”。
它们依赖 F0 和 harmonic-noise separator；清辅音会自然提高 aperiodic energy，SVC 也可能系统性改变
分解结果。必须做音素门控、提取器一致性和 SVC 前后对照。

OpenVPI 默认 44.1 kHz、hop=512，曲线帧率为 86.1328 Hz。当前项目 VAE 是 44.1 kHz/2048，恰好
每 4 个 hop 对应 1 个 VAE 帧。只有 extractor 的 `center/padding/frame-origin` 经验证后才可采用固定
四帧聚合；否则必须走“时间轴合同 v1”的共享 sample-time adapter。聚合仍需分别测试 mean、
RMS-domain pooling 和保留峰值的统计量，不能默认简单均值对短促起音最优。

本地 `StableAudioInfer.encode_audio()` 还会把每条输入按峰值归一到 `-6 dBFS`，随后才送入 VAE。
因此当前 Flow target 不包含录音原始绝对增益，只保留归一化后的局部力度关系。performance 的
`energy/breathiness/voicing` 首版也不能把原始文件 dB 当作可复现控制量。候选预处理是：

```text
peak-matched：对完整歌曲复用 VAE 的 -6 dBFS peak normalization，再提取局部曲线
relative-E ：E_rel(t) = E_db(t) - Q95(E_db on voiced frames)
relative-B ：B_rel(t) = 20log10(RMS_aperiodic / RMS_full)
relative-V ：V_rel(t) = 20log10(RMS_harmonic / RMS_full)
```

`relative-B/V` 更接近成分占比，但会放大低能量区噪声，必须在 voiced/phone mask 内使用。归一化必须
在完整歌曲上离线完成，不能随随机 `ref_len` 对 B 区单独重算，否则同一音频的 condition 会随 A/B
切点改变。

`P1` [Synthesizer V Studio](https://sv2.docs.dreamtonics.com/en/parameter-panel) 暴露 pitch、loudness、
tension、breathiness、voicing、tone shift 和 singer-specific vocal modes。

`P1` [ACE Studio](https://docs.acestudio.ai/ai-vocal-synth/creating-ai-vocals/editing-pitch) 将 AI 自动 pitch
与用户 pitch 分层，允许用户锁定局部、覆盖曲线并重新生成其他部分。

结论：用户界面不应要求直接编辑不可解释的 4D/8D latent。更成熟的交互是“自动生成基础表现 +
显式曲线覆盖 + 局部锁定/重取样 + 参考跟随强度”。

### SVC 作为 B 区参考的边界

`P1` [PPG-based SVC](https://arxiv.org/abs/2010.14804) 对 SVC 的目标定义就是改变 singer timbre，同时
保留内容、旋律和节奏。因此先过 SVC 在概念上可以规范化歌手音色，但它不会消除歌词、F0 和时序；
这些正是 SVC 被要求保留的信息。

`P1/P2` 近期系统仍把 style/timbre 解耦视为未解决问题：

- [S2Voice](https://arxiv.org/abs/2601.13629) 报告 timbre reference 会泄漏 style，需额外使用相对
  style-invariant 的全局 speaker embedding 和 style-aware 模块；
- [CoMelSinger](https://arxiv.org/abs/2509.19883) 报告 acoustic timbre prompt 会泄漏 pitch/prosody，
  需序列级和帧级对比约束以及辅助音高转录监督；
- [Singing Voice Conversion with Disentangled Singer and Vocal Technique](https://arxiv.org/abs/1912.02613)
  的实验中，转换 vocal technique 明显比转换 singer identity 困难，说明真实 SVC 不会天然保持或分离
  所有细粒度技巧。

另外三项实证直接约束了“先 SVC 再提取”的可信范围：

- [RobustSVC](https://arxiv.org/abs/2409.06237) 报告 vocal separation 会残留噪声或过度抑制人声；其
  “先分离再提取原始 pitch+energy”基线在干净输入上反而出现更差的 F0 RMSE。更干净的 stem 不等于
  更忠实的表现轨迹。
- [Serenade](https://arxiv.org/abs/2503.12388) 用源演唱 F0 替换转换结果 F0 后，跑调和自然度改善，
  但 style similarity 略降；作者将其归因于源 F0 与转换后 WORLD mcep/bap 的小失配。F0、频谱包络和
  aperiodicity 不是可以任意混搭的三个独立真值。
- [VibE-SVC2](https://arxiv.org/abs/2606.17126) 专门增加 Energy Style Converter 来处理 pitch-energy
  entanglement，并指出 vibrato 的音高和响度存在同步周期变化；同时另建 timbre-style 路径处理
  straight/belt/breathy/vocal-fry。即使先进 SSC 也不会把 energy 或 phonation 当作普通 SVC 的透明输出。

`D` 因此不建议把 SVC 后音频设为唯一 performance 真值。推荐把原始参考与 SVC 结果当成同一表现的
两个视图：

```text
raw reference -----------------> E_perf ----> P_raw
      |
      +--> SVC(target timbre) --> E_perf ----> P_svc

explicit targets：优先从 raw 提取，并记录 SVC 前后差值
residual token：鼓励 P_raw 与 P_svc 在低速 code 上一致
leakage probe ：要求 singer 可识别率下降，但 performance 指标保持
```

一致性约束不应直接对所有连续 embedding 做强 L2，否则会把 SVC 确实改变的气声、谐波结构和起音细节
也错误地当成噪声。先使用同 code 命中率、对比学习或分布距离，并把显式曲线保持率作为门禁。

推理接口可以保留三种模式：

```text
raw        ：最高表现保真，音色/内容泄漏风险最高
svc        ：音色较统一，但会引入转换器偏差
raw+svc    ：显式曲线取 raw，residual code 由双视图一致部分决定
```

如果 SVC 目标音色就是花丸，SVC 音频已经更接近最终 B 目标，复制风险反而更高；仍必须经过低帧率离散
瓶颈，不能把 SVC 本身当作防泄漏机制。

### 原始参考、分离与 SVC 的 paired consistency pilot

本地尚未发现可直接使用的 raw/SVC 成对音频。现有
`experiments/singing_style_embeddings/outputs/manifests/segments_sofa.jsonl` 有 `92,695` 个 SOFA
句段，且已有 torchcrepe F0/periodicity 与频谱混杂提取框架，可复用其 manifest、读取器、分片和严格
artifact 校验；但该库是同一歌手纯人声，最多用于提取器重复性和 codec/separator 对照，不能替代
“非花丸 -> 花丸 SVC”的跨歌手测试集。

首个真实 pilot 建议取 `256` 个非花丸句段，按时长、音区、voiced fraction、periodicity、F0 波动和
谱倾斜分层。每段生成以下同长度视图：

```text
R0 raw vocal
R1 separator(raw mixture)       # 仅当输入含伴奏
R2 SVC-to-Hanamaru(R0)
R3 codec/resample roundtrip(R0) # 非语义处理的失真控制组
```

若 SVC 输出 sample 数改变，第一轮直接判为时间合同失败，不通过全局 stretch 掩盖。评价按维度分开：

| 维度 | 指标 | 解释 |
|---|---|---|
| 粗 F0 | voiced-intersection cents RMSE、Pearson、median shift | 检查旋律与升降是否保留 |
| 快 F0 | DWT/band-pass 高频相关、vibrato rate/depth/phase error | 检查颤音是否被平滑或重写 |
| 发声边界 | UV F1、onset/offset 误差、phone duration 差 | 检查起音、拖尾和断句 |
| 相对力度 | `E_rel` 相关、局部峰值/动态范围误差 | 排除文件增益和 mastering |
| 谐噪结构 | vowel 内 `B_rel/V_rel`、periodicity、HNR/CPP 差 | 检查气声/清晰度，但不预设必须完全保持 |
| 内容与音色 | ASR/PER、singer probe | 确认内容保持且 singer 信息确实下降 |
| 时间稳定 | cross-correlation lag、局部 DTW path deviation | 防止整体 shape 相同但局部错位 |

准入不先拍固定绝对阈值。先以 `R0 vs R3` 得到 extractor/非语义处理噪声底，再报告
`dist(R0,R2) / max(dist(R0,R3), eps)`。只有 F0、UV、phone timing 在大多数 strata 中接近控制组，才
允许从 SVC 视图取这些显式量；`energy/B/V` 即使相关，也必须保留 raw 版本并做下游听感消融。

当前默认来源表据此收紧为：

| performance 分量 | 默认来源 | SVC 用途 |
|---|---|---|
| F0 low/high、UV、phone timing | raw | 一致性检查；通过 pilot 后才可替代 |
| energy | raw 的归一化相对曲线 | 只作稳健性对照 |
| breathiness/voicing/tension proxy | raw + separator 质量门控 | 不把 SVC 输出当真值 |
| residual token | raw/SVC 双视图的一致部分 | 用于压低 singer-specific 信息 |
| singer/timbre | 不进入 performance 显式量 | 仍由 A 区/目标音色路径负责 |

### 单歌手训练下的跨歌手参考域差

本项目 `final_sum_large` 的现有研究资产是同一目标歌手纯人声。若 `E_perf` 只用花丸 target latent
训练，则下面两条推理路径的统计分布不同：

```text
训练：Hanamaru target latent -> E_perf -> residual code
推理：non-Hanamaru latent     -> E_perf -> residual code  # OOD
```

低维/VQ 不会自动解决这个域差。encoder 可能把源歌手的共振峰、气声基线和录音链映射到训练中从未见过
的 code 区域。SVC-to-Hanamaru 能缩小输入域差，但会同步改写部分 performance；这解释了它为何有用，
也解释了它为何不能作为唯一真值。

`D` 第一版应拆成两套来源政策：

1. `P_explicit` 使用跨歌手可定义的 raw 物理量：相对 MIDI 的 F0、UV、单位时值、相对 energy，以及经
   质量门控的谐噪代理。
2. `P_residual` 在只有单歌手训练数据时，默认只接受 SVC-to-Hanamaru 或 raw/SVC 一致部分；直接 raw
   residual 只作为 OOD 实验，不作为承诺接口。
3. 若要正式支持 non-Hanamaru raw residual，先在外部多歌手歌声上预训练 `E_perf + codebook`，用
   singer adversary、InstanceNorm、同唱法跨音色配对或 SVC augmentation 压低身份信息，再冻结后接入
   花丸 DiT。

压缩器也不应只看 `target latent + MIDI`。MIDI 解释音高/音符结构，但不能解释辅音、元音和发音位置；
若缺少 TEXT/phone side information，residual code 会被迫携带歌词声学差异。更合理的条件残差化是：

```text
z_base = Baseline(TEXT, MIDI, phone boundary)
z_perf = Quantize(E(target_latent, z_base) - z_base_projection)
P      = Decoder(z_perf, TEXT, MIDI, phone boundary)
```

这里不是要求重建完整 `target_latent`，而是让 TEXT/MIDI 解释可预测内容后，code 只补充表现残差。必须
继续用 ASR/phone/singer probe 验证 code 是否真正减少内容和身份信息。

对应最小 2x2 域差消融：

| residual encoder 训练 | 推理参考 | 问题 |
|---|---|---|
| Hanamaru-only | SVC-to-Hanamaru | 第一版可部署基线 |
| Hanamaru-only | raw non-Hanamaru | 测 OOD 崩坏和 singer leakage |
| multi-singer invariant pretrain | SVC-to-Hanamaru | 测预训练是否仍有收益 |
| multi-singer invariant pretrain | raw non-Hanamaru | 最终目标接口 |

若第四格没有明显追平第一格，就不能宣称“直接塞非花丸参考”已被支持；此时仍可保留 raw 显式控制，
而 residual 路径要求先 SVC。

## 核心判断

### 单一黑盒瓶颈只解决一半目标

`D` 极窄 latent 可以从参考演唱向主模型提供 MIDI/TEXT 外的信息，因此能够提高表现控制力。但是：

- CFG 只能控制整体上“跟随这条 latent 多少”；
- 一个黑盒维度没有稳定语义，不能保证某一维就是拖尾、颤音或力度；
- 直接编辑 latent 容易同时改变多个听感属性；
- latent 可能携带歌词、音色和精确声学答案，而不是表现残差。

因此纯 `8D latent + CFG` 无法独立满足“人能控制具体怎么唱”。

### 推荐表示：显式控制加残余 token

```text
P_explicit(t): 人可理解、可画曲线、可从参考自动提取
P_residual(t): 低带宽离散 token，补充未建模细节
```

第一版候选显式维度：

| 维度 | 建议表示 | 主要控制 |
|---|---|---|
| `delta_f0_low` | 相对 MIDI 的低频 log-F0 | 升降、压低、滑音、起收音 |
| `delta_f0_high` | F0 高频残差或小波细节 | 颤音、细微不稳定度 |
| `uv` | F0 提取器的清浊音 mask/probability | 起音、尾音、清辅音边界 |
| `duration_residual` | 实际音素时值相对 score/H 的残差 | 抢拍、延迟、拖尾 |
| `energy` | 句内归一化全波形 RMS dB | 最小基线的渐强、渐弱、重音 |
| `breathiness` | aperiodic 分量 RMS dB | 气声、空气噪声和清辅音强度 |
| `voicing` | harmonic 分量 RMS dB | 有声部分响度、虚实和耳语化 |
| `tension_proxy` | 非基频谐波占总谐波的比例 logit | 声音锐度/紧实度代理 |
| `technique` | 音素级 multi-hot | falsetto、vibrato、glissando 等 |

首轮不能同时输入 `energy + breathiness + voicing`。应将其拆成至少两个显式消融：

```text
E  ：delta-F0 + UV + duration residual + energy
HV ：delta-F0 + UV + duration residual + breathiness + voicing
HVT：HV + tension_proxy
```

`E` 最简单；`HV` 信息更可分解；`HVT` 只在局部编辑能稳定改变听感且不破坏响度自然性时保留。

`P_residual` 第一轮不要求可解释，但必须接受泄漏探针和参考交换实验。

## 信息带宽预算

只说“压到 8 维”无法描述真实瓶颈。至少要同时指定：

```text
通道维度 D
时间率 R token/s
每个值或码字的精度 B
```

以下只作为容量上界近似，不等于真实互信息：

| 表示 | 近似带宽 |
|---|---:|
| 64D fp16 @ 21.533 Hz | 22,050 bit/s |
| 8D fp16 @ 21.533 Hz | 2,756 bit/s |
| 4D fp16 @ 21.533 Hz | 1,378 bit/s |
| 1D fp16 @ 21.533 Hz | 344.5 bit/s |
| 单 VQ，K=256 @ 5.383 Hz | 43.1 bit/s |
| 单 VQ，K=512 @ 5.383 Hz | 48.4 bit/s |
| Vevo2，K=512 @ 6.25 Hz | 56.25 bit/s |

`D` 即使是逐帧 8D fp16，其名义带宽仍约为 Vevo2 prosody token 的 49 倍。因此如果目标是防止答案
复制，时间下采样和离散量化通常比继续从 8D 压到 4D 更关键。

### 音素级 VQ 仍足以编码歌词

低 token/s 不等于低内容容量。若每个 phone 恰好产生一个 code：

```text
K=512 -> 9 bit / phone
K=256 -> 8 bit / phone
K=16  -> 4 bit / phone
```

当前项目日语输出集合约 `28--44` 个有效 phone/token 类，标识一个类别的上界只需约
`log2(28)=4.81` 到 `log2(44)=5.46 bit`。因此 `K=256` 或 `K=512` 单码本在容量上完全足以把 phone
身份编码进 code；甚至 `K=16` 也能泄漏元音/辅音大类。code 序列的长度、边界和重复模式还会额外泄漏
时值与内容结构。

这不意味着音素级 token 不可用，而是必须把“condition on phone”和“remove phone information”写进
训练目标：

```text
L_phone_indep = mean_phone KL(p(code | phone) || p(code))
L_singer_indep = mean_singer KL(p(code | singer) || p(code))
```

可用 adversarial probe、分布匹配或 balanced sampling 近似实现；权重不能大到抹掉辅音起音和元音内
技巧。更稳妥的主结构仍是先由 `Baseline(TEXT,MIDI,phone)` 解释内容，再量化目标残差。

必须报告：

- `code -> phone` probe accuracy、macro-F1、NMI，和 phone majority baseline；
- `code -> singer` probe；
- 相同 technique 下不同 phone 的 code 分布距离；
- 把 code 跨 phone 交换后，目标表现指标是否仍按 code 变化，而非产生错字；
- 只给 code/null TEXT 时的 ASR/PER，及错歌词 reference 的源歌词插入率。

TCSinger 的 `K=512/dim=64` 只能作为有效容量基线，不能作为“已经证明无歌词泄漏”的证据。其已发表
timbre A/B 实验支持音色解耦，但没有替本项目完成 code-level content probe。

## 推荐架构

```text
B reference / SVC waveform
        |
        +--> explicit extractors ----------------------> P_explicit
        |
        +--> VAE latent + MIDI + aligned TEXT
                         |
                temporal pooling/downsampling
                         |
                  low-D encoder + VQ/RVQ -------------> P_residual

[P_explicit | P_residual | MIDI]
        -> small Conv/Transformer decoder
        -> performance embedding
        -> B-only performance branch

base_input = base_proj([x_t, A_cond, text, midi])
dit_input  = base_input + performance_proj(performance_embedding)
```

### 接入方式

`D` 推荐新增独立 `performance_proj`，并将其权重和 bias 初始化为零，而不是直接复用 `audio_cond`。
这样有四个优势：

1. 新 checkpoint 初始化时与旧模型函数一致；
2. A 区和 B-performance 可以独立 dropout；
3. `performance = null` 有明确语义；
4. 不必修改旧 `Linear(768,1024)` 权重布局。

也可以扩展旧线性层并复制原 768 列、将新列置零，但独立投影更便于审计和 CFG。

当前 `YingMusic_Singer.yaml` 使用 `attn_mask_enabled=False`，DiT blocks 是非因果全局 self-attention。
所以 `performance_embedding[:, :ref_len]=0` 只能保证**注入位置**在 B，不能保证经过多层 attention 后
performance 对 A 输出严格无影响。第一版必须在 `performance_proj` 后再次乘 B mask，并报告：

```text
delta_A = mean_norm(v_full - v_noP, frames < ref_len)
delta_B = mean_norm(v_full - v_noP, frames >= ref_len)
spill_ratio = delta_A / (delta_B + eps)
```

同样要在最终采样 latent/波形上比较 full 与 no-P 的 A 区差异。若 `spill_ratio` 或 A 区可听差异明显，
再单独实验“不允许 A query attend B、允许 B attend A”的非对称 mask，或在采样中硬保持 A reference；
不能把 attention mask 改动和 performance 分支首轮同时上线，否则无法归因。

### 时间粒度

第一轮同时比较以下候选，不能只比较通道维：

| 候选 | 优点 | 风险 |
|---|---|---|
| 8D continuous @ 21.53 Hz | 最接近原始设想，易实现 | 带宽仍高，可能复制内容 |
| 4D continuous @ 5.38 Hz | 简单且明显收窄 | 连续值仍可编码复杂信息 |
| VQ K=256 @ 5.38 Hz | 带宽明确，易做泄漏审计 | 可能 codebook collapse |
| RVQ 1--6 层、K=1024 @ 5 Hz | 有 MusicGen-Style 官方实现；50--300 bit/s 可调 | 训练和 checkpoint 更复杂 |
| 音素级 CVQ K=512、dim=64 | 有官方实现依据，最接近 TCSinger | 对本项目可能仍过宽，需严格查泄漏 |
| 音素级 CVQ K=256、dim=8 | 极低容量，便于审计 | 激进项目假设；无 TCSinger 证据保证质量 |

推荐首选“音素级 residual token + 帧级显式表现曲线”。音素 token 负责无法命名的发声方式，帧级
曲线负责长音内部快速变化。显式曲线先比较 `E` 与 `HV`，不默认全部叠加。

### 21.533 Hz 不应承载全部微动态

VAE/DiT 时间率是 `44100/2048 = 21.5332 Hz`，Nyquist 频率约 `10.77 Hz`。VibE-SVC 报告典型
vibrato rate 为 `5--8 Hz`，因此一个颤音周期在 DiT 时间轴上只有：

```text
5 Hz -> 4.31 latent frames / cycle
8 Hz -> 2.69 latent frames / cycle
```

理论上没有超过 Nyquist，但已经不足以稳定表达相位、非正弦形状、短暂启停和与能量同步的微动态。
若把 `86.13 Hz` 曲线每四帧做 box average，5 Hz/8 Hz 振幅还会约衰减到原来的 `0.92/0.80`，之后
再由模型猜回深度并不利于可控性。

`D` 显式 performance 应采用三种时间粒度，而不是把所有量先平均到 `T`：

```text
slow[T]       : delta-F0 low、relative energy trend、连续强弱包络
micro[T,4,C]  : delta-F0 high、UV/onset edge、周期性 energy；每个 latent 帧保留四个 512-sample cell
phone[Nph]    : phone residual code、duration residual、technique、sub-frame start/end offset
```

`micro` 不把 DiT 序列扩成 `4T`。它先按时间轴合同构造规范的 512-sample cell，再把四相位值 pack 到
同一 latent step 的通道维，由小型局部 Conv/MLP 投影到 `performance_embedding`。这样保留 86 Hz
微动态，同时主 DiT 的计算长度不变。

另一个更低带宽、可编辑性更强的候选是对稳定长音使用参数化颤音：

```text
vibrato = {rate_hz, depth_cents, phase, start_offset, end_offset, confidence}
```

在 86 Hz 规范网格上重建后再送入 `micro`。不稳定或非周期段仍使用高频残差曲线。第一轮增加三组：

| 组 | 高频 F0 表示 | 目的 |
|---|---|---|
| Mean4 | 四帧均值后 21.53 Hz | 最便宜基线 |
| Polyphase4 | 每 latent 保留四相位样本 | 检查颤音相位/深度和短起音收益 |
| ParamVib | 音素级 rate/depth/phase + 非周期 residual | 检查可编辑性与最低有效带宽 |

这部分增加的是有名称、可测量的显式带宽，不等于放宽黑盒 residual token。泄漏限制仍主要施加在
`P_residual`；不能为了降低总 bit 数，把已经可解释的 5--8 Hz 颤音先破坏掉。

### 时间轴合同 v1

本节基于当前本地实现审计，不是论文推测。相关代码包括：

- `package_v4c_finetune/train/train_v5p_simple.py`
- `package_v4c_finetune/h_alignment/manifest.py`
- `package_v4c_finetune/h_alignment/placement_v4iph.py`
- `YingMusic-Singer-Plus-src/src/YingMusicSinger/melody/game_cache_v4ph.py`
- `YingMusic-Singer-Plus-src/src/YingMusicSinger/utils/stable_audio_tools/autoencoders.py`

当前实现并没有完全统一的时间换算：

1. VAE 配置的总下采样率是 `2048`。Oobleck encoder 的五级 stride 为 `2*4*4*8*8`；当前卷积
   padding 下，非 chunk 编码长度按逐级 floor 收缩。训练最终以实际 `latent.shape[-1]` 作为 `T`。
2. H manifest 先把秒数按 `ROUND_HALF_UP` 量化为整数微秒，再按 `44100/2048` 有理数四舍五入到
   最近的**相对帧**；但 phrase 绝对 anchor 仍用 `int(start * 44100/2048)` 截断。
3. H 为保证一个帧只能放一个歌词 token，会通过 `solve_monotonic_frames` 移动量化后发生碰撞的 token。
   动态 `ref_len` 下，它还按 phrase center 把整句归入 A 或 B，并可能把句首夹到边界上。
4. GAME adapter 没有采用上述固定帧格。它把 `T` 个目标帧中心均匀铺在真实 PCM 时长上，并对 SOME
   概率线性插值到 `T`。因此 GAME、H 与 VAE 的时间原点/尾部处理目前并非同一个函数。

`D` 第四条件不能继续复制其中任意一套局部规则。第一版冻结以下合同：

```text
N = VAE 重采样到 44.1 kHz 后的实际 PCM sample 数
T = 本次 VAE encode 得到的实际 latent 帧数
R = 2048 samples / latent frame

latent frame i 的物理区间 = [i*R, (i+1)*R)
latent frame i 的中心       = i*R + (R-1)/2
有效 performance PCM 区间   = [0, T*R)
```

- `T` 是唯一长度权威。任何 manifest、duration 或浮点秒数都不能反推并覆盖它。首版加载时断言
  `T == N // 2048`；若某条 chunk/预处理路径不满足，必须显式记录并停止，而不是静默插值。
- 离线 manifest 同时保存原始整数微秒和 44.1 kHz 整数 sample 边界。SOFA phone 使用半开区间
  `[start_sample, end_sample)`；从秒转换时复用 H 的 decimal half-up 规则，禁止平台相关 float round。
- residual code 的基本单位是 SOFA phone/mora 记录，不是稀疏 H tensor。最少保存
  `phone_id/start_sample/end_sample/mora_id/phrase_id/code_id/valid`。H 的碰撞移位只服务歌词 token
  放置，不能改写 performance phone boundary。
- phone code 展开到 latent 时使用区间重叠权重：

```text
w(i,j) = overlap(latent_interval_i, phone_interval_j) / 2048
P_phone[i] = weighted_pool(code[j], w(i,j))
```

  这样短于 `46.4 ms` 的 phone、同一 latent 帧内的多个 phone 和跨帧 phone 都无需碰撞右移。无可靠
  SOFA 区间时 residual 置 null，显式曲线仍可使用。
- `SEP` 和 `PUL` 是 H 的序列/回退语义，不是声学表现标签。performance 分支不读取它们，也不因
  PUL 覆盖而把真实音频区间解释成静音。
- 显式曲线必须携带整数 sample 时间戳或确定的 frame origin，再由一个共享
  `resample_track_to_latent()` 做抗混叠/区间聚合。`44.1k/hop512` 名义上恰好每个 latent 四个 hop，
  但只有在 extractor 的 `center/padding/frame-origin` 合同被验证后才能直接 reshape；否则四帧一组仍
  可能错半窗或多出尾帧。
- 统一 micro grid 定义为 `cell k = [512*k, 512*(k+1))`，中心为 `512*k+255.5`，总数固定 `4T`。
  CREPE、RMVPE、WORLD 或 separator 原生帧先依据各自时间戳投影到该 grid：F0 在 log 域做置信加权，
  UV/edge 保留离散边界，energy 在 sample/RMS 域按区间聚合。`Polyphase4[i]` 才定义为 cell
  `4i..4i+3`；禁止直接按原生数组下标分组。
- 所有显式曲线和 phone manifest 都按完整歌曲离线生成，与随机 `ref_len` 无关。训练运行时只做：

```text
P[:, :ref_len] = null
P[:, ref_len:] = precomputed_performance[:, ref_len:]
```

  performance 使用精确帧边界，不复用 H 的 phrase-center A/B 归属。phone 跨过 `ref_len` 时只保留其
  B 侧 overlap，不移动 phone，也不把整句推到 B 开头。
- Long 数据必须在完整 Long PCM 上重新提取 SOFA 与 performance，成员 offset 继续以整数 PCM sample
  累积。禁止拼接 Short 曲线后用浮点 duration 校正。

时值控制不能从 H 稀疏 token 间距直接得到。H 的空帧、PUL、碰撞移动和 SEP 位置都混合了渲染语义。
推荐训练一个冻结或 out-of-fold 的 score-side duration baseline：

```text
d0 = DurationPredictor(TEXT, MIDI, H identity)
r_duration = log((d_target_SOFA + eps) / (d0 + eps))
```

第四条件只输入 `r_duration` 或人工覆盖值。这样“拖长/压短”有明确零点，也避免用目标 SOFA duration
同时充当 baseline 和 residual。

推理参考按三种合同区分：

| 参考类型 | 对齐方法 | 可承诺能力 |
|---|---|---|
| 与目标 B 已是同一时间轴 | 直接提取并按上述 sample/latent 合同裁切 | 可复制局部起伏、拖尾和技巧 |
| 同歌词同 MIDI，但局部时值不同 | 按 note/mora/phone identity 做单调对应；F0/音色曲线转为单位内相位，时值差单独进入 `r_duration` | 可迁移唱法，同时保留时值控制 |
| 不同歌曲或无法建立单位对应 | 只能提取统计风格或交给无参考 performance prior | 不能声称提供 B 区逐位置控制 |

SVC 只改变参考视图，不解决时间对应。原始参考与 SVC 参考都必须通过同一 alignment contract；全局
拉伸到 B 长度会把局部时值、起音和拖尾混在一起，不作为正式方案。

该合同至少需要以下自动门禁：

1. 随机 PCM 长度下验证 `N/T`、尾部截断和 Long chunk 一致性。
2. 秒、微秒、sample、latent frame 的往返结果跨 Windows/Linux 字节一致。
3. phone overlap 权重有界，且每个有效 B 帧的权重和符合预期；短 phone 不消失。
4. 改变 `ref_len` 只改变 B mask，不改变离线 code、phone boundary 或显式曲线。
5. 同一音频分别经 H、GAME 和新 performance adapter 后，报告最大/中位时间偏差；不允许只看 shape
   一致。

### PerformancePlan 数据合同

第四条件在进入网络前应先形成版本化、可审计的 `PerformancePlan`，而不是直接暴露 8D latent：

```text
PerformancePlan v1
  timeline:
    sample_rate=44100, cell_hop=512, latent_hop=2048, pcm_samples=N, latent_frames=T
  slow[T]:
    delta_f0_low_cents, energy_rel, valid_mask, source, confidence
  micro[T,4]:
    delta_f0_high_cents, uv, onset_edge, energy_micro, valid_mask, source, confidence
  phones[Nph]:
    phone_id, start_sample, end_sample, duration_log_ratio
    technique_probs, residual_code, valid_mask, source, confidence
  edits:
    locked_ranges, overridden_fields, reference_strength
```

所有连续 pitch 都表示为相对 MIDI/score baseline 的 cents 残差，时值表示为相对冻结 duration baseline
的 log-ratio，响度表示为完整歌曲归一化后的相对量。这样“零”具有稳定含义，且参考、自动预测和人工
编辑可以共用同一格式。

用户操作到计划字段的最小映射如下：

| 操作 | 实际修改 |
|---|---|
| 平 | 目标区间 `delta_f0_low/high -> 0`，vibrato depth 降低 |
| 升 | 对 `delta_f0_low_cents` 加单调上升 ramp |
| 高音 | 对选中 note/phone 加正 cents offset；需要改主音符时同步改 MIDI，不伪装成 performance |
| 压低 | 加负 cents offset，可选择 linked 模式联动 energy/tension prior |
| 拖尾 | 增大 `duration_log_ratio`，并延长 release 段的 F0/energy envelope |
| 颤音 | 设置 rate/depth/phase/start/end，或局部缩放 `delta_f0_high` |
| 轻/重 | 调整 `energy_rel`；linked 模式可同时调用 breathiness/voicing prior |
| 气声/实声 | 调整 technique/`B_rel/V_rel` 目标，不直接修改 singer/timbre embedding |

如果用户把整段参考跟随强度设为 `s`，先在 plan 空间插值：

```text
plan_used = neutral_plan + s * (reference_plan - neutral_plan)
```

再由 `gP` 决定主 DiT 对整个 performance 条件的 guidance。两者不同：`s` 改的是输入计划数值，
`gP` 改的是生成器服从该计划的力度。人工锁定区间只覆盖指定字段，未锁定字段由 prior 或参考继续填充。

`residual_code` 默认不作为数值曲线暴露给用户。可将通过人工试听命名的 code/cluster 显示为唱法 palette，
但在完成跨内容一致性验证前，只能叫 `style A/B/...`，不能把一个相关簇直接命名为“气声”或“压低”。

局部编辑应提供两种模式：

```text
strict edit : 只改指定字段，用于验证因果单调性
linked edit : 指定主字段后，由 learned prior 补充符合人类发声耦合的 energy/tension/phonation
```

训练和评估必须保留 strict 模式。否则系统可能通过联动其他字段制造“听起来变化了”，却无法证明目标
控制量本身有效。

## 多条件 CFG

### 当前语义

当前项目使用偏移式定义：

```text
v_guided = v_cond + g * (v_cond - v_uncond)
```

因此 `g=-1` 是 unconditioned，`g=0` 是正常 conditional，`g>0` 是强化。

### performance 嵌套 guidance

定义：

```text
v0    = 全条件丢弃
vbase = A + TEXT + MIDI
vfull = A + TEXT + MIDI + performance
```

推荐先采用层级式 double CFG：

```text
vP = vbase + (1 + gP) * (vfull - vbase)
v  = v0 + alpha * (vP - v0)
```

性质：

```text
gP = -1 -> vbase
gP =  0 -> vfull
-1 < gP < 0 -> 弱化 performance
gP > 0 -> 强化 performance
```

这种结构与音频/文本双条件的
[Discrete Bottleneck Audio Conditioning](https://arxiv.org/abs/2407.12563) 思路一致，且只需要
`v0/vbase/vfull` 三次前向。

### “四路完全平等”的代价

若 audio、text、midi、performance 都有独立 scale，可计算：

```text
v = vfull + sum_i gi * (vfull - v_without_i)
```

但它只是一阶近似。条件之间存在 `text x midi`、`midi x performance` 等交互时，把四个差分直接相加
不能保证 `gi=-1` 后严格等于真实组合。精确表示全部交互最多需要 `2^4=16` 个子集前向。

`P2` [Composable Diffusion Models](https://arxiv.org/abs/2206.01714) 的多条件 score 相加也依赖“给定
输出后各条件近似独立”的假设。歌声中的 TEXT、MIDI 和 performance 明显相关，因此不能将独立加法
当成严格概率结论。

当前建议是：训练地位上 performance 与其他条件平等；推理计算上先把 `A+TEXT+MIDI` 作为内容基座，
performance 作为可独立控制的嵌套条件。待实测证明需要四个完全独立旋钮后，再承担额外前向成本。

### dropout 覆盖率问题

如果直接在现有三个 Bernoulli dropout 上增加 `performance drop=0.30`：

```text
P(full condition) = 0.7 * 0.85 * 0.7 * 0.7 = 29.155%
P(drop all four)  = 0.3 * 0.15 * 0.3 * 0.3 = 0.405%
```

全丢弃路径会非常稀少，不能仅凭独立 Bernoulli 假设 CFG base 已被充分训练。候选训练采样应显式保证：

```text
full
drop performance only
drop all
各单条件 drop
随机组合
```

第一轮可使用命名 mask 调度器而不是第四个独立 Bernoulli。一个不冻结的起始候选是：

```text
full                         30%
drop performance only        25%
drop all                     10%
drop A only                   5%
drop TEXT only                5%
drop MIDI only                5%
legacy-style random masks    20%
```

这里的“第四条件平等”指它有独立 null、独立 dropout、独立 leave-one-out 差分和独立推理 scale，不要求
四个条件具有相同 dropout 数值。`performance-only` 不建议作为常规训练顶点，因为它会奖励瓶颈单独携带
歌词和旋律；只把它作为泄漏诊断。具体比例必须通过训练吞吐、base 回归和 CFG 稳定性消融决定。

评估端至少固定报告 `full / no-P / drop-all / drop-A / drop-TEXT / drop-MIDI` 六项，并记录每个训练
mask 的累计样本数。否则总体 loss 下降无法判断是主任务改善，还是某个更容易的条件组合占比变化。

## 解码器是否需要扩散

### 第一阶段

`D` 不建议使用第二个扩散模型解压 performance。小型双向 Conv/Transformer 已足以把低速 token、
显式曲线和 MIDI 映射为 DiT 条件 embedding。主 DiT 本身负责生成多模态声学细节。

也不建议把辅助解码器的主要任务设为重建完整 64D target latent。这样会直接奖励瓶颈保存答案。更合理的
辅助目标是重建或预测：

```text
delta-F0 low/high
UV
duration residual
energy，或 breathiness+voicing；不能三者同时作为独立目标
tension_proxy（可选消融）
technique labels
少量局部谱统计
```

### 后续阶段

扩散或 Flow Matching 更适合训练无参考时的表现先验：

```text
p(performance plan | MIDI, TEXT, A)
```

同一 MIDI/TEXT 存在多种合理唱法，该分布天然多模态。参考音频、人画曲线或 prompt 存在时则直接覆盖
或约束该先验。

## 训练路线候选

### 阶段一：表现表示预训练

从真实目标 B 提取显式控制，并训练 residual encoder。候选损失：

```text
L_repr = lambda_exp * L_explicit_reconstruction
       + lambda_vq  * L_commitment
       + lambda_pair * L_raw_svc_code_consistency
       + lambda_spk  * L_speaker_confusion
```

`L_raw_svc_code_consistency` 优先使用同码命中、对比学习或分布距离，并只在显式曲线保持率合格的帧上
启用，不对全部连续 embedding 做强制相等。speaker confusion 可以作为低权重训练项；歌词/content
分类器第一轮只作为冻结探针和门禁，因为直接对抗 phoneme 信息可能同时删除起音、辅音和时值表现。
所有权重均待小规模标定。

### 公开数据预训练可行性

外部数据只用于预训练/评测 `E_perf`、codebook、technique head 和 singer/content probe，不直接改变
花丸主 DiT 的声学目标。当前可用性排序如下：

| 数据集 | 关键事实 | 本项目用途 | 限制 |
|---|---|---|---|
| [GTSinger](https://arxiv.org/abs/2409.13832) | 80.59 h singing、20 位专业歌手、9 语言；手工 phone alignment；六种 phoneme-level technique；同歌词 control/technique 对照 | residual/technique 预训练与 held-out singer/style 测试 | `CC BY-NC-SA 4.0`；日语仅 2 人、6.45 h 左右，仓库仍列有 Japanese refinement |
| [SingStyle111](https://zenodo.org/records/10265401) | 12.8 h、8 歌手、英/中/意；111 首中 80 首有同歌手多风格版本；44.1 kHz dry vocal、phone alignment、MIDI/score | 同内容 style delta、reference transfer 与全局风格对照 | 无日语；官方描述限定 research use，正式训练前需再核许可证文本 |
| [JVS-MuSiC](https://arxiv.org/abs/2001.07044) | 100 位日语歌手唱同一首公共歌曲，另有每人一首独立歌曲；公共歌合计 49m23s、独立歌 88m03s | 日语跨歌手 OOD、singer probe、同歌词检索 | 无细粒度 technique 标签，数据量小；音频许可需按项目页条款单独核验 |
| [PJS](https://www.apsipa.org/proceedings/2020/pdfs/0000487.pdf) | 单歌手、100 个音素平衡日语句、平行说/唱、CC BY-SA 4.0 | 日语 phone/frontend 与 alignment 回归 | 单歌手且论文明确尚未覆盖多样唱法，不用于 style residual 主预训练 |

GTSinger 的日语部分约为 `JA-Tenor-1 2.13 h + JA-Soprano-1 4.32 h`，六技巧覆盖不均，vibrato 在日语
子集最少；realistic score 的主要音域约 MIDI `55--70`。它能验证日语 phone/technique 接口，但不能
替代花丸更高音域、直播录音域和细腻颤音的本地数据。

推荐预训练顺序：

1. 用 GTSinger 全语言训练 `E_perf/codebook/technique head`，phone identity 由语言侧输入，codebook
   共享；按 singer 和 song 分割，禁止同歌/同歌手穿过 train/test。
2. 用其 control/technique 对照学习“同内容下的 technique delta”，但不强迫不同 singer 的整段 code
   完全相同。
3. 用 SingStyle111 验证不同全局 style 的 reference transfer；用 JVS-MuSiC 只做日语 singer leakage
   和同歌词检索，不把 100 人的表演强行设为同一个 positive code。
4. 最后在花丸 raw/SVC 双视图上适配，并在接入 DiT 初期冻结 encoder/codebook。
5. 任何含 NC、SA 或 research-only 数据的训练都先经过许可证门禁；研究实验可独立进行，但不能默认
   其派生 checkpoint 可用于商业发布。

公开数据的主要价值是给 residual encoder 学“不同 singer 仍有可比较的表现坐标系”。它不能替代本地
paired consistency pilot，也不能证明非花丸 raw reference 已与花丸 target domain 对齐。

### 阶段二：接入 DiT

1. 从审计过的同一 checkpoint 初始化两个对照。
2. `performance_proj` 零初始化。
3. 先冻结或低 LR 更新主 DiT，确认新分支被使用且 base 不崩。
4. 再联合训练 Flow Matching；target latent 仍是唯一声学目标。
5. 独立记录有/无 performance 的 FlowA、FlowB 和感知结果。

### 阶段三：自动和人工控制

- 自动模式：从 MIDI/TEXT 预测表现计划。
- 参考模式：从 B 对齐参考/SVC 提取表现计划。
- 编辑模式：用户覆盖显式曲线或 technique sequence。
- 混合模式：锁定局部，其他区域由先验重新生成。

### 推理条件

每组至少测试：

```text
无 performance
目标 Oracle performance
同内容 SVC performance
同 MIDI 不同唱法 performance
错歌词/错歌手 performance
随机 shuffle performance
人工只改一个显式维度
```

### 评价

**表现控制力**：

- 相对 MIDI 的 F0 残差相关性；
- F0 高频/颤音 rate、depth 和 phase；
- energy 或 harmonic/aperiodic contour 相关性；
- V/UV 边界 F1 与起音/尾音偏差；
- 音素时值残差和拖尾误差；
- technique classifier 命中率。

**可控性**：

- 单参数从低到高时，输出指标是否单调；
- 局部编辑是否主要影响目标区间；
- `gP` sweep 是否形成连续变化；
- RVQ depth 增加时，参考相似度是否提高且自由度是否下降。

**泄漏**：

- 从 `P_residual` 训练歌词/音素 probe；
- 从 `P_residual` 训练 singer classifier；
- 使用错歌词参考时是否插入源歌词；
- 只给 residual code 时能否异常重建目标；
- reference shuffle 后内容错误率和音色偏移。

**基础质量**：

- `gP=-1` 与 Base 的配对听感和客观差异；
- MIDI/歌词服从度；
- 花丸音色相似度；
- 噪声、雾感和高频伪影；
- Short/Long 分层 MOS 或成对偏好。

## 第一轮建议

`D` 如果只允许做一条低成本路线，建议：

```text
显式：delta-F0 low @ T；delta-F0 high/UV edge @ 4-phase micro；duration residual + breathiness/voicing
对照：用单 energy 替换 breathiness/voicing；tension_proxy 暂不进入默认组
残余：音素级单码本 VQ；并行比较 K=512/dim=64 与 K=256/dim=8
解码：小型确定性 Conv/Transformer
接入：独立 zero-init performance_proj，只覆盖 B
训练：明确覆盖 full / no-performance / drop-all
推理：三前向 hierarchical CFG
```

原因：显式曲线已经覆盖“平、升高、压低、拖尾、颤音、力度和气声”的主要可感知变化；VQ residual
只负责无法明确命名的发声细节。若该组不能在参考交换和人工干预中产生稳定可听变化，继续扩大黑盒
latent 或增加第二个扩散解码器没有充分依据。

总体中位数会掩盖困难层。RMVPE vs WORLD 的 P90 样本中位数由 high-pitch/control 的

更重要的是，`fmax=2000` 不能全局替换 `1100`。在 low-periodicity 层，CREPE-1100 与
CREPE-2000 的 voicing agreement 仅 `0.434`、voiced Jaccard 为 `0`，没有样本形成可报告的共同
voiced median。代码核验确认 torchcrepe 先按 `fmin/fmax` mask 概率，再做 Viterbi decode，并从
mask 后的概率计算 periodicity；扩大上限会让高频候选参与解码，所以不仅改变高音上限，也会改变困难
帧的清浊与置信度。

### 合成真值结果

合成集使用带 6 个谐波和噪声的已知 F0，专门隔离上限、颤音和滑音错误：

| 条件 | 关键结果 |
|---|---|
| 1200 Hz 常音 | CREPE-1100 miss=`1.0000`；CREPE-2000 miss=`0.0025`、median=`0.1037 st`；RMVPE miss=`0.2344`；WORLD miss=`0.0050` |
| 500→1400 Hz 滑音 | CREPE-1100 的 `>1100 Hz` recall=`0.0672`；CREPE-2000=`1.0000`、median=`0.0966 st` |
| 同一高音滑音 | RMVPE 的 `>1100 Hz` recall=`0.9851`，但 median error=`11.9528 st`，即动态跨区时稳定落低一个八度 |
| 同一高音滑音 | WORLD recall=`0.7761`，已检出的高音 median error=`0.0037 st`，精度高但漏帧较多 |
| 600 Hz、6 Hz、1 st 颤音 | CREPE-2000/RMVPE/WORLD median error=`0.1000/0.0196/0.0017 st`，三者均能跟踪该理想化颤音 |

因此 `1100 Hz` 上限确实会截断超高音；RMVPE 不能因为普通音区精度高就单独作为高音真值；WORLD
适合保守校验，但其高音滑音漏帧不适合作为唯一生产轨迹。

### 前端裁决

第一版不采用“选一个最强 tracker”的方案，而采用 MIDI-aware、多 tracker 门禁：

1. 正常音区保留窄范围 CREPE 解码，避免 `fmax=2000` 扩大困难帧搜索空间；高音 MIDI 或窄范围失声时
   才启用宽范围解码。实现时优先复用同一次 CREPE network probability，按逐帧 MIDI 期望施加动态
   bin mask，避免双前向。
2. RMVPE、WORLD 和宽/窄 CREPE 作为候选，不直接平均。先用已知 MIDI note 对候选做 `f/2, f, 2f`
   最近八度修正，再在共同 voiced 且 pair spread 不超过约 `1 st` 的帧形成高置信轨迹。
3. tracker 分歧、全部失声或离 MIDI 过远的帧必须输出 low-confidence/missing mask，不能静默填零后进入
   performance encoder。颤音 rate/depth 只在连续高置信 voiced 区间估计。
4. 本轮证明了前端需要 GPU 实测，但仍没有证明 performance condition 本身有效；在 F0/UV/duration
   adapter、时间轴和泄漏 probe 冻结前，不启动主 DiT 重训。

## 当前结论快照

- `P1/D` 新增 B-performance 条件有充分先例，且与当前项目缺失信息相匹配。
- `P1/D` 纯全局 style 向量不足；表现条件必须保留局部时间结构。
- `P1/D` 纯 8D 连续逐帧 latent 带宽仍高，不能仅凭维度宣称无泄漏或泛化更强。
- `D` 音素级 `K=256/512` 分别有 `8/9 bit per phone`，容量足以编码当前日语 phone 身份；低帧率 VQ
  仍必须做 phone/singer probe 和 conditional residualization。
- `O/D` TCSinger 的官方尺度是音素级 `K=512/dim=64`；`K=256/dim=8` 是本项目激进假设，必须与
  外部实现尺度并行对照。
- `O/D` MusicGen-Style 证明 512 维内部 embedding 仍可通过 5 Hz RVQ 限制到 50--300 bit/s；应以
  帧率、离散码率和 RVQ 深度衡量容量，而不是只看通道维。
- `P1/D` 最稳妥的第一版是显式控制与低速离散 residual token 的混合表示。
- `O/D` 显式响度首轮应比较 `energy` 与 `breathiness+voicing`，不能三者同时输入；`tension` 只作为
  separator/F0 依赖的声学代理消融。
- `P1/D` SVC 可作为降低 singer 差异的配对视图，但它保留内容和旋律，也会重写部分声学表现，不能
  作为唯一真值或防泄漏机制。
- `O/D` 单歌手 Hanamaru latent 训练出的 residual encoder 直接消费 non-Hanamaru raw reference 是
  OOD。第一版 raw 默认只供显式曲线，residual 默认走 SVC-to-Hanamaru 或双视图一致部分；正式 raw
  residual 需要多歌手 invariant pretrain。
- `O/D` 当前 VAE 对每条输入做 `-6 dBFS` peak normalization，因此绝对录音增益不在 Flow target 中；
  energy/breathiness/voicing 应使用完整歌曲归一化后的相对曲线，不能按动态 B 区重算。
- `P1/D` `21.533 Hz` 对 `5--8 Hz` 颤音每周期只有 `4.31--2.69` 点。首轮应比较 Mean4、Polyphase4
  和 ParamVib，不能默认把所有 86 Hz 微动态四帧平均。
- `P1/D` CFG 控制服从强度，RVQ/VQ 控制可见信息量，两者职责不同。
- `D` 解压器第一版不需要扩散；生成无参考表现计划时才优先考虑扩散或 Flow Matching。
- `O/D` 当前训练 dropout 是每个 rank/microbatch 一个 mask；当前验证 loss 仍混合随机条件 mask。新
  实验必须按命名 mask 固定报告，不以单一混合 loss 裁决。
- `O/D` 当前 H、GAME、VAE 的时间映射并不完全同构。第四条件已冻结 draft v1：实际 VAE `T` 为长度
  权威，SOFA 保存整数 sample 半开区间，phone code 用 overlap 展开，动态 A/B 只做精确 `ref_len`
  mask，不复用 H 的 phrase-center 移位。
- `O/D` 当前 DiT 是非因果全局 attention 且 `attn_mask_enabled=False`；B-only 只代表注入位置，必须
  用 full/no-P `spill_ratio` 证明 A 区影响可接受。
- `D` performance 在训练语义上应为第四正式条件，但四条件完全独立 CFG 存在交互和推理成本，先采用
  `v0/vbase/vfull` 三前向层级方案。
- `H` 最终是否优于仅显式曲线、是否需要 target latent residual、最佳码率和 CFG 范围都只能由受控实验
  裁决。
