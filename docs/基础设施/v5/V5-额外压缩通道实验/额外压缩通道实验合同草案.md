# 额外压缩通道实验合同草案

## 目标

在现有 `A + TEXT + MIDI` 之外增加第四类正式条件 `performance`，向 B 区提供 MIDI/TEXT 没有表达的
局部唱法信息，例如平直、升高、压低、起音、力度、颤音和拖尾。

本实验首先验证以下假设：目标或参考演唱经过极窄条件瓶颈后，仍能保留有用表现信息，但不再向 DiT
暴露足以直接复制完整目标的声学带宽；推理时可用 CFG 连续控制模型对该条件的服从程度。

建立本文档只冻结实验语义，不授权实现、上传数据或启动训练。

## 区域语义

- A 区保持当前参考条件职责，不承载本实验新增的对齐表现序列。
- `performance` 只在 B 区注入，并与 B 区时间轴严格对齐。
- SVC 结果放在 B 区 performance 输入侧，不放入 A 区。
- 目标 latent 是训练阶段的 Oracle 输入候选；推理阶段使用同内容、同时间轴的非花丸参考或其
  SVC-to-Hanamaru 结果。
- 不同歌曲、歌词或无法建立 B 区时间对应的参考不能直接作为逐位置 performance 输入，只能退化为
  统计风格或另行训练的无参考先验。

## 核心数据流

第一版冻结为条件自编码器加主 DiT，不新增第二个扩散解码器：

```text
训练：
target_B_latent [T, 64] + MIDI_B [T, 64]
        -> performance encoder E
        -> 极窄 code z [T_p, d_p]
        -> 降精度、噪声或量化（按组消融）
        -> 与 MIDI_B 重新合并
        -> 确定性 decoder D
        -> performance_hint_B [T, 64]
        -> 独立 zero-init performance_proj
        -> DiT

推理：
raw/SVC reference_B_latent + MIDI_B
        -> 同一个 E / bottleneck / D
        -> performance_hint_B
        -> DiT
```

MIDI 在 encoder 和 decoder 两侧都出现。encoder 用 MIDI 帮助识别“目标相对乐谱的表现残差”；decoder
重新获得 MIDI 后，不要求低维 code 重复携带绝对音高和音符结构。

`performance_hint_B` 是有损条件，不是新的 Flow target。主声学目标仍是目标花丸 latent。

## 瓶颈容量

“压到 8 维”不足以完整描述容量。每组必须同时记录：

```text
通道维数 d_p
时间率 T_p / second
连续值精度
是否加噪
量化方式与码本大小
名义 bit/s
```

首轮容量阶梯候选：

| 组 | code | 时间率 | 目的 |
|---|---|---|---|
| `C8-FullRate` | 8D continuous | 21.533 Hz | 复现最直接的原始设想 |
| `C4-LowRate` | 4D continuous | 约 5.38 Hz | 同时收窄通道和时间带宽 |
| `C2-LowRate` | 2D continuous | 约 5.38 Hz | 检验继续收窄的控制/质量拐点 |
| `Q-LowRate` | 低比特 VQ/标量量化 | 约 5.38 Hz | 给信息量建立明确上界 |
| `Phone-Code` | 每音素一个 code | 音素率 | 检验音素级表现轨迹 |

维度越低不保证泛化单调变强。连续逐帧 2D/4D 仍可能通过时间序列携带内容；时间率、精度、噪声和
量化必须与维度一起消融。停止点由表现控制力、基础质量和泄漏探针共同裁决。

## 解码器合同

第一阶段使用小型确定性双向 Conv 或 Transformer decoder。主 DiT 已负责从不完整条件生成多模态声学
细节，因此 performance decoder 不需要再执行一套扩散采样。

允许将完整 64D target latent 重建 MSE 作为独立诊断或低权重辅助项，但不得把该重建 loss 作为路线
晋级依据，也不得让它压过主 Flow loss。需要并行比较：

```text
lambda_codec = 0
lambda_codec = small
```

若确定性 decoder 在相同 code 下只产生明显平均化提示，且主 DiT 无法恢复可听表现差异，才讨论第二阶段
的生成式 decoder。扩散或 Flow Matching 更优先用于无参考表现先验：

```text
p(performance | MIDI, TEXT, A)
```

## 第四正式条件

`performance` 与现有 audio、TEXT、MIDI 在训练语义上平等，最低要求是：

1. 独立 null 表示；
2. 独立 dropout/mask；
3. 独立 leave-one-out 前向；
4. 独立推理 scale；
5. 固定的 full/no-performance 评估。

“平等”不要求四个条件使用相同 dropout 概率或相同数值 scale。各条件信息量和速度场差分范数不同，
必须记录 `||v_full - v_without_i||` 后再校准。

现有 `drop_audio_cond` 会清空整个 audio cond，不能用于只关闭 B-performance。实现必须新增
`drop_performance` 或等价的 B 区 mask，保持 A、TEXT、MIDI 不变。

## 训练 mask

当前 V5-P 训练独立采样 `drop_audio/drop_text/drop_midi`，且一个布尔值作用于当前 rank 的整个
microbatch。直接增加第四个 Bernoulli 会让关键组合，尤其 drop-all，出现过少。

第一轮使用命名 mask 调度器，显式覆盖：

```text
full
drop performance only
drop all
drop A only
drop TEXT only
drop MIDI only
legacy-style random combinations
```

起始比例只作为待标定候选：

| mask | 比例 |
|---|---:|
| full | 30% |
| drop performance only | 25% |
| drop all | 10% |
| drop A only | 5% |
| drop TEXT only | 5% |
| drop MIDI only | 5% |
| legacy random | 20% |

训练日志必须累计每种 mask 的 batch、样本和音频秒数。评估固定报告
`full / no-P / drop-all / drop-A / drop-TEXT / drop-MIDI`，不能继续用单一随机混合 loss 裁决。

`performance-only` 不进入常规训练比例，只作为泄漏诊断；否则会直接奖励瓶颈独自携带歌词、旋律和
音色答案。

## CFG 合同

沿用项目当前偏移式参数语义：

```text
g = -1  -> 忽略该条件
g =  0  -> 直接使用，不强化
g >  0  -> 强化该条件
```

定义：

```text
v0    = A、TEXT、MIDI、performance 全部丢弃
vbase = A + TEXT + MIDI
vfull = A + TEXT + MIDI + performance
```

第一版采用三前向层级 CFG：

```text
vP = vbase + (1 + gP) * (vfull - vbase)
v  = vP + gGlobal * (vP - v0)
```

因此在相同 `gGlobal` 下：

```text
gP = -1   -> 精确退回不含新通道的当前条件路径
gP =  0   -> 正常使用 performance
gP = -0.7 -> 使用约 30% 的 performance 差分
gP > 0    -> 强化 performance
```

首轮固定 sweep：

```text
-1.0, -0.85, -0.7, -0.5, -0.25, 0.0, +0.5
```

训练地位上的四条件平等不等于第一轮必须承担精确四旋钮推理。audio、TEXT、MIDI、performance 若都要
完全独立 scale，精确覆盖条件交互最多需要 `2^4=16` 个子集前向；简单相加 leave-one-out 差分只是一阶
近似。第一轮先验证三前向方案，只有听感或指标证明需要四个完全独立旋钮时再扩展。

## Loss 与对照

新增通道实验不得同时修改 CKA、FlowA:FlowB、数据池、VAE、起始 checkpoint、学习率、训练步数和
采样器。Base 与实验组必须共享同一套既有配方，避免把通道收益与其他超参变化混在一起。

候选总损失写为：

```text
L = L_existing
  + lambda_codec * L_codec
  + lambda_rate * L_rate
```

其中 `L_existing` 原样继承所选 Base；`L_codec` 只训练有损提示；`L_rate` 表示 VQ commitment、KL、
噪声鲁棒或明确码率约束。三项权重在正式训练前单独冻结。

若未来要验证 `NoCKA + FlowA:FlowB=1:3`，应另建配方对照，不能与本实验首轮同时改变。

## 训练阶段

### Oracle 阶段

以目标 B latent 进入 encoder，回答“极窄目标条件是否仍能控制表现”这一上限问题。Oracle 成功不等于
推理路径已成立。

### SVC 阶段

以同内容、同时间轴的 SVC B latent 进入同一个 encoder，目标仍是花丸真实 B latent。至少比较：

```text
target Oracle
raw reference
SVC-to-Hanamaru reference
no performance
```

如果训练只看目标 latent、推理只看 SVC latent，则必须把它标记为域迁移实验，不能由低维本身推断会
自动泛化。可增加 target/SVC code consistency，但不能用强 L2 抹掉 SVC 确实改变的表现信息。

### 自动控制阶段

只有参考和 SVC 路径通过后，才训练 `MIDI + TEXT + A -> performance` 的先验，或开放人工控制序列。

## 最小消融

| 组 | performance 输入 | bottleneck | CFG | 目的 |
|---|---|---|---|---|
| Base | 无 | 无 | 现有 | 严格基线 |
| Oracle-C8 | target B | C8-FullRate | `gP` sweep | 验证原始设想上限 |
| Oracle-C4 | target B | C4-LowRate | 同上 | 验证明显收窄 |
| Oracle-C2 | target B | C2-LowRate | 同上 | 寻找过窄拐点 |
| Oracle-Q | target B | Q-LowRate | 同上 | 验证明确信息上界 |
| SVC-Best | SVC B | Oracle 最佳结构 | 同上 | 验证可部署路径 |

所有组保持 decoder、投影、Base checkpoint、数据、seed、训练步数和评估集一致。

## 门禁

### 基线回归

- step 0 的 `performance_proj` 零初始化；
- `gP=-1` 或 no-P 路径必须与 Base 在相同 `x_t/t/seed` 下近似一致；
- A 区、MIDI 和 TEXT 的现有能力不得因新增 null/mask 语义被改写。

### 通道有效性

- 同一 MIDI/TEXT 下交换平淡、激昂、上滑和拖尾参考，输出对应指标应随参考变化；
- `gP` 从 `-1` 到 `0` 应产生连续、方向一致的变化；
- shuffle performance 应降低参考匹配度，而不是基本无变化。

### 泄漏

- no-P、shuffle、错歌词、错歌手和 performance-only probe；
- 从 code 训练歌词/音素与 singer 分类器；
- 检查源歌词插入、源音色污染和异常目标重建；
- 比较继续降维是否真的降低泄漏，而不是只损害表现控制。

### 基础质量

- MIDI/歌词服从度；
- 花丸音色；
- F0 残差、能量、颤音、起音和拖尾；
- 噪声、雾感和高频伪影；
- Short/Long 分层配对听评。

## 停止条件

满足任一项时停止扩大本路线：

1. `gP=-1` 无法恢复 Base；
2. Oracle 有效但 SVC 路径无法迁移；
3. code 泄漏歌词或歌手信息，且降帧率/量化后仍不能消除；
4. 继续从 8D 压到 4D/2D 只降低表现控制，不改善泄漏或基础质量；
5. performance 变化只能通过破坏 MIDI、歌词或花丸音色获得；
6. 确定性 decoder 与主 DiT 已能完成任务，不再为第二个扩散 decoder 增加复杂度。
