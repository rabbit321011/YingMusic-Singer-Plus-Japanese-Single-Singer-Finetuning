# V4Pf 与 V4vf 协作

本目录用于 V4Pf 与 V4vf 两个并行 agent 的异步通信、文件所有权声明和服务器资源协调。

## 核心原则

- 双方只写自己的状态文件，只读对方状态文件。
- 独占目录和独立新增文件无需等待；公共文件、公共模块和服务器资源必须先申请并收到 ACK。
- 消息、确认和资源释放都落盘，不依赖聊天上下文或口头记忆。
- 实验事实与最终结论仍写回各自分支工人文件；本目录不替代实验文档。

## 工人

| 文件 | 写入者 | 内容 |
|---|---|---|
| `通信与资源规范.md` | 规范维护者；修改前双方确认 | 消息、文件、GPU、tmux session` | 仅 V4Pf agent | V4Pf 消息、资源声明、公共修改申请与 ACK |
| `V4vf状态.md` | 仅 V4vf agent | V4vf 消息、资源声明、公共修改申请与 ACK |

## 阅读顺序

首次接入先读 `通信与资源规范.md`，再读双方状态文件。每次修改公共资源或启动服务器任务前，重新读取双方状态文件。
