## 一、V4 问题全景

### 1.1 项目背景

- **项目**：YingMusic-Singer-Plus 453M F5-TTS DiT 22层 日语 SFT 微调
- **目标**：在官方 CN/EN 权重基础上实现花丸晴琉音色的日文改词翻唱
- **数据**：15122 条花丸晴琉日语翻唱干声 约 90.7h，Whisper large-v3 自动标注
- **硬件**：4x RTX 4090 24GB DDP 训练
- **架构**：
  - VAE：Stable Audio 2 (156.1M) 冻结
  - Melody Extractor：SOME (117.6M) 冻结
  - DiT CFM：F5-TTS (453.6M) 可训练
- **Tokenizer**：CNENTokenizer IPA 音素 363 phonemes + PAD/PUNCT/SEP = 366 tokens
- **日语 token**：28 个 (ID 319-346)，27/28 在 V4 前从未训练

### 1.2 训练历程

| 版本 | 问题 | 结果 |
|------|------|:----:|
| V1 | cond=full_latent=GT 作弊 | 自重建完美，改词翻唱完全失败 |
| V2 | G2P 日文路由错误 | 第 50 步崩溃 |
| V3 | 修复 cond 但 x_t 每帧泄漏 | 训练正常，推理全噪声 |
| V4 | A/B 区分割，FlowB 硬地板 0.90 | PER=0.387，30+字崩塌 |
| V4b | L1+L2+L3 19k 步 | 糊但能听歌词 |
| V4c | L1+L2 30k 步 | 22k 歌词最佳，电音感，回退为主力 |
| GRPO v2-v3 | G=8, 4-reward, 4800 步 | PER 仅 +4.4%，1200 步后回落 |
| V5a1 | 课程训练 24K 步 | 无咬字提升，回退 V4c |

### 1.3 关键现象

- 咬字：第 1-2 句准，第 3 句开始崩塌
- 旋律：第 1 句崩，第 2-3 句准
- 30+字长文本 PER 断崖式下跌至 0.141
- 整体 PER=0.387，官方约 0.08
- SVC 微调也有越训越差现象，但可用小 LR 缓解
- SVS 必须训出日语能力，等训出来时唱功旋律已崩
- 超参调度无效（已尝试）

### 1.4 分层评估

120首，SFT 24K：

| 长度 | PER | 稳定性 | 分析 |
|:---:|:---:|:---:|:---|
| 1-10字 | 0.416 | 76.7% | 短歌尚可 |
| 11-20字 | 0.429 | 56.7% | 中等长度 |
| 21-30字 | 0.562 | 80.0% | 最优区 |
| 30+字 | 0.141 | 96.7% | 断崖式崩塌 |
| Total | 0.387 | — | — |

### 1.5 A/B 分割设计

- **A区（参考区）**前 ref_len 帧：cond=GT, midi=0，提供音色参考
- **B区（生成区）**剩余帧：cond=0, midi=GT，纯靠 text+midi 生成
- FlowB 硬地板 = 0.90，V1 cheating = 0.45
- 典型样本：中位数 23.2 秒、5 句，ref_len 只覆盖第 1 句 2-3 秒，后面 20 秒全 B 区

### 1.6 数据分档

| 分档 | 条件 | 条数 | 占比 | 处理方式 |
|------|------|-----:|:---:|:--------|
| L1 | sim>=0.9, 短语<=10 | ~7,700 | 51% | 直接训练 |
| L2 | sim>=0.7 | ~3,900 | 26% | drop 训练 |
| L3 | sim>=0.5 | ~1,000 | 6.4% | 低权重辅助 |
| L4 | sim<0.5 | ~2,200 | 15% | 丢弃 |

## 二、根因详解

### 2.1 A/B 分割 B 区误差累积

A 区前 2-3 秒有 cond 音色参考，B 区后面 20 秒 cond=0，全靠 text+midi。text 信号弱时模型越来越依赖 midi，咬字逐帧漂移。

完美解释岛岛的观察：咬字 1-2 句准 → 3 句崩，旋律 1 句崩 → 2-3 句准。

**对比官方 YingMusic**：官方使用 VAE latent 帧级 random masking 70-100%，在任何位置都可能遇到 cond=0 或非 0，不存在固定的 A/B 模式切换。官方还有 melody temporal dropout=0.1 防止旋律语义泄漏。

### 2.2 日语 Text Embedding 弱

CNENTokenizer 体系：PAD=0, 音素 1-363, PUNCT=364, SEP=365。日语仅 28 个槽位 ID 319-346。

通过 AdamW optimizer state 交叉验证确认：
- Row 0-318：CN/EN/PAD 已训练
- Row 319-346：JA 音素未训练，边界行 319 有微弱动量

**三层独立性**：
- G2P（文本→音素）：✅ 已改用 pyopenjtalk 支持日文
- Tokenizer（音素→ID）：❌ 未改官方原版
- Embedding（ID→向量）：❌ 未改官方原版，27/28 未训练

### 2.3 数据质量问题

- 花丸翻唱带效果器，MSST 分离后有残留
- Whisper 时间戳 P95 误差 = 6.62 秒
- L1 高质量数据仅占 51%

### 2.4 SFT 趋向均值与动情特征

MSE loss 本质是条件期望，输出最平均的 latent。SFT 把各种唱法全平均掉，训练越久方差越小表达越平。

**岛岛理论**：动情特征不是平均的而是抽查的——"如果是她，她会怎么做"。

### 2.5 VAE 日语编码局限

Stable Audio 2 VAE (156.1M)：
- 44.1kHz 立体声，2048 倍下采样，latent dim=64，帧率 21.5Hz
- 训练数据 AudioSparx 几乎不含日语
- 21.5Hz = 46.5ms/帧，日语短辅音 VOT 仅 20-50ms 在临界点
- 日语专用 VAE：Aratako Semantic-DACVAE-Japanese，UTMOSv2 超原版

## 三、V5 核心方案

### 3.1 数据构成

| 数据源 | 时长 | 类型 | 获取方式 |
|--------|------|------|---------|
| Emilia 日语 | ~1,715h | 干净朗读 | HuggingFace: amphion/Emilia-Dataset（gated，需申请） |
| Emilia-YODAS 日语 | ~1,100h | 干净朗读 | 同上 |
| Galgame | ~10,588h | 游戏语音（干净朗读） | HuggingFace: OOPPEENN/Galgame_Dataset（公开，~479GB） |
| 花丸晴琉 | ~90h | 翻唱干声 | 已有 |

**合计约 13,400h 朗读 + 90h 歌声**

### 3.2 训练策略

- **混合比例**：70% 朗读 + 30% 唱歌
- **朗读样本**：TTS 模式（midi=0，无 CKA loss，只用 L_MSE）
- **唱歌样本**：SVS 模式（midi 开，CKA loss 开），沿用 V4 流程
- **同 batch 内混合**，sentence-level alignment 统一
- **数据加载**：WeightedRandomSampler 按比例采样
- **学习率**：1e-5 起步（微调场景）
- **Batch 模式**：frame 模式按总帧数动态组 batch
- **训练步数**：控制在 500k-700k 以内，避免静音退化
- **精度**：fp16 比 bf16 稳定

### 3.3 为什么比 V4 好

1. 发音基础从 13,400h 干净数据建立，不是 90h 歌声硬啃
2. 70/30 确保发音是主任务、唱歌是辅助，不会为学发音牺牲唱歌
3. 朗读数据天然干净，无效果器无伴奏残留，text→latent 映射更准
4. 一阶段训练，避免 TTS pretrain → SVS finetune 的分布偏移
5. 混合训练本身就是社区公认的最佳防灾难性遗忘策略

### 3.4 UniVoice null melody token（可选优化）

TTS 模式下用可学习的 null token 代替 midi=0。null token 只被 TTS loss 更新，收敛到最优无旋律表示。DiT 不需要切换模式，看到 null token 就知道是朗读。

参考：UniVoice, arXiv:2606.05852

## 四、配套技术方案

### 4.1 SPFM 数据自净化

**来源**：Kim et al., "Self-Purifying Flow Matching", arXiv:2509.19091, Supertone Inc.
**代码**：https://github.com/supertone-inc/self-purifying-flow-matching

**核心逻辑**：每个样本在固定 t=0.5 算两个 loss——L_cond 和 L_uncond。如果 L_cond > L_uncond，说明条件标签有问题，该样本只做无条件训练，忽略 text label。前 40k 步 warmup 不使用 SPFM，防止早期不稳定误判。

**关键参数**：t=0.5 (F1=0.847 最优)，warmup=40k steps，unconditional dropout=0.1

**效果**：TTS WER 从 6.68% 降到 5.96%（↓10.8%）

**在 V5 中的作用**：自动识别并跳过花丸数据中的脏样本，保证 30% 唱歌数据有效

**工程量**：几行代码，在现有训练 loop 中加判断逻辑

### 4.2 Wet 仿真数据增强

**来源**：Zheng et al., "R2-SVC", arXiv:2510.20677, ICASSP 2026

**具体参数**：
- 混响：mixing ratio=0.5, p=0.4
- 回声：0.35, p=0.4
- 和声：0.4, p=0.3
- 三个效果独立触发
- F0 随机抖动 p=0.15，滑音 p=0.15，跳跃 p=0.2

**训练方式**：模型输入=加噪版本，目标输出=干净版本

**在 V5 中的作用**：消除 Emilia/Galgame 干声与花丸湿声之间的 gap，让模型学会不管干湿都能发音

### 4.3 VAE 解码器微调

**思路**：冻结 SAO VAE 的 encoder 和 bottleneck，只微调 decoder

**关键优势**：latent space 完全不变，DiT 不需要重新训练，即插即用

**社区验证**：lyraaaa/sao_vae_tuned_100k (HuggingFace) 已验证此路线

**方法**：stable-audio-tools 自带 `decoder_finetune=True` 参数，但未暴露在 factory.py 中，需自己写 Python 调用 AutoencoderTrainingWrapper

**数据**：日语语音/歌声，44.1kHz 立体声，10-30 秒片段。可用 Emilia、Galgame、花丸干声、tts-dataset/japanese-singing-voice (vocal-only 版 200GB)

**训练量**：50k-100k 步，1-2x RTX 4090 可跑，LR 1.5e-4

**损失函数**：默认 MR-STFT + adversarial + feature matching 即可

**其他 VAE 备选**：
- **STAR-VAE** (ICML 2026)：同帧率同维度，语义保留改善 30-64%，代码权重尚未开源，预计 7 月 9 日后可能发布。如果 latent dim=64 可作为 drop-in 替换。
- **εar-VAE**：43Hz latent rate (SAO 两倍)，信号级指标优于 SAO，语义保留不如 STAR-VAE。
- **Semantic-DACVAE-Japanese**：日语专用 VAE，UTMOSv2 超原版，已被 Irodori-TTS-500M-v2 采用，latent 维度不同，替换需改 DiT 输入层。

## 五、参考项目

### YingMusic-Singer-Plus（官方）

- 论文：arXiv:2603.24589
- 代码：https://github.com/ASLP-lab/YingMusic-Singer-Plus
- 当前 V4/V5 基础框架，仅 CN/EN，无日语支持，训练脚本未开源
- 训练流程：TTS Pretrain → SFT Phase1（无旋律）→ SFT Phase2（有旋律+CKA）→ GRPO
- 已内置 TTS 模式：melody_input_source=none
- 推理使用简化两路 CFG：v_cond vs v_drop_all

### UniVoice

- 论文：arXiv:2606.05852 (2026)
- 统一语音+歌声生成，65k 小时
- 因子化条件分解（内容/旋律/音色/任务）+ null melody token
- 24 层 DiT，dim=1024，0.3B 参数
- V5 训练策略核心参考

### F5-TTS 日语社区模型

- HuggingFace：Jmica/F5TTS (JA_21999120)
- 7.1k 小时日语训练（Emilia 1.7k + Galgame 5.4k），架构与 YingMusic DiT 完全一致
- **Tokenizer 不兼容**：char-level (2976 假名) vs YingMusic IPA (366 音素)
- 不能直接迁移，但 TTS 蒸馏路线曾作为备选

### DiffSinger (OpenVPI)

- 代码：https://github.com/openvpi/DiffSinger
- 两阶段架构，日语支持成熟
- 数据需求 30-60 分钟，硬件 6GB VRAM 起
- **V5 备选方案**

### opencpop-cjke-multidict

- 代码：https://github.com/lottev1991/opencpop-cjke-multidict
- 四语言 DiffSinger 模型，日语用 NNSVS-style 音素 + PJS Corpus

### CrossSinger

- 论文：arXiv:2309.12672, ASRU 2023
- IPA 统一 + CLN + GRL 梯度反转层
- GRL 消除"歌手-语言"隐式绑定，防止日语带中文口音

### R2-SVC

- 论文：arXiv:2510.20677, ICASSP 2026
- Wet 仿真数据增强来源

### SPFM

- 论文：arXiv:2509.19091, Supertone
- 数据自净化核心方案

### DeltaFM（对比流匹配）

- 论文：arXiv:2506.05350
- 解决 SFT 趋向均值问题，与"动情特征"直觉一致
- 训练速度提升 9 倍，FID 降低 8.9 分
- 尚未在 SVS 领域验证，中长期方向

### STAR-VAE

- 论文：arXiv:2606.23064, ICML 2026
- 同帧率同维度，语义保留改善 30-64%
- 代码权重未公开，预计 7 月 9 日后可能发布

### Semantic-DACVAE-Japanese

- HuggingFace：Aratako/Semantic-DACVAE-Japanese
- 日语专用 VAE，UTMOSv2 超原版

### εar-VAE

- 43Hz latent rate（SAO 两倍）
- 信号级指标优于 SAO，语义保留不如 STAR-VAE

## 七、F5-TTS 社区经验

> 来自数百条 GitHub Issue 的总结

### 7.1 数据质量铁律

- 20 分钟干净录音优于 2 小时嘈杂录音
- 24kHz 必须，16kHz 会产生高频伪影
- 必须复制预训练权重，否则从零训练

### 7.2 灾难性遗忘

- 微调新语言后丢失原语言能力是最高频问题
- **解决方案**：混合原语言数据，社区建议 20-50% 原语言
- V5 的 70/30 混合训练正是这个策略

### 7.3 常见失败模式

- 750k-800k 步后输出全静音——疑似 bf16 精度损失，fp16 更稳定
- FlashAttention 在 150k 步后 loss 飙升
- 小数据集 epoch 过大导致学习率衰减到接近 0

### 7.4 反直觉经验

- 最佳 checkpoint 几乎永远不是最后一个
- loss 最低的模型往往听觉质量已经退化
- 需要每 5 个 epoch 做人耳评估，不能只看 loss

### 7.5 日语微调特别注意事项

- 所有汉字必须转平假名，用 pyopenjtalk
- JA_21999120 checkpoint 必须先 prune，只保留 ema_model_state_dict
- 必须用 `--tokenizer custom --tokenizer_path` 指定日语 vocab

### 7.6 社区成功配置参考

| 硬件 | 数据量 | 训练量 | 耗时 |
|------|--------|--------|:----:|
| RTX 3090 | 60-80h | 10 epoch | ~1-3 天 |
| RTX 4090 | 106h | 153 epoch, 195k 步 | ~3 天 |

- 学习率 1e-5 起步，batch 用 frame 模式

### 7.7 Sentence-Level Alignment 机制

- 文本字符序列用 filler token 填充到 mel 帧等长
- ConvNeXt 中 filler token 被 mask 掉，模型只从有效字符推断时序
- 短文本大量 filler 作为位置锚点，长文本 filler 少导致对齐退化
- **这直接解释了 V4 的 30+ 字崩塌**：有效字符占比高，位置信息不足
- 可能缓解方案：人为拉长音频增加 filler 比例，或分段处理

## 八、YingMusic 代码库关键发现

### 8.1 仓库结构

- 代码：https://github.com/ASLP-lab/YingMusic-Singer-Plus
- 训练脚本不在 main 分支，仅推理代码
- VAE 从本地 checkpoint 加载：`stable_audio_2_0_vae_20hz_official.ckpt`
- CNENTokenizer：`vocab.json` 363 IPA 音素，encode 方法加 +1 偏移

### 8.2 DiT 输入构造

- x(64) + cond(64) + text_embed(512) + midi(128) = 768 → 投影到 1024
- TextEmbedding：373 token → 512 dim，4 层 ConvNeXtV2
- text_mask_padding=False，所有位置参与计算
- 支持 drop_audio_cond 和 drop_midi 实现 CFG 训练

### 8.3 CFG 推理

- 简化两路 CFG：`v_cfg = v_cond + (v_cond - v_drop_all) × guidance_scale`
- 默认 32 步 ODE，cfg_strength=3.0，t_shift=0.5
- 已内置 TTS 模式：melody_input_source=none，midi=zeros

### 8.4 旋律处理

- Melody Extractor 基于 SOME，输出 128 维 MIDI 概率 + bound
- 参考区 midi 置零，生成区 midi 正常
- CKA loss 仅在 B 区计算（A 区 midi=0 无意义）

### 8.5 V5 训练脚本改造要点

- 数据加载器支持混合数据源，WeightedRandomSampler 70/30 采样
- 朗读样本：midi=0，无 CKA loss
- 唱歌样本：保持 V4 逻辑
- **可选**：UniVoice null melody token 替代 midi=0
- **可选**：SPFM 在训练 loop 中加条件/无条件 loss 对比
- **可选**：Wet 增强在数据预处理阶段加效果器

## 九、实施路线图

### 9.1 第一步：数据准备

1. 下载 Emilia 日语子集（HuggingFace: amphion/Emilia-Dataset，需申请权限）
2. 下载 Galgame 数据集（HuggingFace: OOPPEENN/Galgame_Dataset，公开 ~479GB）
3. 文本预处理：pyopenjtalk 汉字→假名→IPA 音素→CNENTokenizer
4. 花丸数据沿用 V4 流程
5. 音频预处理：VAE encode 到 latent

### 9.2 第二步：训练脚本改造

在 V4 脚本基础上：
- 数据加载器支持混合数据源 70/30 采样
- 朗读样本：midi=0，无 CKA，只用 L_MSE
- 唱歌样本：保持 V4 逻辑
- 可选加入：SPFM 条件/无条件 loss 对比、Wet 仿真增强、UniVoice null token

### 9.3 第三步：VAE 解码器微调（可并行）

- 用 stable-audio-tools 的 `decoder_finetune=True`
- 在日语数据上微调 50k-100k 步
- 冻结 encoder+bottleneck，latent space 不变，DiT 不需要重新训练

### 9.4 第四步：训练与评估

- LR 1e-5 起步，frame 模式 batch，fp16 精度
- 控制总步数 500k-700k
- 每 5 epoch 人耳评估，最佳 checkpoint 通常不是最后一个
- 监控指标：PER、F0-CORR、Flow Loss

### 9.5 第五步：备选路线

- 如果 V5 效果不如预期 → 花丸数据迁移到 DiffSinger
- 如果 STAR-VAE 开源 → drop-in 替换 SAO VAE
- 如果发音仍有口音 → 引入 CrossSinger GRL 梯度反转层
- 如果表达力不够 → 引入 DeltaFM 对比流匹配
