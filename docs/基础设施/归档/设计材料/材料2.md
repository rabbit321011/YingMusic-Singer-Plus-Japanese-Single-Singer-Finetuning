## 一、核心问题诊断

### 1.1 V4 失败现象

- 咬字：第1-2句准 → 第3句开始崩塌
- 旋律：第1句崩 → 第2-3句准
- 30+字长文本 PER 断崖式下跌至 0.141（120首分层评估中该bucket稳定性96.7%但PER最低）
- 整体 PER=0.387（官方 YingMusic ~0.08）
- GRPO 仅 +4.4%（800步峰值），1200步后回落
- V5a1 课程训练无改善
- SVC 微调也有"越训越差"现象，但可用小 LR 缓解；SVS 必须训出日语能力，等训出来时唱功旋律已崩
- 超参调度无效（已尝试）

### 1.2 根因分析（按可能性排序）

**① A/B 分割导致 B 区误差累积**
- A区（前 ref_len=12.5%-33% T）：cond=GT, midi=0
- B区（剩余帧）：cond=0, midi=GT
- 中位数样本 23.2 秒、5 句，ref_len 只覆盖第 1 句（2-3秒），后面 20 秒全 B 区
- B区 cond=0 持续 20 秒，text 信号弱时模型偏向 midi，咬字逐帧漂移
- 完美解释岛岛的观察：咬字 1-2 句准（A区+刚进B区）→ 3句崩（B区深处），旋律 1 句崩（A区 midi=0）→ 2-3 句准（B区 midi=GT）

**② 日语 Text Embedding 弱**
- CNENTokenizer 共 366 token，日语仅占 28 个槽位（ID 319-346）
- 27/28 在 V4 之前从未训练（通过 optimizer state 交叉验证确认）
- G2P 已改（pyopenjtalk），Tokenizer 未改（官方原版），Embedding 未改（官方原版）

**③ 数据质量问题**
- 花丸翻唱带效果器（混响、delay），MSST 分离后残留
- MSST 分离不净（和声、伴奏漏音）
- Whisper 时间戳 P95 误差 = 6.62 秒
- L1 高质量数据仅占 51%

**④ SFT 趋向均值（岛岛提出的"动情特征"假说）**
- MSE loss 本质是条件期望 → 输出"最平均"的发音
- 训练越久，方差越小，表达越平
- "动情特征不是平均的，而是抽查的，而 SFT 非常容易训出平均值"
- "如果是她，她会怎么做"

**⑤ Stable Audio 2 VAE 对日语编码可能有损失**
- VAE 训练数据 AudioSparx 几乎不含日语
- 21.5Hz 帧率（46.5ms/帧），日语短辅音 VOT（20-50ms）在临界点
- 论文自认 "speech generations are not intelligible"
- 详见第七部分

## 二、V5 核心方案：多数据源混合训练

### 2.1 数据构成

| 数据源 | 时长 | 类型 | 用途 | 获取方式 |
|--------|------|------|------|---------|
| Emilia 日语 | ~1,715h | 干净朗读 | 建立日语发音先验 | HuggingFace: amphion/Emilia-Dataset（需申请权限，gated） |
| Emilia-YODAS 日语 | ~1,100h | 干净朗读 | 补充发音多样性 | 同上 |
| Galgame | ~10,588h | 游戏语音（干净朗读） | 大规模发音训练 | HuggingFace: OOPPEENN/Galgame_Dataset（公开，~479GB） |
| 花丸晴琉 | ~90h | 翻唱干声 | 唱歌能力 + 花丸音色 | 已有 |

**合计约 13,400h 日语朗读数据 + 90h 花丸歌声**

### 2.2 训练策略

- 混合比例：70% 朗读 + 30% 唱歌
- 朗读样本：TTS 模式（midi=0，无 CKA loss，只用 L_MSE）
- 唱歌样本：SVS 模式（midi 开，CKA loss 开），沿用 V4 流程
- 同一 batch 内混合，sentence-level alignment 统一
- 数据加载：WeightedRandomSampler（PyTorch 原生，按比例采样）
- 学习率：1e-5 起步（微调场景，不要用 7.5e-5）
- Batch：frame 模式（按总帧数动态组 batch）
- 训练步数：控制在 500k-700k 以内（避免静音退化）
- 精度：fp16 比 bf16 稳定

### 2.3 预期优势（vs V4）

- 发音基础从 13,400h 干净数据建立，不再是 90h 歌声硬啃
- 70/30 比例确保发音是主任务、唱歌是辅助——不会为学发音而牺牲唱歌
- 朗读数据天然干净（无效果器、无伴奏残留），text→latent 映射更准
- 一阶段训练，避免 TTS pretrain → SVS finetune 的分布偏移
- 灾难性遗忘自然缓解（混合数据本身就是社区公认的最佳防遗忘策略）

## 三、V5 配套技术方案

### 3.1 SPFM 数据自净化

- **来源**：Kim et al., "Self-Purifying Flow Matching", arXiv:2509.19091, Supertone Inc.
- **代码**：https://github.com/supertone-inc/self-purifying-flow-matching
- **核心逻辑**：训练时每个样本在 t=0.5 计算 L_cond 和 L_uncond，若 L_cond > L_uncond → 标记为可疑样本 → 该样本只做无条件训练（忽略可能有问题的 text label）
- **效果**：TTS WER 从 6.68% → 5.96%（↓10.8%）
- **在 V5 中的作用**：自动识别并跳过花丸数据中的脏样本（时间戳不准、分离残留），保证花丸的 30% 是有效的 30%
- **工程量**：几行代码，需要 40k 步 warmup
- **关键参数**：t'=0.5, warmup=40k steps, unconditional dropout=0.1

### 3.2 Wet 仿真数据增强

- **来源**：Zheng et al., "R2-SVC", arXiv:2510.20677, ICASSP 2026
- **具体参数**：混响(mixing ratio=0.5, p=0.4)、回声(0.35, p=0.4)、和声(0.4, p=0.3)，三个效果独立触发；F0 随机抖动/滑音/跳跃
- **训练方式**：模型输入=加噪版本，目标输出=干净版本
- **在 V5 中的作用**：Emilia/Galgame 是干声，花丸有混响。Wet 增强在朗读数据上加效果器，让模型学会"不管干湿都能发音"，消除干湿 gap

### 3.3 UniVoice Null Melody Token

- **来源**：UniVoice, arXiv:2606.05852（2026）
- **思路**：TTS 模式下旋律输入不是粗暴设零，而是用一个可学习的 null token。该 token 只被 TTS loss 更新，收敛到最优的"无旋律"表示
- **优势**：比 midi=0 更优雅，null token 是学出来的而非人为假设的。DiT 不需要切换模式
- **改动**：midi 输入从"零向量"替换为可学习 parameter，TTS 样本用它、歌声样本用真实 midi
- **参考**：UniVoice 用此方法统一了 35k 小时歌声 + 30k 小时语音的训练

### 3.4 VAE 解码器微调

- **思路**：冻结 SAO VAE 的 encoder 和 bottleneck，只微调 decoder，改善日语语音重建质量
- **方法**：stable-audio-tools 自带 `decoder_finetune=True` 参数（但未暴露在 factory.py，需自己写几行 Python 调 AutoencoderTrainingWrapper）
- **关键优势**：冻结 encoder → latent space 完全不变 → DiT 不需要重新训练，即插即用
- **社区验证**：lyraaaa（HuggingFace: lyraaaa/sao_vae_tuned_100k）已验证此路线可行
- **数据**：日语语音/歌声，44.1kHz 立体声，10-30 秒片段。Emilia、Galgame、花丸干声、tts-dataset/japanese-singing-voice（vocal-only 版 200GB）都可用
- **训练量**：50k-100k 步，1-2× RTX 4090 可跑，LR 1.5e-4
- **损失函数**：默认 MR-STFT + adversarial + feature matching 即可，歌声可加 F0 RMSE 和 SingMOS
- **已知限制**：STAR-VAE（ICML 2026，同帧率同维度，语义保留改善 30-64%）尚未开源（预计 7 月 9 日 poster 后可能发布）

## 四、有价值的参考项目

### 4.1 YingMusic-Singer-Plus（官方）

- 论文：arXiv:2603.24589
- 代码：https://github.com/ASLP-lab/YingMusic-Singer-Plus
- 当前 V4/V5 的基础框架
- 只用 CN/EN，无日语支持
- 训练脚本未开源（main 分支只有推理代码）
- 关键发现：TTS Pretrain → SFT Phase1（无旋律）→ SFT Phase2（有旋律+CKA）→ GRPO
- 代码已内置 TTS 模式（melody_input_source="none"）
- 推理使用简化两路 CFG（cond vs drop_all）

### 4.2 UniVoice

- 论文：arXiv:2606.05852（2026）
- Demo：nips-unvoice.netlify.app
- 统一语音+歌声生成，65k 小时（35k 歌声+30k 语音）
- 因子化条件分解（内容/旋律/音色/任务）+ null melody token
- 24 层 DiT（dim=1024），0.3B 参数
- V5 训练策略的核心参考

### 4.3 F5-TTS 日语社区模型

- HuggingFace：Jmica/F5TTS（JA_21999120）
- 7.1k 小时日语（Emilia 1.7k + Galgame 5.4k）训练
- 架构与 YingMusic DiT 完全一致（dim=1024, depth=22, heads=16, text_dim=512, conv_layers=4）
- **Tokenizer 不兼容**：char-level（2976 假名）vs YingMusic 的 IPA 音素（366 token）
- 如果用，必须将所有汉字转为平假名。需 prune checkpoint（只保留 ema_model_state_dict）
- 不能直接迁移（tokenizer 差异），但 TTS 蒸馏路线曾作为备选讨论

### 4.4 DiffSinger (OpenVPI)

- 代码：https://github.com/openvpi/DiffSinger
- 两阶段架构（Variance Model + Acoustic Model + 浅扩散）
- **日语支持成熟**：内置日语词典、SOFA 对齐模型、完整工具链
- 数据需求低（30-60 分钟可训），硬件门槛低（6GB VRAM 起）
- 可控性高（逐音素编辑 duration/pitch）
- 社区活跃（OpenUTAU 集成、大量第三方工具）
- **V5 备选方案**：如果 YingMusic 路线走不通，花丸数据可迁移到 DiffSinger

### 4.5 opencpop-cjke-multidict

- 代码：https://github.com/lottev1991/opencpop-cjke-multidict
- 四语言（中/日/韩/英）DiffSinger 模型
- 日语使用 NNSVS-style 音素 + PJS Corpus 训练数据
- 个人实验性项目（2 stars），但证明了多语言 DiffSinger 可行性

### 4.6 CrossSinger

- 论文：arXiv:2309.12672（ASRU 2023）
- IPA 统一音素空间 + CLN 条件层归一化 + GRL 梯度反转层
- GRL 消除"歌手-语言"隐式绑定——防止日语发音带中文口音
- 非 DiT 架构（基于 Xiaoicesing2/FastSpeech2），但方法论可迁移

### 4.7 R2-SVC

- 论文：arXiv:2510.20677（ICASSP 2026）
- Wet 仿真数据增强的来源
- 三阶段训练（CPT + SFT + Flow-GRPO RL）
- 音色转换鲁棒性提升

### 4.8 SPFM（自净化流匹配）

- 论文：arXiv:2509.19091（Supertone, 2025）
- 代码：https://github.com/supertone-inc/self-purifying-flow-matching
- 数据自净化的核心方案

### 4.9 ΔFM（对比流匹配）

- 论文：arXiv:2506.05350
- 在 FM loss 上叠加对比正则化：强制不同条件的样本产生不同流轨迹
- 解决 SFT"趋向均值"问题（与岛岛"动情特征"直觉一致）
- 训练速度提升 9 倍，FID 降低 8.9 分
- 尚未在 SVS 领域验证，作为中长期方向

### 4.10 STAR-VAE

- 论文：arXiv:2606.23064（ICML 2026）
- 基于 SAO CNN backbone + Mamba + STAR 结构化 KL 正则化
- 同帧率（21.5Hz）、同采样率（44.1kHz）、可能同 latent dim（64）
- 语义保留（FAD）比 SAO VAE 改善 30-64%
- **代码和权重尚未公开**（预计 2026 年 7 月 9 日 ICML poster 后可能发布）
- 如果 latent dim=64，可作为 drop-in 替换

### 4.11 Semantic-DACVAE-Japanese

- HuggingFace：Aratako/Semantic-DACVAE-Japanese
- 专门针对日语语音微调的 VAE
- UTMOSv2 评分超过原始 DAC 模型
- 已被 Irodori-TTS-500M-v2 采用
- latent 维度与 SAO VAE 不同，替换需改 DiT 输入层

### 4.12 εar-VAE

- 43Hz latent rate（SAO 的两倍），44.1kHz 立体声
- 信号级指标优于 SAO，但语义保留（FAD）不如 STAR-VAE
- 替换需改 DiT 时序对齐
