## 一、TTS 领域全景调研 2025-2026

> 本部分来自 agent_reach 多平台搜索（GitHub/Twitter/arXiv/Reddit/YouTube/B站等10通道），搜索主题为"最近AI语音合成/TTS领域的新进展和新模型"。

### 1.1 2026 年新模型

#### 1. dots.tts（小红书/RedNote，2026年6月）

- **参数**：2B
- **架构**：全连续端到端自回归 TTS，无离散 token，AudioVAE + LLM + AR 流匹配声学头
- **亮点**：Seed-TTS-Eval 上中文 WER 0.94%、英文 WER 1.30%，SIM 相似度 81.0（中文）/77.1（英文）
- 24 语言 MiniMax 多语言基准上平均说话人相似度 83.9，全开源 SOTA
- 发布三个 checkpoint：base / SCA 自校正对齐版 / MeanFlow 蒸馏版（4步推理）
- **开源**：Apache-2.0，含训练代码和微调代码
- **来源**：GitHub rednote-hilab/dots.tts

#### 2. Raon-OpenTTS（KRAFTON，2026年4月）

- **参数**：0.3B / 1B
- **架构**：基于 F5-TTS 的 DiT 扩散 Transformer，流匹配
- **亮点**：首个同时开源权重和训练数据的大规模 TTS，训练数据 Raon-OpenTTS-Core 共 510K 小时全部公开
- 1B 版本在 Seed-TTS-Eval 上 WER 1.78%、SIM 0.749，与闭源数据训练的模型相当
- 完全可复现的研究基线
- **开源**：Apache-2.0
- **来源**：GitHub krafton-ai/Raon-OpenTTS

#### 3. OmniVoice（k2-fsa，2026年3月）

- **架构**：扩散语言模型风格
- 支持 600+ 语言，是语言覆盖最广的零样本 TTS 模型
- RTF 低至 0.025（40倍实时速度）
- 支持语音克隆和语音设计（性别、年龄、口音等可控）
- **开源**：Apache-2.0，GitHub 7.7K+ stars

#### 4. MOSS-TTS 系列（OpenMOSS/MOSI.AI，2026年4月）

- **参数范围**：100M ~ 8B
- 子模型：
  - MOSS-TTS-Nano ~100M：仅 4 核 CPU 可运行，支持 48kHz 立体声
  - MOSS-TTS-Local-Transformer ~1.7B
  - MOSS-TTSD ~8B：含延迟控制
  - MOSS-TTS-Realtime ~1.7B：实时 TTS
  - MOSS-VoiceGenerator
- **开源**：Apache-2.0

#### 5. GLM-TTS（智谱AI，2025年12月）

- **架构**：两阶段 Text-to-Token 自回归 + Token-to-Wave 扩散，类似 CosyVoice
- 仅用 100K 小时训练数据即达 SOTA，远少于 CosyVoice 3 的 100 万小时
- GRPO 多奖励强化学习：同时优化发音 CER、音色相似度 SIM、情感 Emotion、笑声 Laughter
- LoRA 微调仅需 1 小时单说话人音频、调整 15% 参数即达全模型性能
- 混合音素+文本输入，解决中文多音字难题
- **论文**：arXiv:2512.14291

#### 6. CosyVoice 3（阿里巴巴/通义，2025年5月）

- **参数**：1.5B
- **架构**：LLM + Chunk-Aware Flow Matching
- 训练数据从 1 万小时扩展到 100 万小时，覆盖 9 种语言和 18 种中文方言
- 提出 DiffRO 可微分奖励优化，适用于所有基于离散 token 的语音合成模型
- 发布 CV3-Eval 基准，涵盖真实场景下的零样本语音合成
- **论文**：arXiv:2505.17589

#### 7. VoxCPM2（OpenBMB，2026年4月更新）

- **参数**：2B VoxCPM2 / 0.6B VoxCPM1.5 / 0.5B VoxCPM-0.5B
- 支持 30 种语言、48kHz 音频、语音设计功能、可控语音克隆
- GitHub 30K+ stars，社区最活跃的 TTS 项目之一
- VoxCPM-0.5B 基于半离散瓶颈表示，WER 低至 1.85% 英文、0.93% 中文
- **开源**：Apache-2.0，可商用

#### 8. Qwen3-TTS（阿里云，2026年1月）

- **参数**：0.6B / 1.7B
- **架构**：离散多码本 LM 架构 + 自研 Qwen3-TTS-Tokenizer-12Hz
- 10 种主要语言 + 多种方言
- 端到端延迟低至 97ms，首个音频包在单字符输入后即刻输出
- 支持语音设计，自然语言描述即可控制音色情感语速
- 3 秒快速语音克隆
- 多码本 LM 架构完全绕过传统 LM+DiT 的信息瓶颈
- 在跨语言基准上大幅超越 CosyVoice 3
- GitHub 12.2K+ stars

## 二、DiffRO vs GRPO 完整技术对比

### 2.1 DiffRO（Differentiable Reward Optimization）

**论文**：Gao et al., "Differentiable Reward Optimization for LLM based TTS system", Interspeech 2025, pp.2450-2454, arXiv:2507.05911
**作者**：Changfeng Gao, Zhihao Du, Shiliang Zhang — 阿里通义千问团队

**核心思想**：将奖励计算从音频空间搬到 token 空间，使整个流程可微分。

**传统 RLHF 流程**：LM 预测 codec token → 解码合成音频 → vocoder → ASR/奖励模型 → 奖励分数 → PPO 更新（不可微）

**DiffRO 流程**：LM 预测 codec token → Gumbel-Softmax 采样 → Token2Text/ASR 可微分奖励 → 反向传播直接优化 LM（可微）

**三个核心技术**：
1. **Gumbel-Softmax 重参数化**：用 Gumbel-Softmax 替代 argmax 对预测 token 采样，使采样过程可微分
2. **Token2Text 奖励模型**：训练一个在 codec token 上运行的 ASR 模型，直接从 token 预测文本后验概率作为奖励
3. **多任务奖励模型 (MTR)**：包括 ASR 发音、SER 情感、SQA 质量、年龄性别预测等多个下游任务

**效果**：在 Seed-TTS-Eval 上达到 SOTA WER；MTR 实现零样本情感/质量属性控制。

**CosyVoice 3 中的 DiffRO**：采用 Token2Text 模型 + MTR（SER, MOS 预测, AED 等），WER 相对改善 20%-50%；低资源语言+跨语言场景 >50%。**明确限制**：不擅长歌声生成 (singing voice)，这是未来方向。

### 2.2 GRPO（Group Relative Policy Optimization）

**来源**：DeepSeek-Math (Guo et al., 2025)

**核心**：从同一 prompt 采样一组输出 (G=8)，用组内平均奖励作为 baseline 替代 value network，无需 critic。

**vs PPO**：显存节省 30-50%，训练速度提升约 2 倍，在 DeepSeekMath 论文中 7B 参数模型训练资源约为 PPO 的 50-60%。

### 2.3 Flow-GRPO

**论文**：Liu et al., NeurIPS 2025, arXiv:2505.05470

**核心**：ODE 转 SDE 转换引入随机性，使 Flow Matching 模型能与策略梯度 RL 结合。

**在 YingMusic-Singer 中的应用**（arXiv:2512.04779）：
- **ODE 转 SDE 转换**：在 ODE 轨迹中注入 Wiener 噪声 σ_t = a · sqrt(t/(1-t))，仅在单一时间步注入随机性
- **多目标奖励函数**：内容准确性奖励 R_con = 1-WER（FireRedASR），旋律相似性奖励 R_mel = 生成音高与参考音高 voiced frames 上 Pearson 相关系数
- **组内优势计算**：每组 G=8 个样本，加权组合 R = Σ w_k · R_k，标准化为 advantage
- **效果**：Zero-shot SVS WER 1.28%、SIM 93.95%、FPC 81.28%（vs TCSinger WER 3.47%、vs Vevo WER 9.83%）

### 2.4 在 SVS 中的对比

**DiffRO 在 SVS 中完全没有应用**。CosyVoice 3 论文明确写了不擅长歌声生成。

**坎**：DiffRO 靠 token 空间跑可微分奖励，但歌声旋律是连续变化的；旋律准确性（F0 Pearson 相关系数）不可微。

**好消息**：已有 DiffRO + GRPO 组合方案（arXiv:2509.18569），用 Sample Filter 策略结合两者。

**算力对比**：
- GRPO：通过群组采样的 baseline 替代 critic 节省显存
- DiffRO：通过梯度替代避免大量采样
- 理论上 DiffRO 更省，但实际受限于离散文本生成的可微近似
- GRPO 是已验证的高效方案，DiffRO 是有潜力的理论更省方案

### 2.5 YingMusic-Singer-Plus 中的 GRPO 实现

**论文**：arXiv:2603.24589

- 纯扩散模型 + 标准 GRPO（非 Flow-GRPO）
- 课程学习 (Curriculum Training) + GRPO 策略优化
- **选择 GRPO 的原因**：PPO 需昂贵 value network，DPO 受分布漂移影响，GRPO 在线运行无 value network
- G=8 个候选，M=4 个 reward model 评分
- SDE 随机噪声 window w_min=1, w_s=8
- 1.2K 步，lr=7e-6
- 推理 32 步 ODE，CFG scale=3

### 2.6 岛岛的 GRPO 实验结果

**V4 GRPO v2-v3**：
- v2：同卡 Whisper reload，OOM 率 5.6%
- v3：GPU 3 独立 Whisper server，零 OOM，43s/step
- 4800 步训练后最佳 PER=0.404（仅 +4.4% vs SFT baseline 0.387），1200 步后已回落
- **非显著性改善，GRPO 路线已暂停**

## 三、SPFM 自净化流匹配 完整技术细节

**论文**：Kim et al., "Training Flow Matching Models with Reliable Labels via Self-Purification", arXiv:2509.19091, Supertone Inc.
**代码**：https://github.com/supertone-inc/self-purifying-flow-matching (MIT License)
**相关论文**：Yi et al., "Robust TTS Training via Self-Purifying Flow Matching for WildSpoof 2026 TTS Track", arXiv:2512.17293

### 3.1 核心原理

**核心直觉**：当条件 c 正确时，conditional loss 应该低于 unconditional loss。如果 L_cond > L_uncond，说明这个样本的标签可能是错误的。

### 3.2 完整训练伪代码

```
for each batch (x1, c):
    x0 ~ N(0, I)                     # 采样噪声
    t_prime = 0.5                    # 固定插值时间
    xt = (1 - t_prime) * x0 + t_prime * x1  # 插值点

    # 计算两个 loss，用相同的 x0 和 t_prime
    L_cond   = ||v_theta(xt, t_prime, c)    - (x1 - x0)||^2
    L_uncond = ||v_theta(xt, t_prime, null) - (x1 - x0)||^2

    if L_cond > L_uncond:
        # 标签可疑，做无条件训练
        loss = L_uncond
    else:
        # 标签可信，标准条件 FM 训练
        loss = L_cond

    loss.backward()
    optimizer.step()
```

### 3.3 关键参数

- **t_prime（插值时间）**：0.5（F1=0.847 最优）。较低时 (0.1/0.3) 插值点太靠近噪声，两个 loss 都很大，区分度不够。较高时 (0.7/0.9) 模型可以不需要条件 c 就准确预测，因为插值点已接近目标 x1。t=0.5 时条件 c 的影响最大，L_cond-L_uncond 分布区分最明显
- **Warm-up**：TTS 实验 40k iterations（总 700k）；2D Toy 实验 4 epochs（总 100）
- **CFG dropout**：10%
- **优化器**：AdamW, lr=5e-4, halved 每 300k 步
- **Batch size**：128, 4×RTX 4090, batch expansion factor=8

### 3.4 实验效果

| 数据集 | WER 改善 | UTMOS | DNSMOS |
|--------|:--------:|:-----:|:------:|
| TITW-Easy | 6.68% → **5.96%** | 3.50→3.55 | 2.88→2.91 |
| TITW-Hard | 7.60% → **6.86%** | — | — |

- Filtered 样本的 WER 高达 24-26%，验证了筛选的有效性

### 3.5 与现有方法的区别

| 方法 | 特点 |
|------|------|
| TDSM | 需要额外的 time-dependent noisy-label classifier |
| LRA | 需要两个 pretrained encoders |
| DLD | 需要 pretrained feature extractor |
| SBDC | 推理时矫正，不修改训练过程 |
| **SPFM** | **不需要任何外部模块，纯训练时策略，即插即用** |

## 四、Wet 仿真数据增强 完整参数

**论文**：Zheng et al., "R2-SVC: Towards Real-World Robust and Expressive Zero-Shot Singing Voice Conversion", arXiv:2510.20677, ICASSP 2026
**代码**：基于 Seed-VC, https://github.com/Plachtaa/seed-vc

### 4.1 整体架构

基于 Seed-VC DiT-based flow matching：17 层、12 头、hidden dim 768、FFN 3072。加入三大模块：
- **SRE (Simulation-based Robustness Enhancement)**：数据增强
- **SETSE (Singing-Enhanced Timbre and Style Extractor)**：音色提取器
- **NSF (Neural Source-Filter)**：声学增强

### 4.2 Wet Sound Simulation 参数

| 效果 | Mixing Ratio | 触发概率 | 说明 |
|------|:-----------:|:--------:|------|
| Harmony（和声） | 0.4 | p=0.3 | 模拟人声分离后残留的和声 |
| Echo（回声） | 0.35 | p=0.4 | 模拟空间反射/延迟 |
| Reverb（混响） | 0.5 | p=0.4 | 模拟房间混响 |

三者的激活是独立的：同一个样本可能同时有和声+回声，也可能只有混响。

### 4.3 F0 Perturbation 参数

| 扰动类型 | 概率 | 说明 |
|---------|:---:|------|
| Jitter（抖动） | p=0.15 | 模拟声乐颤音 (vibrato) |
| Glide（滑动） | p=0.15 | 模拟自然音高滑音 |
| Jump（跳跃） | p=0.20 | 模拟 F0 提取错误的突变 |

每个音频样本包含 2 到 4 个扰动片段。

### 4.4 训练细节

- **输入**：perturbed data (wet audio + perturbed F0)
- **目标**：clean unperturbed data
- 模型学习从 wet 输入中恢复 dry 音频
- Wet simulation 应用于除了 F0 提取器以外的所有模块
- 在 Seed-VC checkpoint 上 fine-tune 50k 步，batch size 24
- **优化器**：AdamW, peak lr=1e-4, exponential decay to 1e-5
- **Vocoder**：BigVGAN v2, 44.1kHz

### 4.5 消融实验结论

- **w/o SRE**：NMOS 从 2.90 降为 2.23，Hard set SPK-SIM 下降 — SRE 是噪声环境下最关键模块
- **w/o SETSE**：SPK-SIM 略有提升但 NMOS 下降 — 独立音色提取器有助于泛化
- **w/o NSF**：NMOS 和 SMOS 均有下降 — NSF 对自然度有贡献

## 五、VAE 完整分析与模型对比

### 5.1 Stable Audio 2 VAE（YingMusic 使用的版本）

**架构**：AutoencoderOobleck，全卷积，基于 Descript Audio Codec 的 encoder/decoder 去掉 quantizer

| 参数 | 值 |
|------|:-----:|
| 总参数量 | 156.1M |
| encoder_hidden_size | 128 |
| downsampling_ratios | [2,4,4,8,8]（总 2048×） |
| channel_multiples | [1,2,4,8,16] |
| decoder_channels | 128 |
| decoder_input_channels | 64 |
| audio_channels | 2 |
| sampling_rate | 44100 |
| 帧率 | 44100/2048 = 21.53Hz（46.5ms/帧） |
| latent 维度 | 64 |

**训练数据**：AudioSparx — 806,284 个音频文件、19,500 小时，66% 音乐、25% 音效、9% 乐器分轨，**几乎不含日语**

**训练硬件**：16 台 A100, batch size 256, 1.1M steps；460K 步后冻结 encoder 仅 fine-tune decoder 640K 步

**损失函数**：多分辨率 STFT loss (window 2048/1024/512/256/128/64/32) + 差异 STFT loss + 感知加权 (Fletcher-Munson 曲线)

**论文自述**：*"speech generations are not intelligible"*；*"trained with English descriptions and will not perform as well in other languages"*

### 5.2 STAR-VAE（ICML 2026，未开源）

**论文**：arXiv:2606.23064, ICML 2026 Poster (2026年7月9日)
**项目页**：https://STAR-VAE.github.io

**架构**：基于 SAO CNN backbone + Mamba 层 + STAR 结构化 KL 正则化

**核心创新**：Gamma-Growth 函数 (γ=2.0) 凸分配，逐通道分配 KL 惩罚权重 β_c：
- 前 37.5% 通道（低惩罚区）：自动捕获结构化语义信息 (Safe Harbor)
- 后 62.5% 通道（高惩罚区）：存储随机纹理残差 (Noise Floor)
- 潜空间呈现类似 PCA 的能量压缩特性

**与 SAO 对比（同 21.5Hz 帧率）**：

| 指标 | SAO VAE | STAR-VAE | 改善 |
|------|:-------:|:--------:|:----:|
| FAD (AudioCaps) | 3.29 | **2.31** | 30% |
| FAD (Song Describer) | 0.69 | **0.25** | 64% |
| Latent Correlation | 0.11 | **0.08** | 27% |
| MOS 重建 | 4.05 | **4.32** | GT=4.45 |

**关键洞察**：STAR-VAE 在 21.5Hz 下语义保留 (FAD) 反而优于帧率翻倍的 εar-VAE (43Hz, FAD=4.44)。证明**潜空间的结构化程度比原始帧率对语义保留更重要**。

**已知限制**：
- 代码权重未公开
- 静态 Gamma-Growth 曲线无法根据输入信号动态调整
- Mamba 训练不稳定，需要特殊 strict Pre-Norm strategy with Layer Normalization
- 两阶段训练：Phase I 标准各向同性 KL 150h (24×H800) + Phase II STAR 微调 70h，总计 220h

### 5.3 εar-VAE

- **架构**：Oobleck-style encoder/decoder，与 Stable Audio 同族
- **帧率**：43Hz（约 23ms/帧），SAO 的两倍
- **采样率**：44.1kHz 立体声，与 YingMusic 完全对齐
- **关键创新**：K-weighting 感知滤波 + Phase Loss（瞬时频率+群延迟+立体声相关性损失）
- **优缺点**：信号级指标 (STFT-D, MSD) 优于 SAO，但语义保留 (FAD) 方面反而不如 STAR-VAE

### 5.4 Semantic-DACVAE-Japanese

- **HuggingFace**：Aratako/Semantic-DACVAE-Japanese (MIT License)
- **基模型**：facebook/dacvae-watermarked
- **增强**：WavLM 语义蒸馏（受 Semantic-VAE 论文启发）
- **UTMOSv2 评测**：
  - 128-dim 版：Emilia 测试集 2.4812，私有测试集 2.1629，均优于原始音频和 DAC base
  - 32-dim 版：即使压缩 128→32 后仍优于原始 DAC base 模型
- 已被 **Irodori-TTS-500M-v2** 采用为 audio VAE 用于日语 TTS

### 5.5 关键结论

1. SAO VAE 训练数据几乎不含日语，21.5Hz 帧率对日语短辅音 VOT (20-50ms) 在临界点
2. STAR-VAE 同帧率同维度但语义保留显著改善，最理想但暂不可用（等开源）
3. **最务实方案**：冻结 encoder 只微调 decoder，latent space 不变，DiT 无需重训
4. SongBloom 确认 VAE 帧率可修改：*"Minor modifications are made to its hyperparameters to ensure they have the same frame rate"*
5. AutoencoderOobleck 默认配置由 HuggingFace Diffusers 集成，暴露所有参数可调

## 七、DiffSinger vs YingMusic 完整对比

### 7.1 DiffSinger 架构

两阶段级联架构：

**1. Variance Model**（FastSpeech2 风格）：
- 预测音素时长 (log-domain)、F0 曲线（可显式或隐式）
- Multi-Variance Predictor：energy/breathiness/voicing/tension
- 输入：ph_seq, ph_dur, 可选 note_seq, note_dur, word_division

**2. Acoustic Model**：
- FastSpeech2Acoustic：将音素+时长+F0 编码为 frame-level condition tensor
- Auxiliary Decoder（可选）：生成快速低质量 mel 预测，作为浅扩散起点
- Diffusion Decoder：DDPM 或 RectifiedFlow，从部分噪化状态开始精化 mel，K_step 通常 200-400
- 结合 DDIM/PNDM/DPM-Solver++/UniPC 加速采样

**3. Vocoder**：NSF-HiFiGAN 44.1kHz，约 50MB 预训练通用 vocoder，建议在目标数据集上 fine-tune

### 7.2 多语言支持机制

- **语言标签**：ISO 639 代码 (zh/ja/en/yue)
- **音素命名**：zh/a, ja/o, en/eh (full name)；a, o (short name)
- **音素合并**：跨语言相似音素共享 embedding (merged_phoneme_groups)，如 [zh/i, ja/i, en/iy]、[zh/s, ja/s, en/s]、[ja/cl, SP]
- use_lang_id: true 启用语言 ID 嵌入
- **词典文件**：tab 分隔的 syllable→phonemes 映射
- **内置日语词典**：dictionaries/japanese_dict_full.txt

### 7.3 数据量需求

|---------|:---:|:----:|
| 从零训练声学模型 | 30 分钟 | 1-2 小时（覆盖所有目标音素） |
| 从零训练方差模型 | 1 小时 | 2-3 小时（需 MIDI/note 标注） |
| 微调预训练模型 | 15 分钟 | 30 分钟-1 小时 |

- **最低 GPU**：6GB VRAM (RTX 3060)
- **推荐**：12-24GB (RTX 3090)
- 从零训练：3-7 天；微调：1-2 天
- 支持 AMP FP16 和 BF16，AMP+DDP+梯度累积

### 7.6 核心差异对比

## 八、UniVoice 完整架构

**论文**：arXiv:2606.05852 (2026)
**总训练数据**：约 65k 小时（35k 歌声 + 30k 语音，Emilia 子集 15k 中文 + 15k 英文）

### 8.1 因子化条件分解

条件 c = c_cnt (内容) + c_mel (旋律) + c_tmb (音色) + c_tsk (任务标记)

| 条件 | 语音模式 | 歌声模式 |
|------|---------|---------|
| c_cnt（内容） | IPA 音素序列，ConvNeXt 编码 | 同左 |
| c_mel（旋律） | 可学习空标记 e_null | MIDI 音符序列，Conformer 编码 |
| c_tmb（音色） | 3-10s 参考音频，Song Bloom VAE 编码 | 同左 |
| c_tsk（任务） | "sp" 可学习嵌入，AdaLN 调制 | "sg" 可学习嵌入，AdaLN 调制 |

### 8.2 空旋律标记理论基础

**Proposition 1**：单体编码器中语音和歌声对旋律参数的梯度方向负相关。语音推动旋律参数趋向常数函数 (melody is irrelevant)；歌声推动忠实编码 MIDI。因子化后旋律编码器只从歌声接收梯度，空标记只从语音接收梯度，梯度冲突完全消除。

**Proposition 2**：对于语音生成，理想的速度场应该是对所有可能的旋律变现进行边缘化：v*_sp = ∫ v*(c_mel) p(c_mel) d(c_mel)。可学习的空标记 e_null 提供高效的摊销近似。由于 e_null 和旋律编码器 g_phi 接收完全不重叠的梯度（e_null 只由语音损失优化，g_phi 只由歌声损失优化），空标记收敛到最优的无旋律表示。

### 8.3 骨干网络

| 参数 | 值 |
|------|:-----:|
| 架构 | DiT 24 层 |
| dim | 1024 |
| 头数 | 16 |
| 参数量 | 0.3B |
| 来源 | Wan-DiT 视频生成改编 |
| 注意力 | FlashAttention-2 + RoPE |
| VAE | Song Bloom VAE (25Hz, 48 维) |
| 条件注入 | 通道维拼接（非 cross-attention）+ AdaLN 调制 |
| AdaLN | h' = γ(c) · (h - μ(h)) / σ(h) + β(c)，其中 c = c_time + c_tsk |

### 8.4 训练策略

- **Batch size**：32,000 帧/GPU × 8×A800 (80GB)
- **100 epochs**，AdamW，LR 7.5e-5，2k 步 warmup + cosine decay
- **条件随机丢弃**：p_text=p_melody=p_timbre=0.1（实现轴选择性 CFG）
- **推理**：Euler ODE 32 步，EMA weights，CFG 尺度 w_txt=5（强文本引导），w_aud=w_mel=1

### 8.5 消融实验

| 配置 | 语音 PER | 歌声 PER |
|------|:--------:|:--------:|
| 完整模型 | **5.26%** | **16.22%** |
| 去除因子化单体编码器 | 12.31% | 23.45% |
| 去除任务标记 | 退化 | 退化 |
| 空标记→固定零向量 | 退化 | — |
| 去除旋律编码器 | 几乎不变 | 严重退化 |
