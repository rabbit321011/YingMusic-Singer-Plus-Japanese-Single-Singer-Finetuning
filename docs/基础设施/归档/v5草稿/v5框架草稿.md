## 一、背景与目标

### 1.1 V4失败复盘

V4实验最终PER=0.387，远未达到预期，主要存在三大症状：

| 症状 | 表现 |
|------|------|
| **咬字模糊** | 辅音丢失严重，日语清浊音区分度差 |
| **唱功不稳定** | 音高偏差大，颤音过度/不足交替出现 |
| **长句崩坏** | 超过5秒的句子末尾出现音素错乱 |

失败根因分析详见材料6第零章及第一章：核心问题在于**分块策略过于粗放**、**对齐精度不足**，以及**数据预处理管线存在漏洞**。

### 1.2 V5目标

| 指标 | 目标值 | 说明 |
|------|--------|------|
| **日语歌声合成 PER** | **< 0.1** | 较V4（0.387）降低约74% |
| **咬字清晰度** | 显著提升 | 辅音还原率>95%，清浊音区分准确 |
| **唱功稳定性** | 显著提升 | 音高偏差<10音分，颤音自然度MOS>4.0 |

优先级总览参照材料6第二章。

## 二、P0：bake-off对齐

**优先级：最高** — 分块对齐是V5最大单一杠杆（材料6第三章）。

### 2.1 分块方案（A7粗边界 + 窗口宽度 + 低置信标记）

采用材料6第三章锁定的分块策略：

| 参数 | 值 | 说明 |
|------|-----|------|
| **粗边界方案** | A7（7级粗粒度边界） | 比A5粒度更细，提升边界召回率 |
| **上下文窗口宽度** | 左2句 + 右1句 | 保证跨句连贯性，显存可控 |
| **低置信标记** | 置信度<0.6触发重新切分 | 降低"幻觉对齐"风险 |

### 2.2 四候选配置表（B1/B2/B3/B4）

参照GRPO_train_plan_0529.md脚本路径索引格式：

| 配置 | 命令行（核心参数） | 模型路径 | 关键差异 |
|------|-------------------|----------|----------|
| **B1** | `python train.py --config configs/bakeoff_b1.yaml` | `models/checkpoints/b1/` | 固定窗口±2句，无低置信回退 |
| **B2** | `python train.py --config configs/bakeoff_b2.yaml` | `models/checkpoints/b2/` | 动态窗口（根据句长调整），低置信回退开启 |
| **B3** | `python train.py --config configs/bakeoff_b3.yaml` | `models/checkpoints/b3/` | B2 + 花丸MFA对齐替换原有aligner |
| **B4** | `python train.py --config configs/bakeoff_b4.yaml` | `models/checkpoints/b4/` | B3 + 推理侧人工对齐+时间抖动 |

> 详细命令行参数见 `scripts_archive/yingmusic_plus/run_bakeoff.sh`（路径待岛岛确认）

### 2.3 Gold Set评测方案

参照材料4 §1.4分层评估数据：

| 层级 | 歌曲类型 | 数量 | 考察重点 |
|------|----------|------|----------|
| **L1** | 慢速（≤120BPM）、简单旋律 | 30首 | 基础发音、元音稳定性 |
| **L2** | 中速（120-160BPM）、中等复杂度 | 40首 | 辅音清晰度、过渡自然度 |
| **L3** | 快速（≥160BPM）、复杂旋律 | 30首 | 高速咬字、长句稳定性 |
| **合计** | — | **100首** | Gold Set，固定不变，用于所有评测对比 |

**P95计算方式**：每首歌计算PER，取全部歌曲的95百分位数作为最终指标（更鲁棒，不受极端值影响）。

### 2.4 粒度-精度决策表

参照材料6第三章：

| 场景 | 推荐粒度 | 精度代价 | 说明 |
|------|----------|----------|------|
| 训练阶段（SFT） | A7 | 中等 | 精度与泛化平衡，V5默认 |
| 推理阶段（高要求） | A7 + 低置信回退 | 较低 | 牺牲少量速度换精度 |
| GRPO强化阶段 | A7 | 中等 | 与SFT保持一致 |
| 极端快速歌曲（>180BPM） | A7 + 窗口缩小 | 较高 | 防止上下文污染 |

### 2.5 花丸自训MFA流程

参照材料6第三章"花丸自训MFA声学模型"：

```bash
# Step 1: 准备数据（花丸99h → 44.1kHz单声道）
# Step 2: 生成发音词典（使用pyopenjtalk）
python -c "import pyopenjtalk; ..." > dict/hanamaru_lexicon.txt

# Step 3: 训练MFA声学模型
mfa train --clean -j 8 \
  data/hanamaru_wav/ \
  dict/hanamaru_lexicon.txt \
  output/hanamaru_mfa_model/

# Step 4: 对齐验证
mfa align -j 8 \
  data/hanamaru_wav/ \
  dict/hanamaru_lexicon.txt \
  output/hanamaru_mfa_model/ \
  output/hanamaru_alignments/
```

**发音词典来源**：统一使用pyopenjtalk生成，保证与UniVoice前端一致。

### 2.6 推理侧人工对齐方案 + 时间抖动参数

参照材料6第三章"推理侧对齐器"：

| 参数 | 值 | 说明 |
|------|-----|------|
| 时间抖动（jitter） | ±50ms | 模拟自然演唱微偏差 |
| 抖动分布 | 正态分布（μ=0, σ=25ms） | 非均匀分布更自然 |
| 应用位置 | 音素边界 + 音节中心 | 两者独立抖动 |
| 人工对齐回调 | 置信度<0.65时触发 | 使用PyWorld进行波形级微调 |

### 2.7 验收标准

| 检查项 | 通过条件 | 备注 |
|--------|----------|------|
| B1-B4全部跑通 | 无崩溃，loss收敛 | 约24h/配置 |
| Gold Set PER(P95) | 至少一个配置 < 0.15 | 最优配置进入P0.5 |
| 花丸MFA对齐质量 | 边界误差<20ms（vs 人工标注） | 抽样验证50句 |
| 推理侧对齐器 | 抖动后自然度MOS>3.5 | 内部评测5人 |


## 三、P0.5：V4d证伪实验

**优先级：高** — 在全面投入V5前，用最小代价验证"重对齐"是否能单独修复V4核心问题。

### 3.1 实验设计

参照材料6第四章：

| 实验项 | 设置 | 与V4c差异 |
|--------|------|-----------|
| **配方** | 完全复用V4c | 相同模型架构、超参数 |
| **数据** | 重对齐数据（花丸MFA替换原对齐） | **唯一变量** |
| **精度** | fp32（与V4c一致） | 相同 |
| **训练步数** | 10k - 20k | 提前停止观察 |
| **实验代号** | V4d | — |

### 3.2 分级判据

参照材料6第十章核查清单#6：

| 判据层级 | 指标 | 阈值 | 结论 |
|----------|------|------|------|
| **主判据** | FlowB（基频平稳度） | **> 0.88** | 通过→对齐是主因；不通过→需查架构 |
| **辅助判据①** | 辅音PER（Gold Set L2） | 较V4c下降>30% | 对齐改善有效 |
| **辅助判据②** | 长句PER（>5s） | 较V4c下降>40% | 窗口策略有效 |
| **缓冲机制** | 20k步内持续下降 | 无反弹/平台 | 可信度确认 |

**判定逻辑**：主判据通过 + 至少一项辅助判据通过 = **V4d证伪成功**（对齐即主因，沿用V4架构继续）。

### 3.3 失败后的备选路线

若V4d证伪失败（FlowB<0.88），按以下优先级切换：

| 优先级 | 备选路线 | 说明 | 参考 |
|--------|----------|------|------|
| 1 | **VAE诊断** | 检查VAE隐空间是否坍缩，重构误差是否异常 | 材料4 §5 |
| 2 | **架构检查** | 验证UniVoice v3各模块（encoder/decoder/时长预测） | 材料6第四章 |
| 3 | **DiffSinger切换** | 若UniVoice架构无法修复，切换至DiffSinger+日语音素适配 | 材料4 §7 |

### 3.4 训练脚本

复用V4c训练脚本，仅替换数据路径：

  --data_path ${PRIVATE_PATH} \   # 【唯一变更】重对齐数据

### 4.2 Null Token三处统一方案

参照材料6第五章 + 材料4 §8 UniVoice架构：

| 位置 | Null Token用途 | 统一值 | 说明 |
|------|---------------|--------|------|
| **Encoder输入** | 填充占位 | `[NULL_ENC]` ID=0 | 统一pad token |
| **Decoder输入** | 空帧占位 | `[NULL_DEC]` ID=0 | 与encoder保持一致 |
| **时长预测** | 无音节标记 | `[NULL_DUR]` ID=0 | 三处统一为同一token |

**实施方式**：在tokenizer定义中，将三处null token映射到同一个embedding向量。

### 4.5 Emilia低通指纹处理

参照材料6第五章：

- **问题**：Emilia部分数据存在低通滤波痕迹（<8kHz能量缺失）
- **处理方式**：
  1. 所有Emilia音频经过频谱分析，标记低通可疑样本（8kHz以上能量<-40dB）
  2. 可疑样本不参与P1训练，仅作为补充验证集
  3. 剩余合格样本预计~150h，仍满足训练需求
