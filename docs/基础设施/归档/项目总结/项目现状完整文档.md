## 一、YingMusic-Singer-Plus 是什么

> 本节全部来自论文 arXiv:2603.24589v2（中文译版），只提取与我的训练直接相关的部分。

### 1.1 模型做什么

论文提出 YingMusic-Singer-Plus，一个全 diffusion SVS 模型，实现旋律可控的歌声合成与歌词编辑。接受三种输入：

- **可选**的音色参考片段
- 提供目标旋律的歌唱片段
- 对应的修改歌词

**无需手工对齐或精确标注**。输出 44.1kHz 采样率歌声。

训练采用课程学习（curriculum learning）和 Group Relative Policy Optimization（GRPO）。代码、权重、benchmark 及 demo 已公开。

### 1.2 四个组件

论文 §2.1 原文：

> 1. **VAE**：沿用 Stable Audio 2，编码器将 44.1kHz 立体声波形下采样 2048 倍得 latent（帧率 21.53Hz，维度 64），解码器重建高保真音频。
> 2. **Melody Extractor**：基于预训练 MIDI 提取模型的编码器构建，中间表征捕获解耦的旋律信息。输出 128 维，经时间插值匹配 latent 帧率。
> 3. **IPA Tokenizer**：将中英文歌词统一转换为离散音素序列。采用句子级对齐——每句歌词转为 IPA 子序列，放置在对应起始帧位置。推理时提示歌词置于序列开头，目标歌词置于掩蔽区域起始处。
> 4. **DiT-based CFM Backbone**：沿用 F5-TTS。22 层、16 注意力头、隐藏维度 1024、FFN 膨胀因子 2、4 层 ConvNeXtV2 文本编码器、RoPE 位置编码、长跳跃连接。

### 1.3 官方训练方式：随机掩码

论文 §2.1 原文：

> 训练时，随机掩蔽比例为 γ 的 VAE 隐变量帧作为合成目标，未掩蔽部分作为音色上下文。令 z\_ctx 表示未掩蔽的 VAE 隐变量（掩蔽区域零填充）。条件 c = \[h̃; e; z\_ctx] 与带噪隐变量 z\_t 沿通道维度拼接后输入 CFM。

即：DiT 每帧的输入是四路拼接——`[noised_latent(64) | cond(64) | text_embed(512) | midi_proj(128)]`，投影到 1024 维。

Flow Matching 公式（论文 Eq.1）：

$$L\_{MSE} = \mathbb{E}_{t,z\_0,z\_1,c} | v_\theta(z\_t, t, c) - (z\_1 - z\_0) |^2$$

线性流：$z\_t = (1-t)z\_0 + t z\_1$，$v\_{target} = z\_1 - z\_0$。

### 1.4 课程训练四阶段

论文 §2.2-2.3 + §3 实验设置：

| 阶段          |  步数  | Batch 时长     |   LR   | 说明                                              |
| ----------- | :--: | ------------ | :----: | ----------------------------------------------- |
| TTS 预训练     |  1M  | 1.268 h      |  1e-4  | 无旋律条件，使用 Emilia 中英文子集                           |
| SFT Phase 1 | 240K | 1.69 h       | 2.5e-5 | 歌唱数据，旋律条件禁用（句子级对齐）                              |
| SFT Phase 2 | 170K | 1.69 h       | 2.5e-5 | 激活旋律条件 + CKA loss（λ 前 2K 步从 0.3 衰减至 0.01）       |
| GRPO        | 1.2K | batch size 6 |  7e-6  | G=8, M=4 等权奖励, SDE 噪声 a=0.8, 窗口 w\_min=1/w\_s=8 |

所有阶段随机掩蔽 70-100% 隐变量帧。总数据：SFT 使用 33,562.6 小时内部歌唱数据（经 SongFormer 分割、Mel-band RoFormer 人声分离）。GRPO 数据经 ASR WER<5% + pyannote 单人检测 + DNSMOS≥3.5 过滤，得到约 20,240 精选片段。硬件：8×A800 80GB，DDP + bf16。总参数 \~727.3M（DiT 453.6M + VAE 156.1M + Melody Extractor 117.6M），仅训练 DiT。

推理：32 ODE 步，CFG scale 3。

### 1.5 CKA 损失

论文 §2.2 原文——SFT Phase 2 引入 CKA 以强制旋律遵循。从 DiT 中间层 hidden states 与旋律 GT 计算：

$$L\_{CKA} = 1 - \frac{|K^\top L|\_F^2}{|K^\top K|\_F \cdot |L^\top L|\_F}$$

其中 $K = v\_\theta v\_\theta^\top$（hidden states 的 Gram 矩阵），$L = \tilde{h} \tilde{h}^\top$（旋律特征的 Gram 矩阵）。总 SFT loss: $L\_{SFT} = L\_{MSE} + \lambda L\_{CKA}$。

### 1.6 GRPO

论文 §2.3 原文——SFT Phase 2 激活旋律条件后 PER 回升（旋律保真 vs 歌词忠实的权衡），MSE loss 无法针对性优化，调整 λ 只改变平衡点不解决根本矛盾。GRPO 在线运行，组内统计估计 baseline，无需 Value Network。

将确定性 ODE 转为 SDE，随机步限制在有界窗口内。M 个 reward model 联合评分，组内标准化得 advantage：

$$A\_i = \sum\_{k=1}^{M} w\_k \cdot \frac{R\_i^k - \text{mean}({R\_j^k})}{\text{std}({R\_j^k})}$$

最终：$L\_{GRPO} = \frac{1}{G}\sum\_{i=1}^{G}\frac{1}{|S|}\sum\_{t\in S}(-L\_{clip} + \beta D\_{KL})$，ε\_l=0.002, ε\_u=0.01, β=1。

### 1.7 论文消融实验（关键证据）

论文 §4.2 表4 原文（旋律控制模式，中文）：

| 变体             |   PER↓   | SIM↑ | F0-CORR↑ |  VS↑ |
| -------------- | :------: | :--: | :------: | :--: |
| TTS Pretrain   |   0.41   | 0.57 |   0.01   | 0.50 |
| SFT Phase1     | **0.05** | 0.68 |   0.03   | 1.55 |
| SFT Phase2     |   0.08   | 0.63 |   0.92   | 1.57 |
| -w/o CKA       |   0.08   | 0.64 |   0.91   | 1.57 |
| **-w/o Dist**  | **0.45** | 0.63 |   0.94   | 1.42 |
| **Full Model** |   0.06   | 0.64 |   0.94   | 2.06 |

论文对消融的原文解释：

> - **TTS Pretrain** 建立了发音先验但 F0-CORR 接近零，当歌唱片段作为提示时 PER 显著下降，领域适应不足
> - **SFT Phase 1** 大幅提升所有指标，实现最低 PER，从上下文中自由生成旋律，绕过显式旋律对齐
> - **SFT Phase 2** 激活 Melody Extractor，F0-CORR 提升至 0.92 以上，但 PER 增加——旋律保真和歌词忠实之间的权衡
> - **GRPO** 恢复 PER 同时提升 F0-CORR 和 VS（SIM 不变），确认基于奖励的优化联合增强所有维度
> - **-w/o CKA**：移除 CKA，F0-CORR 降低
> - **-w/o Dist（关键）**：移除对旋律隐变量施加的 temporal dropout，**PER 从 0.08 退化到 0.45**——因为未受扰动的隐变量保留了残留语义信息，模型利用这些信息绕过真正的歌词生成。Temporal dropout 迫使模型依赖抽象的旋律轮廓

## 三、我做了什么

> 本节来自 `plus-finetune-fullplan-v0527.md`、`VOCAB_TOKEN_MAP.md`、`plus-v4-training-log.md`、`GRPO_train_plan_0529.md`、`GRPO_v2_debug_log.md`。

### 3.1 为什么需要 A/B 分割

官方训练使用随机掩码——随机掩蔽 70-100% latent 帧，未掩蔽帧作为 cond。但在官方 CN/EN 权重上做日语增量训练时，直接随机掩码无法收敛——因为 28 行日文 embedding 从未训练、日语发音分布与中英文完全不同。

issue-v4-finetune-report.md 记录了 V1 和 V3 的失败尝试。V1 使用 `cond = full_latent = GT` ——DiT 每帧都能从 cond 直接抄答案，30k 步从未学会 text→latent 映射。V3 修复了 cond（仅前 50% 帧给真值），但 `x_t = (1-t)×noise + t×full_latent` 每帧仍泄漏真实值。训练 loss 正常（24.9→0.45），推理全噪声——因为推理时 x\_t 初始化为纯噪声，而训练时从未见过纯噪声。两版权重均已删除。

V4 的核心设计原则：**训练和推理的 B 区信息分布必须完全一致**。

### 3.2 A/B 分割方案

fullplan §41-46 定义——将每条音频的 VAE latent 序列在 ref\_len 处切分为两区：

```
帧索引:   0 ──────────── ref_len ──────────────────── T
          ├──────────────────────┼───────────────────────┤
          │       A区（参考区）    │       B区（生成区）      │
          ├──────────────────────┼───────────────────────┤
x_t       │ (1-t)×noise+t×真latent│ (1-t)×noise+t×真latent │
cond      │ 真latent              │ 零                     │
midi      │ 零                    │ 真旋律（SOME+FuzzDisturb）│
text      │ 真token（时间戳对齐）   │ 真token（时间戳对齐）     │
```

**四条约束**：

1. A 区 cond = 真 latent ——通过 DiT self-attention 向 B 区传递音色
2. B 区 cond = 零 ——训练和推理 B 区 cond 完全一致（都是零）
3. A 区 midi = 零 ——防止模型依赖 A 区旋律
4. B 区 midi = 真旋律 ——提供音高引导

**ref\_len 计算**（fullplan §194-226）：`ref_len = T × random(0.125, 0.33)`，≥5s（108 帧），≤65% T。±2.5s 范围内吸附最近短语边界（使用 §2.6 的 A7 时间戳）。

**compute\_loss**（fullplan §280-316）：A 区 x\_t 也走标准 flow matching（不特殊处理——有 cond 直接参考，重建极简单）。B 区 cond=零，仅凭 text+midi 生成。Flow loss A/B 区分开记录合并反传。CKA loss 仅在 B 区计算（A 区 midi=零，CKA 无意义）。

**文​​本编码**（fullplan §153-176）：按空格分句 → pyopenjtalk 逐句 G2P → 句间插入 `<SEP>`（ID=365，官方已训练）→ 按 A7 时间戳放置到 latent 帧序列。L1/L2 精确对齐，L3 均匀分布兜底。

**训练/推理对齐**（fullplan §318-329）：

| <br />  |     训练 B区     |   推理 B区   |
| ------- | :-----------: | :-------: |
| x\_t 初值 | flow matching | 纯噪声 (t=0) |
| cond    |       零       |    零 ✅    |
| midi    |      真旋律      |   真旋律 ✅   |
| text    |    真 token    | 真 token ✅ |

### 3.5 GRPO 训练计划与改造

#### 3.5.1 论文 GRPO 原理

GRPO\_train\_plan §52-111 完整记录：

- Flow Matching 的确定性 ODE → 等价 SDE（仅窗口 `[w_min=1, w_s=8)` 注​​入 Wiener 噪声 α=0.8）
- MDP 建模：状态 s\_t = (c, t, x\_t)，动作 a\_t = x\_{t-1}，策略 π\_θ = p\_θ(x\_{t-1}|x\_t, c)，终端奖励 R = r(x\_0, c)
- 每 prompt 采样 G=8 候选 → 4 个 reward model 打分 → 组内标准化得 advantage → PPO-clip 更新（ε\_l=0.002, ε\_u=0.01, β\_KL=1.0）
- 训练 10 步 Denoising Reduction / 推理 32 步 ODE，无 CFG
- 4×4090 DDP, batch=6, lr=7e-6, total 4800 步

train\_plan §159-168 记录数据过滤三项（ASR WER<5% / pyannote 单人检测 / DNSMOS≥3.5）全部跳过——花丸单人数据风险低；ASR WER<5% 会删除 >90% 数据不可行；DNSMOS 分数区间窄（2.5-3.4）区分度有限。

## 四、效果怎么样

### 4.1 自重建：唱功退化

用户描述（2026-07-04 本对话中的原话）：

> 自重建像同一个人在浴室唱歌。而且唱功像是变成了没学过唱歌的花丸。不自然，像普通人唱歌了，没有灵动感了。

> 自重建也不行，不是训练数据的问题。

自重建是同一段花丸的歌——A 区前段的真 latent 做 cond + B 区自己重建自己。A 区 cond 提供了准确的花丸音色，但 B 区在训练时 cond=零，模型在 B 区只能产出一个「中性」的、没个性的歌声。音色大概对，唱功退化。

### 4.2 字位错乱：普遍存在（自重建就有）

用户描述（原话）：

> B区的text有错位，音符和咬字容易出现滑偏（比如第一个字提前发了，然后在该真正发第一个字的时候，发出的是第二个字，然后跟着滑脱了），这个现象和跑调强联系。如果B区有三句，那么这个现象基本只在第一句\~第二句有，第二句\~第三句基本就很准了。text在一定位置就会完全胡言乱语了，基本在B区的第三句开始，二句也有一点点这个问题。然后就是如果歌词比较快，那么也会有乱咬字的现象，可能提前到第一句。

> 时序对齐不是跨歌手的，而是普遍存在的。

即：同一个花丸的歌自重建时，B 区第一句音节漂移 → 连锁崩塌 → 第二句才稳。歌词快时第一句直接崩。第三句以后 text 完全胡言乱语。**这不是推理时换了另一个歌手才有的问题，自重建就有。**

### 5.1 材料4：TTS 领域全景调研（2025-2026）

- CosyVoice 3（阿里，1.5B）：百万小时训练数据，DiffRO 可微分奖励优化
- Qwen3-TTS（阿里，0.6B/1.7B）：离散多码本 LM 架构，端到端延迟 97ms
- 其余：OmniVoice（600+ 语言）、MOSS-TTS（100M\~8B）、GLM-TTS（GRPO 多奖励）、VoxCPM2（2B/30K stars）

### 5.2 材料4：DiffRO vs GRPO

材料4 §2 完整对比：

- **DiffRO**（CosyVoice 3, Interspeech 2025）：将奖励计算从音频空间搬到 token 空间（Gumbel-Softmax + Token2Text ASR），整个流程可微分。CosyVoice 3 WER 改善 20-50%。**明确限制**：不擅长歌声生成，这是未来方向。
- **GRPO**（DeepSeek-Math 2025）：组内采样（G=8），组内平均奖励替代 value network，无需 critic。vs PPO 显存节省 30-50%，训练速度提升 2 倍。
- **Flow-GRPO**（NeurIPS 2025）：ODE 转 SDE 引入随机性，使 Flow Matching 与策略梯度 RL 结合。YingMusic-Singer-Plus 采用此方案。
- **在 SVS 中的对比**（材料4 §2.4）：
  - DiffRO 在 SVS 中**完全没有应用**
  - 坎：DiffRO 在 token 空间跑可微分奖励，但歌声旋律连续变化（F0 Pearson 不可微）
  - 已有 DiffRO + GRPO 组合方案（arXiv:2509.18569）
  - 算力：GRPO 通过组采样替代 critic 节省显存，DiffRO 通过梯度替代避免大量采样
- **YingMusic-Singer-Plus 的 GRPO**（材料4 §2.5）：纯扩散 + 标准 GRPO，课程学习 + GRPO 策略优化。G=8, M=4 奖励等权（ASR\_WER + F0\_CORR + QwenFeat + WavLM\_Sim），1.2K 步，lr=7e-6，推理 32 步 ODE + CFG=3。
- **岛岛的 GRPO 结果**（材料4 §2.6）：v2 同卡 Whisper reload OOM 率 5.6%；v3 GPU 3 独立 Whisper server 零 OOM 43s/step；4800 步后最佳 PER=0.404（+4.4% vs SFT 0.387）；**非显著性改善，GRPO 已暂停**。

### 5.3 材料4：SPFM 自净化流匹配

材料4 §3 完整记录（Kim et al., arXiv:2509.19091, Supertone Inc., MIT License）：

**核心直觉**：当条件 c 正确时，conditional loss 应低于 unconditional loss。如果 L\_cond > L\_uncond，说明这个样本的标签可能错误。

**训练伪代码**：固定 t=0.5 插值，同时计算 L\_cond 和 L\_uncond。L\_cond > L\_uncond → 做无条件训练，否则标准条件 FM 训练。Warm-up 40k steps，t=0.5 时区分度最优（L\_cond-L\_uncond 分布区分最明显）。

**效果**：TITW-Easy WER 6.68%→5.96%，TITW-Hard 7.60%→6.86%。Filtered 样本 WER 达 24-26%，验证了筛选有效性。

**与现有方法的区别**：不需要额外的 noisy-label classifier（TDSM）、不需要 pretrained encoders（LRA）、不需要 pretrained feature extractor（DLD）、不需要推理时矫正（SBDC）。**纯训练时策略，即插即用。**

### 5.4 材料4：Wet 仿真数据增强

材料4 §4 完整参数（R2-SVC, ICASSP 2026, arXiv:2510.20677）：

**Wet Sound Simulation**：和声 mixing ratio=0.4/p=0.3 | 回声 0.35/p=0.4 | 混响 0.5/p=0.4。三者独立激活。

**F0 Perturbation**：Jitter(p=0.15) 模拟颤音 | Glide(p=0.15) 模拟滑音 | Jump(p=0.20) 模拟 F0 提取错误突变。每个样本含 2-4 个扰动片段。

**消融**：w/o SRE → NMOS 2.90→2.23（SRE 是噪声环境下最关键模块）；w/o SETSE → NMOS 下降；w/o NSF → NMOS/SMOS 均下降。

### 5.5 材料4：VAE 完整分析

材料4 §5 完整对比五个模型：

- **SAO VAE**（YingMusic 在用）：21.5Hz/64维。训练数据 AudioSparx 19,500h（66% 音乐），**几乎不含日语**。论文自述 "speech generations are not intelligible"。21.5Hz 帧率（46.5ms/帧），日语短辅音 VOT 20-50ms **在临界点**。
- **STAR-VAE**（ICML 2026, arXiv:2606.23064）：同帧率 21.5Hz、同 latent dim（可能 64）。Gamma-Growth 结构化 KL 正则化。语义保留 vs SAO 改善 30%（FAD 3.29→2.31）至 64%（FAD 0.69→0.25）。**最理想但未开源**——ICML 2026/7/9 poster 后可能发布。
- **εar-VAE**：43Hz 帧率（SAO 两倍），信号级指标优于 SAO，但语义保留不如 STAR-VAE。
- **Semantic-DACVAE-Japanese**（Aratako, HuggingFace）：日语专用，UTMOSv2 超原版。128-dim 和 32-dim 版均优于 DAC base。被 Irodori-TTS-500M-v2 采用。

材料4 §5.5 关键结论：**最务实方案**——冻结 encoder 只微调 decoder，latent space 不变，DiT 不需重训。STAR-VAE 等开源后 drop-in 替换。

### 5.6 材料4：F5-TTS 社区经验

材料4 §6 来自数百条 GitHub Issue 的总结，12 条关键案例：

- 日语微调：#1167 checkpoint 必须先 prune（只保留 ema\_model\_state\_dict）；#1181 必须指定日语 vocab；#693 **所有汉字必须转平假名**，ref\_text 也必须转；#943 转平假名后仍无法理解——确保 ref\_audio 的 ref\_text 也转平假名。
- 采样率：#438 16kHz 微调后模型失去中英文能力——**采样率必须 24kHz**。
- 精度：#1101 泰+英+中 bf16 → 输出逐渐静音，**切换 fp16 解决**。
- 混合训练：#636 215h 西语+35h 英语 → 英语单词重复——**原语言比例不能太低**；#57 西语 280k 步后失去英语能力。
- 社区微调配置：RTX 3090 60-80h / RTX 4090 106h / 8×4090 73h 意大利语。多语言模型可以将所有语言数据合并训练，无需标记语言种类。

### 5.7 材料4：DiffSinger vs YingMusic 对比

材料4 §7：

- DiffSinger 两阶段（Variance→Acoustic），需音素级时长标注；日语成熟（内置词典+SOFA+工具链）；支持 zh/ja/en/yue 全语言；参数约 50M。

### 5.8 材料4：UniVoice 架构

材料4 §8（arXiv:2606.05852, 2026）：同一 DiT 同时做语音和歌声合成。因子化条件分解——c = c\_cnt(内容) + c\_mel(旋律) + c\_tmb(音色) + c\_tsk(任务标记)。语音模式下旋律条件用可学习空标记 e\_null 替代。证明因子化消除了语音和歌声之间的梯度冲突（Prop 1：单体编码器中两者梯度方向负相关）。0.3B 参数，约 65k 小时数据。

### 5.11 材料5：核心理论——作为谁 × 谁为作

材料5 §1 提出歌声生成的两个正交维度：

**作为谁（歌手身份）**：

- SVS 模型没有天然的"身份"。人类歌手有"风格"作为上下文——意外之处被视为风格；AI 的输出偏差被视为缺陷。
- 方案 A——SVC 教师蒸馏：SVS 输出过 SVC → SVC 输出必然是花丸音色 → SVS 以 SVC 输出为目标训练。学术对应 CoMoSVC 一致性蒸馏。
- 方案 B——BYOL 自监督歌手身份：Sony CSL Paris (ISMIR 2023)，跨域泛化最优，参数量比 Wav2Vec-base 少 19 倍，不压缩域内方差。
- 方案 C——子中心嵌入（arXiv:2407.04291）：20 个子中心代替单一 embedding，保留类内方差→更自然的表达。

\*\*谁为作（唱歌动作）\*\*的五个子维度：

1. 唱功：YingMusic-Singer-Plus GRPO 四维奖励，V4 实际仅 +4.4% PER
2. Text 咬字：CE 辅助损失（Whisper teacher-forcing），确定性梯度 vs GRPO 策略梯度高方差
3. Text 对齐：DiTSinger 隐式对齐（字符级 attention mask）、BBC 编码器（边界随机掩码）、CPC 对比预测编码
4. MIDI 旋律：已有 CKA loss，问题不大
5. 性格/live 存在：子中心嵌入保留表达变化

### 5.12 材料5：平均化税与条件集

材料5 §2 提出 Averaging Tax 理论：

> 所有用 MSE loss 训练的扩散/流匹配模型，其最优预测器永远是条件均值 E\[v|x\_t, t]。在多模态的中间点，这个均值指向"没有真实轨迹使用的方向"——导致生成模糊。这不是模型缺陷，是 MSE loss 的数学必然。**加参数、加数据、换架构都不改变这个极限。**

**对 V4 的直接解释**（材料5 §2.1）：

- FlowB=0.90 不是"模型只能学到这个程度"，而是"MSE 在这个条件集下只能到这个程度"
- 唯一解法：缩小条件集——让模型面对更窄的条件范围
- 更好的 text 对齐 → 每个帧只有 1-2 个可能音素；更精确的 midi → 音高范围更窄；更强的 cond → B 区不再裸奔

**平均化区间假说**（材料5 §2.3）：训练存在三个阶段（0\~a 拟合 → a\~b 平均化陷阱 → b\~1 精细调优）。FlowB 不降可能是进入了 a\~b 区间。

**学术对应——Low-Noise Pathology**（arXiv:2509.20952）：t 很小时 flow matching 的 loss landscape 条件数发散到无穷，导致病态优化、Jacobian 重分配、表示退化。检测方法：Jacobian 条件数追踪、编码器特征方差、F0 RMSE 趋势。LCF 解决方案：t\<T\_min 时切换到 contrastive loss。

### 5.13 材料5：Loss 设计原则

材料5 §3：

- **GradNorm**（ICML 2018）：每步检测各 loss 组件相对于初始值的下降比例，下降慢的自动加权。V4 诊断：Flow loss 降得飞快，text 相关一动不动——shortcut learning。**SVS/TTS 领域目前没有人用 GradNorm**，是领先做法。
- **Loss 的复合性**：Flow B 同时包含文本+midi+性格，调节一个影响另一个。GradNorm 假设各 loss 独立，SVS 中不成立。UniVoice 的因子化是解决方案。
- **Loss 幅度调节四层**：①尺度平衡（对数变换/不确定性加权）→ ②梯度幅度平衡（GradNorm）→ ③梯度方向平衡（PCGrad/GradDrop）→ ④训练进度平衡（AMTL 几何均值）。真正的平衡发生在第四层。

### 5.14 材料5：对比 Loss——ΔFM

材料5 §3.4 岛岛原创推导：

```
Loss = (1+n)·LE - mean(L_alternatives)
```

放大正确 cond 的 loss 权重，减去错误 cond 的平均 loss。学术对应 **ΔFM**（ICCV 2025, arXiv:2506.05350）：

```
L_ΔFM = ||v̂ - v⁺||² - λ·||v̂ - v⁻||²
```

本质完全一样——"正损失 - 负损失"的对比结构。

ΔFM 关键特性：代码改动极小（只改 loss 函数），负样本从 batch 内随机采样（randperm），λ=0.05 图像最优 / λ=0.2 TTS。**ΔFM 在 SVS 中是明确的研究空白**——没有任何 SVS 工作用过 ΔFM。

### 5.15 材料5：V5 技术方案详情

材料5 §4：

**数据集最终确定**：Emilia 日语 2,800h（发音基础）+ JSUT 10h（质量锚点，48kHz）+ JVS 30h（100 位专业声优）+ 花丸 90h（唱歌+音色）。排除 Galgame（HTTP 451/动画声线偏差/性别失衡）和 J-CHAT（无现成音频）。数据量论证：2,840h 朗读 + 90h 唱歌对于增量训练绰绰有余。

**V5 训练主线**：70% 朗读 TTS + 30% 唱歌 SVS 混合训练，WeightedRandomSampler；SPFM 数据自净化；Wet 仿真增强；UniVoice null melody token（TTS 模式用可学习 token 代替 midi=0）。

**VAE 方案**：短期冻结 encoder 只微调 decoder（社区前例 lyraaaa/sao\_vae\_tuned\_100k）。中期等 STAR-VAE 开源（ICML 2026/7/9）做 drop-in 替换。

**对比学习增强**：ΔFM（代码几行）对抗平均化；CPC 对比预测编码（SVC 已验证）平滑对齐误差。

**对齐增强**：DiTSinger 隐式对齐（字符级 attention mask，窗口外 M=-∞ 禁止注意）；BBC 编码器（音素边界随机掩码）。

**训练阶段检测**：Low-Noise Pathology + LCF 局部对比流。

**后处理增强**：GAN 多频带判别器（XiaoiceSing2/WeSinger2）；多教师蒸馏（SVC 音色 + ASR 内容 + Pitch 旋律 + HiFi-GAN 质量）。

## 六、我想要什么

> 想训练出花丸唱歌的效果。传统SVC/RVC容易出现咬字，唱法什么的非常依赖翻唱源，而不是花丸本人的特征。

即：训练一个模型，使其无论翻唱源是谁——无论另一个人的节奏快慢、音节疏密、唱法风格如何——输出的歌声都表现出花丸本人的特征：花丸的音色、花丸的咬字方式、花丸的唱法表达。花丸的「歌手身份」应该主导生成，而不是被 B 区旋律源的特征覆盖。
