## 一、模型路线

### 1.1 Vevo2 AR 微调

| 项目 | 详情 |
|------|------|
| **应用位置** | 数据管线末端（花丸数据集构建完成后） |
| **做了什么** | 在 Vevo2 posttrained AR 模型上做 v1/v2/v3 全量微调 + 6 组消融实验 + LoRA r=16 |
| **训练数据** | 花丸 3.7k~16k 条日语歌唱数据 |
| **核心发现** | **非英文（日/中）文本跟随能力为零**——所有微调本质上在背 CS 序列 |
| **结果** | 🔴 **路线废弃**，转向 YingMusic-Singer-Plus DiT CFM |

**关键诊断证据**：
- 三语言 baseline：EN/CN/JP 默认 loss ~13.5-13.9
- 错配文本实验：文本不影响 loss（delta=0.009）
- 零文本实验：空文本 loss 低于正确文本
- SVS demo：EN 文本跟随完美，JP/CN 完全失败

### 1.2 YingMusic-Singer-Plus V1

| 项目 | 详情 |
|------|------|
| **应用位置** | 花丸日语 SFT 第一版 |
| **做了什么** | `train_plus.py`，30k 步，cond 直接用 full_latent = GT |
| **核心问题** | cond 泄露了完整 GT 信息 → DiT 抄答案，不需要学文本 |
| **结果** | 🔴 **rewrite 从未成功**，权重丢弃 |

---

### 1.3 YingMusic-Singer-Plus V3

| 项目 | 详情 |
|------|------|
| **应用位置** | 花丸日语 SFT 第二版 |
| **做了什么** | `train_plus_v3.py`，30k 步。cond = 前 50% 帧（修复 V1 的 cond 泄漏） |
| **训练结果** | Flow loss 24.9→0.45（训练侧看起来正常） |
| **核心问题** | x_t = (1-t)×noise + t×full_latent，**每一帧都泄露答案**；推理时 x_t 只有首帧重复→分布外→全噪声 |
| **结果** | 🔴 **推理全噪声**，权重无效（~90GB），已删除 |

---

### 1.4 YingMusic-Singer-Plus V4（当前主力）

| 项目 | 详情 |
|------|------|
| **应用位置** | 花丸日语 SFT 第三版 |
| **核心修复** | **A/B 区分割**：A 区 [0, ref_len) = cond 真值 + midi 清零；B 区 [ref_len, T) = cond 零 + midi 真旋律 |
| **关键改造** | x_t 构造、flow loss A/B 分区记录、ref_len 短语边界吸附（A7 时间戳）、t_shift 对齐、文本 P10 编码（空格分句+SEP） |
| **训练配置** | 4×4090, batch=1+grad_accum=4, lr=7e-6, 30k 步（V4a/b/c 逐步迭代） |

#### V4 各版本演进

| 版本 | 步数 | 说明 |
|------|:--:|------|
| **V4a** | 30k | 初始训练，基础版 |
| **V4b** | + | 迭代改进 |
| **V4c** | **24k** | **当前主力模型**。SFT baseline: total PER=0.387 |

#### V4c SFT baseline 评估（120首分层）

| 桶（B区假名数） | avg PER | 观察 |
|:--:|:--:|------|
| 1-10 | 0.416 | 短句尚可 |
| 11-20 | 0.429 | 中等 |
| **21-30** | **0.562** | 最优区间 |
| **30+** | **0.141** | 长文本崩塌——SFT 基本失效 |
| **Total** | **0.387** | — |

## 二、强化学习路线

### 2.1 GRPO v2

| 项目 | 详情 |
|------|------|
| **应用位置** | V4 SFT 后的 RL 精调 |
| **设计** | 4 卡 DDP 同卡 Whisper（每 20 步 reload） |
| **Reward 四路** | DNSMOS 0.45 + PER 0.25 + SIM 0.15 + F0 0.15 |
| **核心问题** | S4 backward 碎片化，Whisper 找不到连续 3GB 块 |
| **结果** | 🔴 **OOM 率 5.6%**，不可靠 |

---

### 2.2 GRPO v3（最终版本）

| 项目 | 详情 |
|------|------|
| **应用位置** | V4 SFT 后的 RL 精调（v2 的 GPU 架构修复版） |
| **核心修复** | GPU 0-2 训练 + GPU 3 独立 Whisper TCP server（终生不动，零碎片） |
| **配置** | G=8, batch=6, lr=7e-6, 10步训练去噪, SDE 窗口[1,9), CFG 禁用 |
| **训练步数** | 4,800 步，~43s/step，零 OOM |

#### GRPO v3 完整评估

| 步数 | Total PER | Δ vs SFT（0.387） |
|------|:--:|:--:|
| SFT 24K | 0.387 | — |
| GRPO 400 | 0.391 | +1.1% |
| **GRPO 800** | **0.404** | **+4.4%（最佳）** |
| GRPO 1200 | 0.392 | +1.4% |
| GRPO 4800 | 回落 | — |

**结果**：🔴 **非显著性改善**（~1.1σ，在统计噪声范围内），GRPO 路线已暂停。

**根因分析**：SFT 阶段 text dropout 仅 15%，text conditioning 先天不足，GRPO 难以修复。

### 4.3 A7 时间戳对齐

| 项目 | 详情 |
|------|------|
| **应用位置** | V4 训练需要句级时间戳将歌词 token 放置到 latent 帧序列 |
| **最终方案** | faster-whisper large-v3 ASR → difflib 模糊匹配歌词 → sim 分四档 |
| **硬件** | 6×RTX 4090，train 15,122 条约 20 分钟 |
| **P95 误差** | 6.62s（长尾由极少数长句串烧拉高） |

**分档产出**：

| 档位 | 条件 | 条数 | 用途 |
|------|------|:--:|------|
| L1_high | sim≥0.9, 句≤10 | 7,725 (51%) | 精确时间戳对齐，主训练集 |
| L2_medium | sim≥0.7 | 3,924 (26%) | 允许偏差，辅助训练 |
| L3_low | sim≥0.5 | 967 (6.4%) | 均匀分布兜底 |
| L4_discard | sim<0.5 | 2,243 (15%) | 丢弃 |

**淘汰的对齐方案**：

| 方案 | 方法 | 淘汰原因 |
|------|------|------|
| A1 | CTC-Seg + wav2vec2-ja | 域不匹配（语料模型→歌唱），大量 `<unk>` |
| A2 | MFA + japanese_mfa | HMM 音素模型，唱歌拖长音被压缩，误差逐句累积（P95=9.37s） |
| A3 | WhisperX forced alignment | 有边界时最优（P95=1.27s），但全量数据无边界信息 |
| A4 | Qwen3-ForcedAligner-0.6B | 结果极度不稳定（MAE=2.90s） |
| A5 | 日语专精 ASR（Reazon/Kotoba）| 唱歌识别崩溃（sim=0.00~0.76） |
| A6 | Torchaudio forced_align（MMS-FA） | 同样需要边界引导（MAE=12.21s） |
