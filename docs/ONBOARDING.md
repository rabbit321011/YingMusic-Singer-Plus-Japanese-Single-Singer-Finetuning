## 1. 项目是什么

花丸晴琉（Hanamaru Hareru）日语歌声合成。基于 YingMusic-Singer-Plus DiT 模型，目标：花丸音色 + 任意旋律 + 任意日文歌词 → 高质量歌声。

## 2. 文档系统的两个角色

- **索引文件**（`main_*.md`） — 描述一个目录下有哪些文档、它们的阅读顺序、彼此间的关系。索引不承载具体知识。
- **工人文件** — 具体内容。工人不声明自己的位置、上下文，所有关系由索引托管。

一个目录 = `main_*.md`（索引） + 若干工人 + 若干嵌套子目录（子目录各有自

己的索引）。

## 3. 版本机制

版本目录命名规则：`vX/` 或 `vX_Y/`。数字越大越新。
每个版本目录有一个 `main_vX.md` 作为版本级索引。
扫描目录可找到最新版本，不在此枚举。

## 4. 接入策略

### 4.1 找到根

进入 `基础设施/`，读 `main_基础设施.md`。它告诉你：

- 项目的固定知识域（架构、论文、数据管线、部署运维）的位置
- 版本目录的识别规则
- 归档在哪

### 4.2 定位当前版本

找到版本目录中数字最大的 `v` 目录，读其 `main_vX.md`。它告诉你：

- 这个版本要解决什么问题
- 有哪些实验分支
- 分支间是并发还是串行

### 4.3 进入分支

按任务选择分支目录，读其 `main_*.md`。它告诉你：

- 分支内有哪些文档
- 阅读顺序
- 哪些子目录需要进入

### 4.4 读工人

按索引指定的顺序读工人文件。工人间的交叉引用为标准 markdown 链接。

### 4.5 查底层知识

架构、数据管线、词表、部署 — 回到 `基础设施/` 对应固定领域。

## 5. 策略总结

```
基础设施/main_基础设施.md    （根索引）
  → v{N}/main_vN.md         （版本索引）
    → {分支}/main_*.md      （分支索引）
      → 文档.md              （工人）
      → {子分支}/main_*.md  （嵌套索引）
        → ...
```

## 6. 命名约定

| 模式              | 含义                |
| --------------- | ----------------- |
| `main_*.md`     | 索引：声明同目录下文档的关系和顺序 |
| `vX/` / `vX_Y/` | 版本代际              |
| `基础设施/` 下无编号目录  | 跨版本固定知识域          |
| `归档/`           | 历史材料，新任务一般不读      |

## 7. 如何维护

### 7.1 写一个新工人文件

1. 在该分支目录下创建 `.md` 文件，命名用描述性中文，不加编号前缀
2. 编辑所在目录的 `main_*.md`，在"工人"表中新增一行，说明内容和顺序位置

工人文件自身不声明版本号、日期或阅读顺序。不修改已有工人文件的内容。

### 7.2 新建一个子分支

1. 创建子目录，在子目录内写 `main_*.md`
2. 在父级 `main_*.md` 的"子目录"表中新增一行，说明内容和启动条件
3. 子分支内的工人和嵌套同上

### 7.3 新建一个版本

1. 在 `基础设施/` 下创建 `vN/` 或 `vN_M/`（数字比已有最大版本号大）
2. 在版本目录内写 `main_vN.md`，说明该版本的目标和分支结构
3. 在 `基础设施/main_基础设施.md` 中不枚举具体版本——版本由目录名自动识别

### 7.4 增量推进

- 实验进行中，工人文件可以持续更新——此时它是活文档
- 当一个实验阶段完成后，这个工人就"封存"了。后续即使结论被推翻，不回头改它，而是新开一个工人记录新结论，父级 main 里的顺序体现时序
- 索引文件（`main_*.md`）随时保持与实际文件状态一致：新增、调整顺序、补充说明
